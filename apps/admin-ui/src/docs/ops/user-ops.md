---
title: 用户维度运维
order: 2
---

面向平台运维（system_admin）——查看/管理某个 `user_id` 下的四类资产，以及清除一个用户全部数据的完整链路。

## 入口

左侧「用户」（`/users`，仅管理员可见）列出全平台按 `user_id` 维度聚合的用户——这里的“用户”不是租户成员花名册，而是调用 Agent 时传入的 `user_id`：既包括外部终端用户，也包括开通了控制台账号的员工（成员），两者共用同一套资产视图。点某一行进入该用户的详情页（`/users/:userId`）。

详情页顶部有一条只读提示：查看这个页面本身不会以该用户身份执行任何操作，但查看和修改他人数据都会记入审计日志。

## 四个 tab

- **对话**：该用户跨 Agent 的会话列表，可按 Agent、按“活跃起始”日期筛选；点一行跳转到只读的对话详情重建视图。
- **记忆**：该用户跨 Agent 的长期记忆条目——这是记忆治理的主入口：可编辑内容/类型，可“遗忘”（软删除）单条记忆；表格另有重要度/置信度两列（可排序）和来源运行的跳转链接。顶部有一个时间点选择器，选中某个历史时刻后表格会切成该时刻的历史快照（时间旅行查看），此时编辑/遗忘按钮会被禁用——防止在回看历史时误改当下状态。
- **工作区**：该用户跨 Agent 共享的持久化存储卷——已注册的产物（可下载/删除）和原始文件（可下载/删除，隐藏点号开头的运行期临时文件）。顶部一行会显示卷名和已用/上限的用量提示（约 30 分钟一次的粒度，不是实时值）。
- **用量**：该用户当月跨全部 Agent 的实时 token 计数——总量、输入/输出拆分、按模型分组，是实时值（与工作区用量的 30 分钟粒度不同）。

以上四个 tab 都是只读观察面，“记忆”和“工作区”里的写操作（编辑/遗忘记忆、删除文件/产物）在管理员切入其他租户查看时会被整体置灰——切入态下这些按钮不可点。

## 清除用户数据（purge）

详情页右上角「清除用户数据」按钮打开一个高危二次确认弹窗：必须原样输入该用户的 `subject_id` 才能点亮确认按钮。清除自己账号的数据时会额外多一条强化警告，但不会被禁止——清数据这件事对任何用户（外部/员工/自己）都一视同仁。

**这与账号本身的删除是两件事**：这个按钮只清数据（会话/记忆/工作区/上传/触发器/Webhook 全部删除；账单与分析记录保留但脱敏，不再关联到具体用户），从不触碰 Keycloak 账号或角色绑定——账号本身的删除是成员管理页的职责，两者解耦。

## 删除收尾：janitor 30 分钟异步链路

点击确认后，purge 端点立即返回，但工作区那部分的物理清理是**异步**完成的，走后台的清扫任务（janitor），每 30 分钟一轮：

1. purge 端点先在该用户的工作区目录旁落一个**墓碑标记**（不直接删文件）。
2. 下一轮 janitor 发现这个标记，把该用户的工作区**流式打包归档**到对象存储。
3. 归档成功后清空该用户在文件服务器上的原始目录。
4. 数据库行标记为“已归档”。墓碑标记本身**永久保留**（不会被这一步清掉）——它的作用是继续挡住这个用户以后再申领沙箱/工作区。

也就是说：点了「清除数据」之后到工作区被真正清空之间，有一个最长约 30 分钟的窗口——这段时间里该用户没法再被分配新的沙箱（墓碑标记从落下的那一刻起就已经在生效阻拦，不需要等归档完成）。归档后的数据保留 90 天可恢复，具体恢复步骤见《备份与恢复》。
