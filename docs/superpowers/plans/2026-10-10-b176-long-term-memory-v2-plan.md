# B-176 长期记忆 v2 实施计划

- **状态**:计划稿,**不排期**(2026-10-10 用户拍板:开工时间等指令)。
- **设计**:[`docs/superpowers/specs/2026-10-10-b176-long-term-memory-v2-design.md`](../specs/2026-10-10-b176-long-term-memory-v2-design.md)(下称「设计」)。
- **粒度**:本计划到「阶段 → PR → 主要改动 / 验收」一级。每个阶段开工前,另写该阶段的逐 task 计划(TDD 步骤、精确文件与测试),并**按当时代码重新核对**本计划与设计里的 file:line。

## 0. 全局约定(每个 PR 都适用)

1. **测试先行**:先写会红的测试,再实现;每条新断言做一次「改坏 → 红 → 恢复 → 绿」自证。
2. **真栈用例**:要上测试环境才能验的 PR,同一个 PR 往 `docs/runbooks/pending-test-release-acceptance.md` 加用例(触发方式 / 判据 / 没修好时的表现)。
3. **迁移**:只做 expand(新列可空或带默认值、新表、新索引),三段式发布;revision id ≤32 字符;新表带 `tenant_id` + RLS 策略并进 `test_rls_policy_coverage`。
4. **存储契约**:SQL 与内存两套 memory store 谓词同义,新增 / 改动的方法补参数化契约测试(内存档进单元 CI,SQL 档 integration)。**作用域谓词(用户 × 对象 × 智能体)只写一处**,召回 / 比对 / 整理 / 清除 / 导出全部调用它,并有 AST 或调用点穷举测试防漏。
5. **评测回归**:M1 之后,任何影响抽取 / 召回的 PR 在描述里贴评测前后数字(分阶段指标 + token + 记忆耗时)。
6. **与 B-175 共用**:中文关键词查询函数、重排用途拆分、评测运行器 —— 谁先开工谁建,接口先在两份计划里对齐;改重排 / 嵌入代码时,知识库侧行为不变并有测试锁定。
7. **平台文本**:提示词与工具说明不出现任何租户业务内容;示例用中性占位。
8. **管理端**:`pnpm typecheck` / `pnpm test` / `pnpm build` 通过;中英文案键一致;跨租户只读置灰语义不变。
9. **对外 API**:按设计 §8.3;按风格指南写文档、同步侧栏、`auth.md`、`errors.md`;构建与死链检查通过;路由登记 gate + lockdown 两张表。
10. **评审**:每个 PR 合前跑代码评审;作用域、对外 API、删除路径加安全评审。
