# 长期记忆总计划(2026-11-13 收成一条主线)

- **为什么有这份**:长期记忆的工作挂在两个编号上 —— B-300(助手得出的内容被当成用户事实记下,11-11 设计已合)和 B-176(长期记忆 v2,10-10 出了设计与 M0–M9 计划,不排期)。B-300 开工前做了一次深度研究(下称「11-13 深度研究」,未入库,结论摘入本文),又查出 12 组代码里现在就有的缺陷和 13 项缺失,其中 10 组缺陷在哪份计划里都没登记。再往两份设计里各塞一点,就看不出先做什么、哪些并进哪里(用户 11-13:「关于记忆的,我觉得你需要重新整理开发计划」)。
- **本文是长期记忆唯一的排期入口**。[B-300 设计](../specs/2026-11-11-b300-memory-provenance-design.md)、[B-176 设计](../specs/2026-10-10-b176-long-term-memory-v2-design.md)和 [B-176 计划](2026-10-10-b176-long-term-memory-v2-plan.md)仍是「怎么做」的依据;**做什么、先后、代价、谁来定,只看本文**。B-176 计划里的阶段顺序与并行波次(§1、§2)以本文 §2 为准。
- **11-13 用户拍板**:
  1. B-300 开工前先做深度研究,研究后重排计划:「关于记忆的,我觉得你需要重新整理开发计划」。
  2. 研究查出的六项小修**全部并入 B-300**:D1(整理要过滤已作废 / 已过期的记忆,写汇总前再确认一次)、D2(写入安全扫描补到所有写入路径,按条丢弃而不是整批丢弃,审计事件真的发出来)、D3(提炼输入加总量上限、检查回复是否被截断、加计数把「解析失败」和「这轮没什么可记」分开)、G9(两处复核提示词带上记忆的日期和今天的日期)、D6 前半(汇总行带出处和分数)、D4 + D5 前半(整理按用户轮转,有排序和游标;频次加分挪到预算截断之后)。
  3. B-176 的顺序改为:**中文评测(M1)→ 删除语义与写入审计(M0-2 的范围)→ 服务对象隔离(M4)+ 敏感内容开关 → 终端用户入口最小集(M8)** 先行;之后才是其余:检索与提炼质量(M2 / M3)、记忆工具与画像(M5)、保留期与上限(M6),从经验里学做法(M9)放最后。
  4. 形式:一份总计划;B-300 与 B-176 的设计文档保留;排期和范围只从总计划读。
  5. 关于「健康类智能体默认关」,用户问:「平台怎么确定是健康类的智能体」—— 平台没有智能体分类,也不该由平台来判断。**处理办法(助手提出;用户随后定了,见下面两组追加拍板)**:平台默认值维持现状(智能体配置里没写 `memory.long_term` 就不开长期记忆);另加两个通用开关 —— 按用户退出(同时停读和停写)、按智能体「不记哪几类内容」(由配置智能体的人选)。平台的文字和逻辑里不出现任何具体行业。是否需要单独同意的记录,请法务确认。
- **11-13 用户追加拍板(看过本文初稿后)**:① 「这两个开关延后」—— 按用户退出、按智能体「不记哪几类内容」两个通用开关**移出步 4,延后**,什么时候做另等用户指令;平台默认值维持现状(没配 `memory.long_term` 就不开),平台不判断行业。上面第 3、5 条里「+ 敏感内容开关」「另加两个通用开关」以本条为准。② 「暂时不做导出」—— 步 5 按 B-176 设计 §8.4 的一期(列出、删单条、批量删),不加导出。③ PR A 不单独上生产(用户:「不单独上吧」),三个 PR 同一班车,见 §2.2。
- **11-13 用户第三轮拍板(把没定的全部定掉;与上面各条冲突处以本组为准)**:

  2. **G13 单条消息 1000 字截断**:步 6 改成按句切块(与增量提炼一起做);B-300 只加「截断发生了多少次」的计数。
  3. **§4 全部确认**:四项不做(图记忆、敏感信息自动识别、追公开榜单分数、参数级记忆);三项缓做、不排期(从经验里学做法 M9、多模态记忆、每条记忆写入都要人批)。
  4. **两个通用开关**(按用户退出、按智能体「不记哪几类内容」):计划里不留位置,等用户指令(不变);与它们相关的两个问题一起搁置(§6.1)。
  5. **删会话不删由它提炼出的记忆**;对外文档必须写清:删了什么、还留着什么、怎么删记忆。
  6. **逐条写入记录表(B-176 M2-3)提前到步 3**;**M0-1、M0-3 都在步 3 做**。
  7. **保留期和条数上限**:用户先选「都不设」,随后更正:「我选错了…我决定按你推荐的做」—— **软过期 + 条数上限兜底,步 8 做**:(a) 提炼时给每条记忆估一个有效期,分几档;(b) 到期后交模型复核,三种结果:保留 / 删除 / 延期;用户明确更正过的记忆不做到期复核;(c) 每个用户一个条数上限兜底,超了先清置信度最低、最久没用的;不按时间硬删。档位长度和上限的具体数值,步 8 开工前按步 2 的评测集和生产记忆量报用户定。
  8. **D11**:行锁留在步 6;重算向量的工具不做,等真要换向量模型时再做。**D5 后半**(被质疑的记忆是否降权、召回频次是否继续参与排序):步 6 做,做法由步 2 的评测结果定。**D6 后半里的「汇总行复查」**:步 8。

## 4. 不做 / 缓做(用户 11-13 全部确认)

**不做**

| 项 | 一句话理由 |
|---|---|
| 图记忆 | 贵(每条内容要多次模型调用),且没有证据表明比调好的向量检索加作用域过滤更好;有项目已把图记忆从开源版里删掉(mem0 `docs/migration/oss-v2-to-v3.mdx`,源码级) |
| 敏感信息自动识别 | 靠规则识别敏感内容会绑定某类内容和语言,不通用,误报多。形态相近的开源项目试过自动探测,因误报在代码里暂时禁用(OpenViking `docs/zh/concepts/13-privacy.md`,源码级)。替代办法是「不记哪几类内容」的开关,那个开关目前搁置(§6.1) |
| 追公开榜单分数 | 各家自报分数互不可比,同一系统被不同方测出的分数差得很远(搜索摘要级);目标是自建的中文分环节评测(步 2) |
| 参数级记忆(把记忆训进模型) | 平台用的是各家托管模型,没有这条路 |
| 按时间硬删记忆 | 用户定的是软过期:到期交模型复核,不是到期就删(步 8) |
| 重算向量的工具(D11 后半) | 现在不换向量模型,用不上;触发条件:真要换向量模型。届时靠 B-300 加的「向量模型名」列分清新旧 |
| 终端用户记忆导出 | 11-13 用户:「暂时不做导出」 |

**缓做、不排期**

| 项 | 一句话理由 |
|---|---|
