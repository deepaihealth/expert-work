# 文档站点(三视角)Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 公开 API 文档站(VitePress,`/docs/`)+ admin-ui 应用内文档页(`/handbook`,使用手册全员/平台运维仅 system_admin),全中文。Spec:`docs/superpowers/specs/2026-08-11-docs-site-design.md`。

**Architecture:** VitePress 站源码放 `apps/admin-ui/docs-site/`(**admin-ui 的 docker build context 就是 apps/admin-ui,放仓库根会 COPY 不到**),产物进 admin-ui 镜像 nginx 的 `/docs/` location;应用内文档 = `src/docs/{tenant,ops}/*.md` 经 Vite `?raw` glob 打包 + `markdown-to-jsx` 渲染(既有依赖),SPA 路由 **`/handbook`**(**不能用 `/docs`——会撞 nginx 的静态 location**)。

**Tech Stack:** VitePress + pnpm(corepack 10.14.0,与镜像 build stage 一致)、React + antd、markdown-to-jsx。

## Global Constraints

- **机密红线**:任何文档不得出现凭据、密钥名、金库路径、内网地址、集群连接串。运维篇从 runbooks 改写时只保留操作语义。评审必须专项扫这条。
- 文档内容里的 API 事实必须能溯源到代码(端点/参数/错误码写明出处文件,评审对照);**禁止凭记忆编造参数**。
- SPA 路由用 `/handbook`,nginx 静态区用 `/docs/`,两者不得互换。
- VitePress config `base: "/docs/"`(否则资产路径 404)。
- front-matter 只支持 `title` / `order` / `group` 三键,手写 8 行解析器(不引 gray-matter——浏览器端 Buffer 坑)。
- 角色:平台运维组 = 菜单显隐 + 页面内过滤 + 直连 slug 404 三重;判定沿用 admin-ui 既有 `isSystemAdmin` 通路(navModel 注释说的 belt-and-suspenders 先例)。
- i18n 新键 en+zh-CN 同步(界面文案;文档正文本身纯中文不进 i18n)。
- 变异自证仓库铁律:每条新断言 break→red→restore→green。
- 验证:`cd apps/admin-ui/docs-site && pnpm build`;`cd apps/admin-ui && npx vitest run src/pages/__tests__/Handbook.test.tsx && npx tsc --noEmit`。

- [ ] **Step 2: 六篇正文**。每篇的事实出处(写作时必须打开对照,文中 curl 示例域名用 `https://<your-domain>` 占位):
  1. `quickstart.md`——流程:管理员发 key(指到认证篇)→ `curl -N -X POST …/v1/agents/{agent_code}/runs` 带 `Authorization: Bearer <key>`、body `{"user_id":"u-123","input":"你好","mode":"stream"}` → SSE 回流。出处 `services/control-plane/src/control_plane/api/agents.py`(`run_agent_for_user` + `ExternalRunRequest`)。
  2. `auth.md`——服务账号↔key 关系(钥匙/持钥人)、scope 三档 read/write/admin 语义与选择(调 run=write,queue 轮询加 read,admin 永不外发)、key 格式前缀、轮换(grace 窗口)与回显、过期语义(可空=永不过期,建议设置)。出处 `packages/expert-work-protocol/src/expert_work/protocol/service_account.py`、`services/control-plane/src/control_plane/auth/api_key_verifier.py`、`api/api_keys.py`。
  3. `run-agent.md`——全参数表(`user_id` 必填含语义:自动铸终端用户,记忆/工作区/计费 key 其上;`session_id` 续会话=响应头 `X-Expert-Work-Session-Id`;`input`;`mode` stream/queue;`image_refs`;`untrusted_content`)、`agent_code`=租户 ACTIVE agent 名、202 queue 形态。出处 `agents.py` 的 `ExternalRunRequest` + `run_agent_for_user` docstring。
  4. `sse-events.md`——改写 `docs/api/streaming-events.md` 成对外口径(事件类型、帧结构、结束帧、断线重连建议)。
  5. `errors.md`——401(key 无效/过期)/403(scope 不足)/404(agent 不存在)/413(文档超限)/429(两种:限流、workspace is full 文案)语义与建议动作;限流与配额概念一段。出处 `agents.py`、`api/uploads.py`、限流中间件。
  6. `best-practices.md`——服务端调用(CORS + key 泄露)、`user_id` 取值设计(稳定、每终端用户唯一)、key 保管轮换、stream 断线处理。
- [ ] **Step 3: 构建绿**。`pnpm build` 零 error 零 dead link(VitePress 默认坏链即 fail)。
