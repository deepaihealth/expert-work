## 0. 全局约定(每个 PR 都适用)

1. **测试先行**:先写会红的测试再实现;每条新断言做一次「改坏 → 红 → 恢复 → 绿」自证。
2. **真栈用例**:要上测试环境才能验的 PR,同一个 PR 往 `docs/runbooks/pending-test-release-acceptance.md` 加用例(触发方式 / 判据 / 没修好时的表现)。拦截类用例用金丝雀租户与平台中性测试语料,不用对接方的 Agent。
3. **迁移**:只做 expand;revision id ≤32 字符;新表带 `tenant_id` + RLS 策略并进 `test_rls_policy_coverage`;新表进留存清理(`retention-cleanup-job`)。
4. **默认开**:内容安全对所有 Agent 默认生效,不新增「要人去开」的开关(记忆「平台缺口先改默认」)。上线先**影子模式**(只记录不拦截)跑一周,看误杀率再切拦截 —— 影子 / 拦截是平台级运行参数,不是每个 Agent 的配置。
5. **不留原文副本**:事件表只存类别、分数、哈希与截断摘要;摘要过现有审计脱敏器。日志行只打类别,不打内容。
6. **供应商隔离**:所有第三方调用走 `ContentSafetyProvider` 接口;单测用假实现,集成测试不打真供应商;真供应商只在测试环境真栈验。AccessKey 存 `platform_tool_secret`(`secret://` 引用),不进 env 明文、不进 argv。
7. **平台文本**:拒答 / 转介模板、规则公示模板不出现任何租户业务内容。
8. **对外 API**:按外部文档风格指南写;路由登记 gate + lockdown 两张表;`exit_reason` 新取值写进 `sse-events.md` 与 `best-practices.md`。
9. **管理端**:`pnpm typecheck` / `pnpm test` / `pnpm build` 通过;中英文案键一致;改页面前 grep `e2e/` 的 testid。
10. **评审**:每个 PR 合前代码评审;输入 / 输出挂点、对外 API、审计改动加安全评审。

## 2. 各阶段要点与验收

### M0 供应商探针(不进主干代码,产出一页实测记录)
- 金丝雀式脚本(scratchpad)直连护栏:中性正常语料 / 各类违规样例 / 健康类正常问答各 100 条。
- **验收**:记录 p50 / p95 延迟、每类命中率、健康类误杀条数与命中标签;确定一期用护栏还是文本审核 PLUS(看流式与价格);确认接入地域与是否走 VPC;拿到「数据是否留存、留多久」的书面答复;确认能否出具关键词库规模与类别证明。任何一项不满足,回到设计 §3 重新选型再开 M1。

### M1 检测主链路(2~3 个 PR)
- **PR-1 服务与 provider**:`ContentSafetyService`、`Verdict`、护栏 provider(超时、重试一次、熔断)、关键词 provider(Aho-Corasick,平台内置健康领域增补词)、失败策略(必拍 ②)。单测覆盖:命中 / 放行 / 超时 / 熔断 / 兜底。
- **PR-2 挂点**:输入挂点(`runs.py` `validate_prompt_inputs` 之后;`:regenerate` 跳过;触发器在 `_scan_fire_time` 旁并修 run 行状态)、输出挂点(终答分支,与 Judge / DLP 同处)、拒答 / 转介模板、`exit_reason` 三个新值、影子模式运行参数。测试:外部 / 控制台 / `:edit` / 触发器四条入口都被检测(调用点穷举测试,防新入口漏挂);拦截时 run 以 success 结束、会话里有用户消息与模板回复;影子模式下只记事件不改回复。
- **PR-3 事件、审计、指标**:`content_safety_event` 表 + 迁移 + RLS + 留存;审计动作 `content:*`;指标与两条告警规则。
- **验收**(真栈):测试环境金丝雀发正常 / 违规 / 健康类样例,控制台会话、审计页、事件表、Prometheus 四处都对得上;影子模式一周误杀率报告。

### M2 策略与敏感词(1~2 个 PR)
- 策略 / 词表两张表、只能收窄的合并规则(平台拦截不可被租户放行,单测覆盖)、累计处置计数(按租户 + 终端用户,跨副本一致 —— 用库或 Redis,不用进程内存)、两个设置页、批量导入导出、每次变更写审计。
- **验收**:租户加词立即生效(跨副本);租户试图把平台拦截改放行被拒;累计第 N 次后进入暂停、T 小时后恢复。

### M3 复核队列(1 个 PR)
- 列表 / 筛选 / 详情(摘要已脱敏)、确认与误判、误判一键白名单(写审计);Judge 拦截补审计;输出审计 `resource_id` 改为 run_id(查现有读者,确认没有人依赖字面量 `"agent"`)。
- **验收**:截图位就绪(设计 §6 材料 2、3、4)。

### M4 投诉举报(2 个 PR:后端 + 对外文档,管理端)
- 对外接口、投诉表(状态、时限、处理人、处置记录)、处理台、超时告警、联动动作。
- **验收**:对接方用 API key 提交与查询;超时触发告警;联动下架后检索不再命中该文档。

### M5 内容安全评测(1~2 个 PR + 题库数据)
- 套件与判定、题库 YAML(按 31 类 + 健康专项组织,带来源标注)、发版前跑接入执行单。
- **验收**:一期回归题库全量跑通,出合格率 / 拒答率 / 误拒率三个数;健康类非拒答题误拒率单列。

### M6 知识库(1 个 PR)
- 入库检测、两种新状态、检索过滤、四种操作审计。
- **验收**:违规文档不进检索并进复核队列;下架 / 恢复即时生效;审计页能按动作查到。

### M7 生成内容标识(1 个 PR + 技能版本)
- 元数据写入的落点(`save_artifact` 落盘前统一处理,或平台技能共享层)按当时代码定;`health-plan-report` 页脚加显式标识,出新技能版本。
- **验收**:用 `python-pptx` / `pypdf` 读回元数据字段;交付件页脚可见标识。

## 3. 发布

- 一期合入后随下一班车发测试,影子模式跑满一周、误杀率报告给用户拍板后再切拦截。
- 切拦截前通知对接方:新 `exit_reason`、`token` 预览必须以 `updates` 替换(B 方案前提)。
- 执行单要加的项:生产护栏开通与 AccessKey 录入、平台默认策略导入、影子 → 拦截切换步骤与回退(切回影子即可,不需回滚镜像)。
