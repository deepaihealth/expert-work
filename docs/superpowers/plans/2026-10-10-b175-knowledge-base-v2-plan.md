## 0. 全局约定(每个 PR 都适用)

1. **测试先行**:先写会红的测试,再实现;每条新断言做一次「改坏 → 红 → 恢复 → 绿」自证。
2. **真栈用例**:要上测试环境才能验的 PR,同一个 PR 往 `docs/runbooks/pending-test-release-acceptance.md` 加用例(触发方式 / 判据 / 没修好时的表现)。
3. **迁移**:只做 expand(新列可空或带默认值、新表、新索引),三段式发布;revision id ≤32 字符;新表带 `tenant_id` + RLS 策略并进 `test_rls_policy_coverage`。
4. **存储契约**:SQL 与内存两套 store 谓词同义,新增方法补参数化契约测试(内存档进单元 CI,SQL 档 integration)。
5. **管理端**:`pnpm typecheck` / `pnpm test` / `pnpm build` 通过;中英文案键一致;跨租户只读置灰语义不变。
6. **对外 API**:按设计 §8.3 的清单;按风格指南写文档、同步侧栏、`auth.md`、`errors.md`;构建与死链检查通过。

8. **知识库与记忆解耦**:改重排 / 嵌入相关代码时,记忆侧行为必须不变,补测试锁定。
9. **评审**:每个 PR 合前跑代码评审;安全相关(开放 API、权限、key)加安全评审。

## 3. 各阶段 PR 切分

### P0 地基修复(2 个 PR)

**P0-PR1 入库可靠性 + 切块乱码**
- 迁移:`knowledge_document.ingest_generation`。
- `sql.py`:认领 / 重传递增代际;`replace_chunks` / `set_document_status` / `mark_document_failed_terminal` 写回加 `status='processing' AND ingest_generation=:mine`;去掉 `upsert_document` 里提前删分段;内容哈希相同且就绪返回「未变化」;终态巡检方法。
- `recovery.py`:先跑终态巡检;认领数 = 可并发数,处理中续约。
- `ingestion.py`:快速通道全局并发上限;嵌入 429 退避。
- `chunking.py`:重叠只取到语义边界(段落 > 换行 > 句号),修 U+FFFD;`_hard_split` 保留换行。
- 测试:两个并发 worker 复现「旧覆盖新」;第 5 次尝试崩溃后被巡检置 failed;中文重叠无 U+FFFD。
- 真栈用例:重传同名文件期间文档持续可检索;同内容重传不重新嵌入。

**P0-PR2 审计 + 上传上限 + 分页 + 管理端按角色**
- `api/knowledge.py`:全部写操作 `emit` 审计;上传流式读入 + 字节上限(413)+ 配额准入;库列表 / 文档列表分页(`limit`/`offset`/`total`)。
- 管理端:列表分页;按角色隐藏 / 置灰写按钮(viewer 只读、operator 无删除);`KnowledgePicker` 校验库存在。
- 测试:审计行形状;超限 413;viewer 看不到写按钮(vitest)。

**验收**:设计 §2 缺陷 7、8、9、10、11、12(角色部分)关闭。

### P1 评测基准(1 个 PR + 数据)

- 产出:基线数字写进 PR 与 ROADMAP。

### P2 检索质量(4 个 PR)

**P2-PR1 中文关键词**
- 先在测试 / 生产 RDS 实查 `pg_available_extensions`;用 P1 评测集对比两条路线:A 应用侧 jieba 搜索模式 + 停用词 + `to_tsquery('a|b')` + `ts_rank_cd`;B `pg_jieba` / `zhparser` text search configuration(+ `rum`)。选优者落地。

**P2-PR2 向量参数 + 融合**
- `search_scored`:事务内 `SET LOCAL hnsw.ef_search` / `iterative_scan = strict_order`,失败降级;候选 `clamp(2k,100,200)`。
- 加权 RRF(k=60)替换等权融合,保留子分数;记忆侧继续用原 `rrf_fuse_scored`。

- **离线验证**(先做,不进主干):一家真实资料包跑「抽取 → 引用 → 去重 → 摆矛盾」脚本,人工抽查准确率、矛盾数、条目 vs 原文检索命中率;数字出来再定范围。
- PR1 流水线:条目表、任务、按库串行、抽取 / 引用 / 三层去重 / 合并提示词、预算上限。
- PR2 确认队列:`knowledge_review_item` 统一队列(条目、矛盾、AI 生成项、解析异常)、确认 / 修改 / 驳回 / 锁定、审计;源文档更新 / 删除的撤回。
- PR3 管理端:确认台、条目浏览、矛盾并排对比。

### P8 FAQ 类型(2 个 PR)

### P9 数据源(2 个 PR)

### P10 物料库(按原 B-172 M0~M5)
