## 去查的结果：我的因果模型错了一个数量级

预测里我算的是「省掉 20,064 字符的重打 ≈ 5,016 输出 token × 18ms ≈ 90 秒」。

**实际省了约 950 秒。差 10 倍。** 原因是我只算了「少写一个文件」，没算**那个文件引发的连锁**：

基线那一次实际写了 **46,385 B**，不是 20,064：

| 写了什么 | 字节 | 那东西本来就在工作区里吗 |
|---|---|---|
| `style/render_plan.py` | 20,064 | **在**（重打） |
| `style/PLAN_STYLE.md` | 2,591 | **在**（重打，我原先漏数了这个） |
| 方案 JSON 第一遍 | 11,619 | — |
| 方案 JSON 第二遍 | 12,111 | 同一轮里又写一遍 |

而重放只写 15,944 B（JSON 一次，且比基线那份**更大**）。

**真正的机制**：`list_dir` 报 `sandbox create failed: 504` → 模型判定 `style/` 不存在 → 重建渲染脚本 → 重建版式锚 → 拿不准又把 JSON 写两遍 → 每一步都是额外的 LLM 轮次。**24 → 13 次调用，差的 11 次就是这条连锁。**

所以：**一次失败的目录探测，赔的不是一个文件，是半个 run。** 这一点在开跑前我没想到，是数据告诉我的。

## 按开跑前写死的判读规则

老臂 269s ≈ 新臂 222s（都远低于基线 1,178s）→ **本波对这个场景的贡献 ≈ 0**。

代入公式：`(269 − 222) / (1,178 − 222) = 4.9%`。而两臂的散布是 177~254 与 256~283，**区间重叠**。
n=3 说不出 4.9% 是真信号还是噪声。**诚实结论：在这个场景下测不出本波的贡献。**

## 那 5.3× 是哪来的

**09-16 那次是异常值。** 证据链：

1. 基线有 **2 次 `list_dir` 失败**；今天两臂共 4 次 `list_dir` 调用，**0 失败**
2. ai-health-plan 全体均值是 **228s**，两臂（222 / 269）都落在均值附近
3. 基线 1,178s 是 298 个 run 里第 5 长的

**今天跑什么版本都快，因为那天让它慢的东西今天没发生。**

## 所以本波的价值是什么

不是「更快」，是**把那次异常的成因结构性地切断**：

| | 09-16 那次 | 现在 |
|---|---|---|
| `list_dir` 怎么实现 | 每次一次沙箱 exec | 宿主侧 NAS 本地目录操作 |
| `sandbox create failed: 504` | 会发生 | **没有发生通路** |
| 模型把失败读成「文件不存在」 | 会 | #1639 改了错误文案 |

**这是尾部风险，不是均值改进。** 期望收益 = 故障概率 × 故障代价，而故障代价实测约 900 秒（一次失败的探测引发连锁重建：重写渲染脚本 + 重写版式锚 + 方案写两遍，LLM 调用 13 → 24）。

**尾部风险统计上测不出来** —— 今天 7 次真栈重放一次都没撞上那个 504。

## 关于工作区块的负面结果，要如实记

三次老臂（没有块）里，模型**全都自己 `read_file` 读回了已有文件**，一次都没重打。

这与群体统计一致：279 个「文件已存在」的后续 run 里，44%（123 个）是读回来用的，只有 5%（13 个）重打。**模型本来就大多会读。**

所以工作区块要证明价值，得瞄准那 5%，而 n=3 看不见 5%。**本次验收不构成它的证据，也不构成它的反证。**

## 方法论教训

我记过一条「**在不可能失败的条件下验证等于没验证**」。这次是它的变体：

> **我在故障不会发生的时段，去统计那个故障有没有减少。**

分辨判据：**先问「被修的那个故障，今天还会不会发生」。**
- 会发生 → 统计对比有效
- 不会发生（已被结构性切断，或本就低频） → **必须改用结构性验证**，去证明「不可能」，而不是统计「没出现」

第二条：**两臂都要跑。** 只跑新臂时我报了 5.3×，还附了一堆看起来严谨的机制解释（连锁重建、输出 token 对账、逐项拆解）——那套解释每一条都对，唯独把功劳归错了人。**自洽的因果故事不是归因证据，对照组才是。**
