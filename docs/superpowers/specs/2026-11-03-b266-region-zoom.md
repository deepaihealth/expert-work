# B-266 看图「放大局部」

日期:2026-11-03 · 状态:用户 11-03 已确认 · 同分支带 B-263(上传图片转正 + 提质)

## 为什么做

实测(豆包 seed-2.1-pro,合成密集化验单 2480×3508,24 题 × 2 次,共约 ¥11):

| 看法 | 小字读对 | 用时 p50 | 每题费用 |
| --- | --- | --- | --- |
| 整页快看 | 10% | 2.7 s | ¥0.0095 |
| 整页 + 深看「低」 | 27% | 38 s | — |
| 先定位(0–1000 框)→ 裁 ≥1/6 页 → 快看 | 65% | 5.4 s | ¥0.018 |
| 定位 → 整宽横条 + 上方一条 | 90% | 5.3 s | ¥0.027 |
| **切 2×3 块并行快看,看不到答 NOT_FOUND** | **92%** | **约 3 s** | ¥0.051 |
| 人工给准区域(上限) | 100% | 1.9 s | ¥0.0095 |

- 厂商不论图多大都压到约 1,400 输入 token;裁剪 = 同样预算看更小面积。放大像素没有增益。
- 区域里有目标就读对;读错几乎都是没裁到。定位常见错法是「高度对、栏错」。
- 加了「看不到就答 NOT_FOUND,不要猜」之后,285 张不含目标的块 / 条**没有一张编数字**。
- 剩下的错全在 7–8 像素的字。
- 主模型多数看不见图(Path B),它没法自己指定区域。

**通用性复查(11-03,豆包,合成样本)** —— 2×3 块 + JSON(J6)只在化验单上好,换题型就坏:

| 题型 | 2×3 块(J6) | 重设计:门槛 + 整宽横条 + 并行整张读 |
| --- | --- | --- |
| 化验单具体数值(L) | 100% | 24/24 |
| 手机照片(P) | 67% | 5/6 |
| 幻灯片 / 宽表(S) | 67% | 6/6 |
| 图表(C) | 33% | 6/6 |
| 长截图 | — | 6/6 |
| **具体问题合计** | — | **98%**(只看整张 44%) |
| 整张图的问题(计数、比较、整体) | 1/12 | 11/12(唯一一错由规则 4c 修掉) |

- 2×3 把图表的轴 / 图例、宽表的表头与数值、整张图的问题切散了;整宽横条不竖着切,一行永远在某一条里。
- 门槛灵敏度:门槛降到 300 万像素时图表会被切开,多出一个错答案;400 万像素时图表都整张读。

## 方案

### 1. `ask_image` 加 `region`

- `region: "auto"` —— 只为「在一张大而密的图里读一个具体的小字值 / 名字 / 日期」。一律快看(`depth` 忽略并在 `meta`
  注明):推理交给主模型。进程内同时在飞的切块 / 整张读调用不超过 12 个,排队时间算在单次上限里。
  1. **门槛**:图不到 **400 万像素** → 不切,整张快看一次照常返回,结果里说明「图够小,整张读了」,`meta.auto="gated"`。
     像素怎么算:图片是转正后的原像素;**文档页按放大用的 300 dpi 算**(A4 = 2480×3508 ≈ 870 万像素,即验证用的
     合成化验单尺寸)。文档页没有「原像素」(矢量),已有整页渲染只有 100 dpi(A4 ≈ 97 万像素),拿它比会把每一页都当小图,
     所以用 100 dpi 渲染的像素 × (300/100)²。**门槛只用这个 300 dpi 的量**;横条实际按多少 dpi 渲见 §2
     (大幅面会降到 300 以下,门槛不跟着变)。
  2. **整宽横条**代替 2×3:条数 N = ceil(像素 / 150 万),夹在 3..8;相邻两条重叠条高的 **12%**;每条横跨整个宽度,
     合起来盖满整个高度(一行字只要不高过重叠,总在某一条里整行可见)。宽:高超过 **4:1** 的图改切**竖条**
     (整高、沿宽度切);每条长边:短边尽量不超过 8,超了就少切几条(最少 3 条)。文档页的横条在沙箱里按 300 dpi 渲,图片按原像素裁
     (单条超过约 150 万像素才缩,从不放大)。`meta` 里留每条的 0–1000 框。
  2a. 横条准备不出来(渲染失败、图解不开)→ 仍整张快看一次,标「整张读,小字可能不准」
     (`full_fallback` / `bands_unavailable`);给主模型与 `meta.bands_error` 的只有异常类型和一句固定的话
     (异常文字可能带 NAS 路径,细节只进日志);整张读也失败才报错。**文档在整页渲染之后改过(stale)照样报错**,
     与指定框一样:整张读看的也是那张过期的页,不能拿来回答。
  3. **同时并行整张快看一次**:原问题、不加 JSON 要求,用它的普通回答文字;计入记账与在飞名额(一次 auto 共 N+1 个调用)。
  4. **最终答案**:
     - (a) 横条按下面的保守相容判定给出**唯一一致**的值 → 用它(`meta.auto="bands"`);
     - (b) 横条冲突或都没读到 → 用整张读的回答,明确标「整张读,小字可能不准」,附上各条读数与框,主模型可以拿框
       再用 `region=[…]` 问(`full_fallback`);
     - (c) **只要有一条报 `partial`,就不采用横条的值**,按 (b) 用整张读(验证里一条只数到自己那一截的计数推翻过
       整张读的正确答案);
     - 有一条报 `partial`、或横条冲突 / 都没读到,而整张读又失败 → 回「没有可靠的读数」加各条读数与框,
       **不拿任何一条的值当答案**;
     - (d) `meta.auto` 记 `bands` / `full_fallback` / `gated`,`meta.auto_reason` 记原因
       (single / conflict / none / partial / bands_failed / small_image;要退回整张读而整张读也失败时仍是 `bands`,
       原因带 `+full_failed`)。横条与整张读全失败才报错,与整页看失败同一种错误。
  - **每条横条回一小段 JSON**(review 11-03 改,原来是只回 NOT_FOUND):问题原样,后面加英文平台说明 ——
    只回 `{"status":"found|not_found|partial","label":"<值旁边印的行名/字段名>","value":"<要问的值或文字(数、名字、日期、词……),照印的写,保留 < > ↑ ↓ ± (-)>","unit":"<照印的单位>"}`;
    看不到这一项或它的值用 `not_found`;**只看这一截不够回答**(要在整张图上数、比,或要看这里看不到的坐标轴、
    图例、行 / 列表头)也用 `not_found`;值被边缘截断用 `partial`,不要猜。所有厂商都只靠提示词
    (GLM-V 没有 `response_format`,Qwen-VL 带图时会降级它),各家原生结构化输出以后再说。
    实测(豆包,2×3 块,24 题 × 2 次):**J 94% 读对,不含目标的块 0/236 报「找到」,288 次回答 100% 是合法 JSON**,label 48/48 对。
  - **解析阶梯**(每块一样):先去 `<think>…</think>` 再截到 4 KB(推理模型的思考可能有几 KB,先截会把后面的 JSON 截掉;去 think 之前另有
    64 KB 的上限;合法回答不到 300 字符;配平扫描是一遍扫完的线性算法 ——
    round 2 前的写法是平方级的,2 万个 `{` 要 8.7 s,而它在共享事件循环上跑)→ 去 `<think>…</think>` 与代码围栏 → `json.loads` → 第一个配平的 `{…}` → 字段校验
    (`status` 不分大小写)→ 交叉核对:`found` 但值为空或值本身是「没看到」→ `not_found`;`not_found` 却带值 → 仍是
    `not_found`(原文留在 meta)。**完全不是 JSON 才走散文兜底**:回答里任何位置有 NOT_FOUND / NOT FOUND,或**整句**
    命中「看得见 / 有没有」词表(未找到、找不到、看不到、看不清、无法识别、图中没有…、被截断、not visible、cannot see、
    N/A、单独的「无」「没有」—— 这几个单字**只在散文兜底里**认,JSON 里 `found` 的值是「无」仍是一个读数)→ 没看到;化验结果词(未检出、未见异常、阴性、无异常、-、+、<0.5、Not detected)一律仍是值;
    ≤ 40 字且带数字或定性词 → 值(`parse_mode="prose"`);其余 → 读不懂,**从不算作值**。拒答 / 截断 → 这一块报错。
  - **读数归一**:NFKC(全角转半角)、统一减号、只在数字之间统一范围分隔符(~ ～ 至 – —)、只去 `\d{1,3}(,\d{3})+`
    的千分位逗号;上标数字先展开成 `^数字`(在 NFKC 之前,否则 10⁹ 会被压成 109);拆出比较符(< > ≤ ≥ 小于 低于 大于 高于)、数(Decimal,含 1.2×10^9 / 1.2E9;指数绝对值超过 50 或数字串过长就当文字比)、范围、升降标记
    (↑ ↓ H L 偏高 偏低 *)、单位(只统一写法:大小写、μ/µ/u、×10^9/L ≡ 10^9/L ≡ 10*9/L,**从不换算**)、定性等级
    ({阴性, -, (-), negative} / {阳性, +, (+), positive} / {±, 弱阳性} / ++ / +++ 各自一级)。
  - **相容判定宁可报冲突,不可错合并**:数按 Decimal 相等(5.6 = 5.60,无容差);两边都有单位时写法必须一致
    (g/L 与 g/dL 冲突),一边没单位算相容;比较符必须一致(<0.5 与 0.5 冲突,并提示可能是图块边缘截掉了「<」);
    ↑ 与 ↓ 冲突;范围两端都相等;定性同级;文字归一后逐字相等。一个读数要与组内**每一个**相容才进组。**不投票**。
  - 横条读数的汇总(用在 (a),以及 (b)(c) 附在整张读后面):
    - **单值** → 最完整的原文(如「5.6 mmol/L ↑」)、label、哪几条读到、几条 not_found / partial、不同写法;
    - **冲突** → 每块一行(位置、0–1000 框、label、原文),注明「label 不同 → 多半是不同的行 / 列」或「同一 label、读数不同」,
      主模型可以拿框再用 `region=[…]` 看;
    - **全无** → 明说「各块都没看到,可能字太小或页面上没有」,不编;有块报 `partial` 时建议看这几块的并集框(值多半在接缝上);
    - 读不懂的块、失败的块各说一句,不算作值。
  - `meta.bands[*]`:status、原文(≤200 字)、parse_mode、label、value、unit、box、dpi / 像素;`meta.full`:整张读的
    回答(≤200 字)或失败原因;`meta.auto_pixels`:门槛用的像素数。
- `region: [x1, y1, x2, y2]` —— 0–1000 整数坐标(看图模型自己报框就是这个尺度,实测让它报 0–1 比例全部失败),
  只看这一块。主模型能看图时、或看图模型已经说出位置时用。
- 校验:四个整数、`0 ≤ x1 < x2 ≤ 1000`、面积不小于 1%;不合法当场报错。

### 2. 像素从哪来

- **文档页**(`path` + `unit`,pdf / docx / pptx):在沙箱里只渲染所需区域,`pdftoppm -x -y -W -H`,
  分辨率按区域面积自动定,让每块约 1.5 百万像素(上限 400 dpi)。一次沙箱执行渲完全部块。docx / pptx 复用
  `read_page` 已转好的 PDF,和 `read_page` 共用同一把按 `(run, path)` 的锁。
- **上传图片 / 工作区图片**:宿主机用 Pillow 从存储的字节裁(原像素,不放大),解码上限同 B-263(6000 万像素)。
- `region="auto"` 的横条:文档页按 min(300 dpi, 每条不超过 300 万像素, 长边不超过 4000 像素)渲 —— A0 等大幅面
  会降到 300 以下(厂商单边上限 8000,留一半余量);一次沙箱执行渲完全部横条;每条 pdftoppm 限 20 s,
  最多 8 条 + 重转一次 PDF(90 s)仍在沙箱 300 s 的兜底之下。图片照上面按原像素裁,超过约 150 万像素或长边
  4000 像素就等比缩(从不放大)。
- 指定框(`region=[…]`)同样有长边 4000 像素的上限(又细又长的框按面积定会出上万像素宽的图)。
- 文档页局部的文件名带实际 dpi:`page-<N>-<x1>-<y1>-<x2>-<y2>-d<dpi>.jpg`,只复用同 dpi 的图 —— 一个与某条横条
  相同的指定框按自己的 dpi 重渲,不拿 300 dpi 的横条顶替;`meta` 报的 dpi / 像素就是实际的。图片的裁图由
  「源图哈希 + 框」唯一决定(缩放规则是确定的),文件名不带 dpi。
- 宿主裁图进程内最多 2 张同时解码:名额在进线程之前用 `asyncio.Semaphore` 拿,线程池里的线程从不阻塞着等;
  同一 run 同一张图的裁图按 (run, 裁图目录) 排队,后来的直接复用。
- 裁出的图写进本对话 `.tool_results/<run>/crops/<源 sha + 框 + dpi 的哈希>.jpg`(B-262 之后就在本对话目录),
  按工作区 ref 交给看图模型 —— 模型接口、适配器都不用改。同一张图同一个框再问,直接复用。

### 3. 主模型能看图的智能体(Path A,用户 11-03 拍板一起做)

- `read_page` 加同样的 `region: [x1, y1, x2, y2]`(不支持 `auto`:主模型自己看得见整页,自己挑框)。
- 区域按上面的规则高分辨率渲染,像普通页一样内联给主模型,进 `viewed_figures`(渲染页形状的正则扩一种 `crops` 形状)。

### 4. 什么时候用(工具说明 + 结果提示)

- 工具说明(英文、通用、零租户 / 行业用词):默认看整张;`region="auto"` 只用来在一张大而密的页面或照片里读一个
  具体的小字值、名字或日期;**计数、比较、趋势、「哪个最高」、关于整张图的问题一律不用它**;结果说不确定时,
  用明确的框再问,或如实告诉用户不确定;字看清了还要推理才用 `deep`。
- 整页快看之后,只有 `region="auto"` 不会被门槛挡回的图(同一个 400 万像素判据,文档页按 300 dpi)才在结果末尾提示,
  措辞与工具说明一致:读一个具体小字值 / 名字 / 日期时可以用 `region="auto"`,计数、比较、整体问题不要用。
- 平台文本零租户内容。

### 5. 观测

- `meta` 记 `region`、`auto` / `auto_reason`、门槛像素、每条横条的结果与框、整张读的回答、横条汇总结论;
  看图用量按实际调用次数计(一次 auto 是 N+1 次)。
- 计数:`expert_work_ask_image_region_auto_total{path, reason}`,path = bands / full_fallback / gated。

## 不做

- 不默认自动切块:只有模型主动要 `region="auto"` 时才切。
- 不做按文字方向自动转正(只按 EXIF 标记,见 B-263)。
- 7–8 像素字的剩余误差:暂不做更细的切法;上线后看真实数据再定。
- 各厂商原生的结构化输出(`response_format` / json_schema):以后再说,现在所有厂商都只靠提示词。

## 已知缺口(review round 2 记下,暂不改)

- B-263 PNG 重编码超字节上限时直接 413,没有先试 `optimize=True` 再存一次。
- 整页快看后判断要不要加 `region="auto"` 提示时,会为读尺寸多解析一次图(上传图走缓存,工作区图片会多读一次盘)。
- `read_page(region=…)` 每次先完整重渲一次整页(拿页面尺寸与转好的 PDF),再渲局部。
- 用 `image_ref` 手写的渲染页 ref 带 `region` 时,在宿主从 100 dpi 的整页图上裁(不走沙箱高分辨率渲染)。
- 线性配平扫描在**残缺**的输入上与原来的逐个起点重扫可能挑出不同的 `{…}`(字符串状态只从第一个 `{` 起算一次);
  失败方向是保守的 —— 挑不出合法对象就走散文兜底 / 读不懂,不会编出一个值。
- 极端宽高比的下限:横条最少 3 条,宽:高接近 4:1(还切横条)的图每条长:短可能仍超过 8(约 11:1)。

## B-263(同分支)

上传图片先按 EXIF 方向转正再删元数据;JPEG 质量 92(保持 4:2:0)、WebP 90;超过 6000 万像素的 JPEG 用
`draft` 直接解码成小图后接收,其它格式超限 413。

## 验收(发测试后手册新节)

- 指定框、docx / pptx 页、上传照片(带方向标记)各一例;Path A 智能体 `read_page(region=…)` 一例。
- 花费约 ¥2。
