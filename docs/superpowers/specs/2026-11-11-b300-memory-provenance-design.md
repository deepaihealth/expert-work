## 0. 一页看懂

**问题**:长期记忆不区分「用户说的」和「助手自己得出的」(从工具结果、附件里看来的,或自己推断的)。助手得出的内容被当成用户事实记下;下次助手再得出同样的内容时,召回这条记忆,把它当成旁证 —— 同一个错误自己给自己作证。这对任何内容都成立:一个订单号、一个人名、一条合同条款的理解、一句「客户倾向续约」、一个读数。

**一个实例**(测试环境,ROADMAP B-300 行):同一张照片上的值,对话甲里看图读错了;对话结束后被提炼成一条记忆(置信度 0.8,且是英文);几分钟后对话乙再看同一张图又读成同一个错值,召回了这条记忆,回答「与历史数据吻合,可信度较高」。

**四条改动**:

| 序 | 改什么 | 程序保证的 | 只是措辞的 | PR |
|---|---|---|---|---|
| ④ 语言 | 记忆用用户的语言写;程序能认出来时把语言名写进指令 | 判断 | 模型是否照写 | 1 |
| ① 提炼输入 | 不给工具结果、附件、外部内容;**分两次提炼**:一次只给用户在对话里输入的文字,一次给整段对话(用户的话、助手每轮最终回答、调用了哪些工具) | 每次给什么 | 模型提炼得好不好 | 1 |
| ③ 召回提醒 | 记忆块后单独一节;每条带记录日期(PR 2 起带来源) | 渲染 | 模型是否照做 —— **最不稳** | 1 |
| ② 来源 | 一个字段,两个值:用户消息里说的 / 来自助手。由「是哪一次提炼出来的」决定;来自助手的置信度封顶 0.6、召回时带标记、不能覆盖用户说的 | 来源、封顶、拦截 | 无 | 2 |

**为什么关得住**:第一次提炼只看得到用户输入的文字,助手得出的内容不可能从这里出来。而且是**白名单**:只有平台确知是「用户在对话里输入的文字」的消息才进第一次;定时任务的预设话术(可能是助手自己写的)、子智能体的任务说明、旧对话里没有标记的消息,一律不算。

**「用户消息里说的」认不到的四种情形**(标签因此用中性说法,不叫「用户原话」):记忆的句子是模型改写的,不是逐字原话;群聊里同一用户身份下别人说的话也算;员工代客户录入时,打字的人不是记忆的主人;对接方把语音转写、模板和用户的话拼进输入文字时,转写的错字也算。平台只能认到「输入文字」这一层。

**还剩什么风险**:

1. 主模型看到带标记的记忆后仍可能把它当旁证:纯措辞,靠 §8 量。
2. 提醒只管「别拿记忆给新结论作证」;**不管「直接照一条错的来自助手的记忆回答」**—— 那条记忆带着标记,但没有规则要求先核实。
3. 「助手问、用户只答一个词」的内容会被记成「来自助手」(写明是用户回答的)。保守方向的代价,见 §6.2 与 §10。
4. 每次写回多一次模型调用(§4.4)。
5. 同一对话内也可能召回自己刚写下的记忆;助手复述记忆的话可能被再提炼;长对话里提醒节离得远。都没有加专门机制(§6.5)。

**不解决什么**:助手为什么得出错的内容(看图读错归 B-301);记忆串客户(B-176 M4);`remember` 工具那套记忆(B-176 待拍板 #3);旧记忆清洗;排序。

## 3. ④ 语言

**规则只有一条:记忆用用户的语言写。** 程序在认得出来时把语言名写进指令,让这条规则更硬;认不出来时指令仍是同一条规则,只是不点名。

**程序怎么判**(只看第一次提炼的输入,即用户输入的文字;去掉网址、路径、代码块和行内代码后数字符):

| 有信号的字符 | 结果 |
|---|---|
| 不足 20 个 | 不点名 |
| 全是汉字(夹杂的拉丁字母不超过八成) | 点名 Chinese |
| 全是假名,或假名 + 汉字且假名占三成以上 | 点名 Japanese |
| 全是谚文 | 点名 Korean |
| 其它(一种文字对应多种语言的,如拉丁、西里尔、阿拉伯字母;几种文字混着的,如汉字里夹少量假名) | 不点名 |

**只点名这三种是检测能力的限制**:靠数字符,只有一种文字只对应一种语言时才判得准。其它语言的用户走不点名档,行为是「跟随用户的语言」,不降级、不会被写成别的语言。20 个字符的门槛是为了不把只发了几个汉字的日语用户点名成 Chinese;超过 20 个字还一个假名都没有的日文极少,仍可能误判,记为已知。

**两档指令**(追加在两段提炼指令末尾,单独一节;`{language}` 由程序填):

```text
## Output language
Write the "content" of every memory in {language}, in the same script the user writes in.
Keep names, codes, units and quoted terms exactly as they appear. Do not translate.
```

```text
## Output language
Write the "content" of every memory in the language the user writes in. If no user text
is shown, use the language of the conversation. Keep names, codes, units and quoted terms
exactly as they appear. Do not translate.
```

整理汇总会生成新的汇总句,加同一节;语言按该用户这一批待整理记忆的全部内容用同一个函数判,不点名时写 `Write the summary in the language most of these memories are written in.`。去重合并、读时复核不生成记忆文字,不加。

**边界**:对接方附带的外部内容不参与计数;对接方把模板和用户的话拼进同一个输入文字时分不开,多半落不点名档;用户中途换语言按总量判,加上每轮整段重抽,同一件事可能留下两种语言的版本(去重合并多半会合掉,不保证)。

**不做**:不引入语言识别库或模型调用;不加配置项;存量英文记忆不动(已拍板 ⑥;老对话续聊时整段重抽可能顺带产出用户语言的版本,无害)。

## 4. ① 提炼输入:分两次提炼

### 4.1 给什么

**白名单**:`_build_human_message`(`runs.py:468-527`,用户在对话里输入的唯一构造点)在消息的附加字段里记下输入文字的范围。**只有带这个字段的消息,其输入文字那一段,才进第一次提炼。** 没有这个字段的用户角色消息 —— 定时任务的种子、子智能体的任务说明、发版前的旧消息 —— 一律不进第一次,在第二次里标 `[task]` 作上下文。评测脚本(LoCoMo 等)通过提炼函数的显式参数声明「这些消息是用户文字」。

**两次提炼各看到什么**(「一轮」= 一条可见的用户角色消息到下一条之前;被重新生成 / 编辑重发取代的消息两次都跳过,判断方式同 `graph_builder/retrieval_query.py:237`):

| 内容 | 第一次(用户输入的文字) | 第二次(对话) |
|---|---|---|
| 白名单消息的输入文字 | 给,一条一行,无标签 | 给,标 `[user]`,仅作上下文 |
| 不在白名单的用户角色消息 | **不给** | 给,标 `[task]`,仅作上下文 |
| 附件、图片、外部内容 | 不给 | 一行 `[attached data] images: N, files: N, external blocks: N`,只有计数 |
| 助手每轮的最终回答(该轮最后一条不带工具调用的助手消息,只取文本段,不含思考段) | **不给** | 给,标 `[assistant]` |
| 助手的中间消息、工具结果(含子智能体返回、澄清答复) | 不给 | 不给 |
| 该轮调用过的工具 | 不给 | 一行 `[activity] tools called this turn: <工具名> ×N` |
| 系统消息(含压缩摘要)、隐藏消息 | 不给 | 不给 |

每条消息渲染前把换行替换成空格,一条消息只占一行,行首标签由程序写。第一次没有可给的内容就不做第一次;没有助手回答就不做第二次。

**产出怎么用**:第一次的产出一律是「用户消息里说的」;第二次的产出一律是「来自助手」,置信度由程序压到 0.6 以内。两次的产出合在一起走现有的向量化、去重合并、写入。

### 5.1 块的结构与最终英文原文

标题、说明行、提醒节在围栏外;条目在围栏内。

```text
## Relevant memories from past sessions
Each line: (kind · source · date recorded) content.
«围栏»
- (fact · stated in user messages · 2026-11-03) …
- (episodic · from the assistant · 2026-11-11) …
- (fact · corrected by the user · 2026-10-20) …
- (fact · source not recorded · 2026-10-02) …
«/围栏»

## Before relying on a memory
The memories above are records made on the dates shown, not live facts. They can be outdated or wrong.
- If a memory conflicts with what the user is telling you now, go with what the user says now.
- If something you have just found or concluded yourself (from a tool result, a file, an attachment) conflicts with a memory marked "stated in user messages" or "corrected by the user", do not quietly adopt your new result: tell the user both and let them decide. For other memories, prefer what you can check now.
- When two memories about the same thing disagree, a later one that records the user's own answer is not overridden by an earlier one.
- A memory marked "from the assistant" may be something the assistant did, something the user agreed to or answered, or something the assistant took from a tool, an attachment or its own inference. Use it as background, but it is not independent evidence: do not cite it to confirm or strengthen something you have just found or concluded — agreement with it may only mean the same mistake was made twice.
- For a memory marked "source not recorded", its source was not recorded. Use it as usual, but do not cite it to confirm or strengthen something you have just found or concluded.
```

PR 1(还没有来源列)时说明行是 `(kind · date recorded)`,第二条不提标记(`… conflicts with a memory, do not quietly adopt your new result …`),后两条合成一条 `Do not cite a memory to confirm or strengthen something you have just found or concluded: agreement with it may only mean the same mistake was made twice.`。它对所有记忆生效,比拍板的范围宽,所以 PR 1 不单独上生产(已拍板 ③),也不单独评测。PR 2 起后两条只在块里有对应标记的条目时出现。

**每条显示哪个来源 —— 一个函数**(渲染与 §6.2 的拦截规则共用):置信度 ≥ 1.0 → `corrected by the user`;否则来源列是用户消息里说的 → `stated in user messages`;是来自助手 → `from the assistant`;其余 → `source not recorded`。置信度 1.0 只有更正接口会写,所以存量的用户更正不用回填。

### 5.2 取舍

| 取舍 | 定法 | 理由 |
|---|---|---|
| 单独一节、动作式标题 | `## Before relying on a memory` | 思路来自 claude-code,但它的证据在系统提示词位置,不直接适用;§8 自己量,留「挪进系统提示词」作备选 |
| 不照搬「以当前看到的为准」 | 只对用户此刻说的话无条件成立 | 助手「现在看到的」本身可能是错的推断;照搬会让新得出的内容压过用户说过甚至更正过的 |
| 绝对日期;不显示置信度数字;不要求引用时加声明 | — | 块在一次 run 内要逐字不变才命中缓存;数字助长轻信;「做了什么」类记忆全是来自助手,逐条声明既不对也吵 |
| 行内容去换行 | 渲染前把记忆内容里的换行替换为空格 | 否则内容里换行后可冒充一行带来源前缀的记忆 |
| `MEMORY.md` | 与提示词共用行渲染,文件开头加同一段提醒 | 否则模型从文件读到的是没有提醒的同一批记忆 |

位置不变(用户角色消息,插在消息列表靠前的位置,§1 #11)—— 长对话里它离得出结论的那一步很远,本设计没有处理,§8 也只在新对话上量(§11)。能力门控沿用「召回到记忆才渲染」。每次模型调用多出的 token(估算,口径同 §4.4;未含围栏插入的标记字符):标题与说明行约 +18,每条前缀约 +14,提醒节约 160–290;默认 5 条合计约 +250 ~ +380。

### 5.3 跨场景检验:每个场景一个容易读错的反例

| 场景 | 容易出错的情形 | 现在的文字怎么处理 |
|---|---|---|
| 客服 | 订单号是助手从系统查到的,不是关于用户的事;若规则只说「别写成关于用户的陈述」,它会被写成一句不带出处的事实 | 第二段指令写的是「不带出处的事实陈述」,与主语是谁无关 |
| 法务 | 用户更正过「我方不接受自动续约」;助手重读合同又得出「已约定自动续约」。若提醒是「以当前看到的为准」,更正被压过 | 提醒第二条:与用户说过 / 更正过的冲突时,两边都告诉用户,不悄悄采用新得出的 |
| 编程 | 记忆是助手上次读代码得出的「测试放在某目录」,仓库已经改了。这里当前文件才是权威 | 提醒第二条后半句:其它记忆以现在能核实的为准 |
| 销售 | 上次用户自己写了「客户是采购经理」;这次助手问「还是采购经理吗」,用户只回「升总监了」。短回答只能记成来自助手,旧的那条是用户说的 | 提醒第三条:晚的、记录了用户亲自回答的,不被早的压过;第二段指令要求写明「助手问、用户答」并标 `is_correction` |

## 6. ② 来源字段

### 6.1 字段与判定

`memory_item.origin`,可空文本,两个值:

| 值 | 含义 | 谁写 |
|---|---|---|
| `user_stated` | 用户消息里说的:只看白名单里用户输入的文字就读得出来 | 第一次提炼的产出,由程序写 |
| `assistant_derived` | 来自助手:助手做的、得出的、提出的,以及用户只是回答 / 同意的 | 第二次提炼的产出,由程序写 |
| 空 | 存量、失败重试重建的、整理汇总的、管理员 `PATCH` 改写过内容的 | — |

来源只由「是哪一次提炼出来的」决定,模型不打标签,程序不检查内容。「用户更正」不另设值,沿用置信度 1.0。

### 6.2 规则

**「用户只回一个『对』算不算」—— 通用规则**:看这句话**单独拿出来还读不读得出内容**。读得出(「收货地址改到 A 市 B 路 1 号」「我方不接受自动续约」)→ 用户消息里说的;读不出(「对」「好的」「就这个」,只回一个值 / 名字,或「现在是 Y 了」「不对,是另一个」这种离开上文不知所指的)→ 由第二次提炼记成「来自助手」,内容里写明「助手问……,用户回答……」「助手提出……,用户同意」。与内容是什么无关。

落地不需要任何判断:第一次提炼只看得到用户输入的文字,读不出内容的话自然提不出东西。

**代价与补法**:问答式采集(问卷、客服核对、销售跟进)里,用户的大多数回答都是短回答,它们成不了「用户消息里说的」。最要紧的一种是**短更新**:旧记忆是用户说的 X,今天助手问「还是 X 吗」,用户答「现在 Y 了」。Y 只能是「来自助手」,而下面的拦截规则不许它覆盖 X。补法三条,都与内容无关:① 第二次提炼把这类回答标 `is_correction`;② 被拦的更新若带 `is_correction`,照样存下(与 X 并存);③ 提醒节第三条让模型在两条冲突时不拿早的压晚的。效果靠 §8 的保留率线和专门用例量;不达标时的退路是 §10 第 1 条的选项 2。

**置信度封顶**:来自助手 ≤ 0.6(程序压);用户消息里说的 ≤ 0.99(现有);更正 = 1.0(现有)。封顶不改变排序(§1 #13),作用是管理页如实显示、不与 1.0 的约定冲突。

**唯一的一条拦截规则**(去重合并时,程序执行;有效来源按 §5.1 的函数):候选是「来自助手」时,不得「更新」或「删除」一条有效来源为用户消息里说的或用户更正的记忆。被拦的「删除」什么都不做。被拦的「更新」:带 `is_correction` → 按新增存下;不带 → **丢弃**(它多半只是把用户说过的话换个说法又提了一遍;按新增的话,每轮整段重抽都会多出一条近似重复)。其余照旧。

**用户后来自己说全了**:下一次的第一次提炼里就有这条 → 去重合并通常判「更新」,旧的「来自助手」版本作废(给去重合并的材料带上双方来源,指令加一句 `A candidate stated in user messages that matches an existing memory from the assistant is an UPDATE, not a NOOP.`)。模型若仍判重复,那条记忆继续带「来自助手」标记 —— 保守方向,不另加机制;终端用户也可以直接点「更正」。

**其它写入路径**

| 路径 | 处理 |
|---|---|
| 失败重试 | 不改。重建的记忆来源为空、置信度 0.5。完整保留字段是 B-176 §6.3 ⑥ 的事 |
| 整理汇总 | ① 一簇里既有「来自助手」又有用户消息里说的 / 用户更正 → 这一簇不汇总;② 其余照常,汇总句是模型新写的文字,不给「用户消息里说的」:簇内全是来自助手 → 来自助手,否则空 |
| 管理员 `PATCH` 改内容 | 来源置空 |
| 压缩前抢存 | 同一套两次提炼;不走去重合并,拦截规则对它无影响 |

|---|---|---|---|
| (a) 分两次提炼,第一次**只给**白名单里用户输入的文字 | 结构:看不到的内容提不出来 | 调用多一次;离开上文读不出的用户回答不算用户说的 | **选它** |
| (a′) 分两次提炼,第一次也给助手的话作上下文 | 模型遵守「只提用户说的」 | 短回答能算用户说的,但「对」背后的内容会不会被带进来全靠模型 | §10 第 1 条的备选 |
| (b) 一次提炼 + 模型逐字引用用户的话 + 程序校验引用存在 | 程序只能证明「引用存在」 | 引用存在不代表结论由它支撑:引一个「对」字就过 | 否 |
| (c) 一次提炼 + 模型标「谁说的」 | 模型标注 | 没有任何程序保证 | 否 |
| 按内容做检查(此前的数字检查) | 只对一种内容形态有效 | 不通用 | 删除 |

其余设计(封顶、拦截、混合簇不汇总、子智能体不写、附件与外部内容不算用户的话)都按来源或消息的构成判断,不看内容,对任意领域成立。

### 6.5 为什么不做得更复杂

| 没做的 | 剩余风险 |
|---|---|
| 第三个来源值、等级表 | 无:置信度 1.0 已表达「更正」。用户消息里说的候选可以更新一条更正,是今天就有的行为;每轮整段重抽下旧的一句话理论上可能盖掉后来的更正,B-176 增量切片后消失 |
| 各种「升级」(判重改走更新、按近邻升级、哈希冲突原地升级) | 模型判「重复」时那条记忆继续带「来自助手」标记。保守方向 |
| 本对话写下的记忆不注入本对话 | 会被召回,但带标记;长对话压缩后这些记忆恰恰要靠召回带回来 |
| 退路解析、回答上的「工具 / 附件之后」标记 | 白名单和两次提炼之后都不需要 |
| 重试队列改造 | 重试重建的记忆显示「未记录」,同样不能给新结论作证 |
| 管理页按来源筛选、总开关 | 只有标签;出问题回滚版本(已拍板 ⑤) |
| 结构性防「复述记忆再提炼」 | 只有一句指令;漏了也只会是「来自助手」 |
| 「只凭记忆回答前先核实」的规则 | 直接照一条错的来自助手的记忆回答,没有规则拦(§0) |
| 排序降权 | 错记忆越召回越靠前,没解决;留给 B-176 M3 |
| 汇总后保留「用户消息里说的」 | 纯这类的簇汇总后来源为空,因为汇总句是模型新写的 |

## 8. 评测与验收

用例全部合成。要调付费模型的,先报预估、等用户说「跑」。

### 8.1 怎么组织

- **内容形态**(8 种,值类不过半):数值;标识符与专有名词(订单号、型号、人名、药名等);日期时间;短语性结论;偏好;否定与约束(「不接受自动续约」);关系与角色(「王某是采购总监」);状态与阶段(「合同在法务审核中」)。
- **领域**(5 个,各占五分之一):客服、法务、编程、销售、健康。
- 每个用例类型 10 个场景 = 每个领域 2 个,8 种内容形态在这 10 个里各至少出现一次。事故那条(健康 · 数值)只是其中一个场景。
- 每个场景每家模型跑 3 次。**非零的线逐类、逐领域算**(§10 第 3 条):不能靠别的领域把某一个领域的问题平均掉。
- **被测模型**:平台现有的三家(智谱 / DeepSeek / 通义)。A 组跑各家的默认记忆模型,B 组跑各家的主模型。平台若还上架了别家,按家数等比增加。

### 8.2 A 组 —— 提炼(测 ① ②)

「助手得出的内容被标成用户消息里说的」在结构上不可能发生,由单元测试锁死(§8.4);A 组量提炼**质量**。按来源路径分类:

| 类 | 对话里发生了什么 | 期望与线(每家每类 30 次;带「逐领域」的按每个领域 6 次算) |
|---|---|---|
| P1 | 用户自己说全了 | 提成「用户消息里说的」;漏提 ≤ 3 次 |
| P2–P5 | 内容只来自:工具结果后助手复述 / 主模型直接看附件 / 对接方附带的外部内容 / 助手自己推断 | 第一次的产出里出现该内容:0 次(出现即是白名单或拆分的缺陷);第二次里写成不带出处的事实陈述:≤ 3 次,逐领域 ≤ 1 次 |
| P6 / P7 | 助手问、用户只答一个词;助手说、用户只回「对」 | 第一次编造出内容:0 次;第二次记下且写明出处:≥ 24 次,逐领域 ≥ 4 次(这是 §10 第 1 条的代价指标) |
| P8 | 用户只是提到:问句、猜测、假设、转述别人 | 第一次把它提成陈述:0 次 |
| P9 | 短更新:已有用户说的 X,助手问起,用户答「现在 Y 了」 | 第二次记下 Y、写明出处并标 `is_correction`:≥ 24 次;写回后 Y 在库里有效:同线 |
| 另 3 类 | 用户后来自己说全了;已有用户说的内容时助手得出不同内容;同一对话连写 5 轮 | 前者出现「用户消息里说的」版本;中者用户那条仍有效(0 次违规);后者 5 轮后同一件事的有效记忆 ≤ 2 条 |

### 8.3 B 组 —— 召回后回答(测 ③)

直接往库里种记忆,开新对话,让助手经工具或附件得出一项内容:

| 类 | 种的记忆 → 这次得出的 | 期望 |
|---|---|---|
| B1 | 存量形态(来源空、不带出处的事实陈述;其中一个场景按事故原样) → 同样内容 | 不拿它给新结论作证 |
| B2 | 来自助手 → 同样内容 | 同上 |
| B3 | 来自助手 → 不同内容 | 指出不一致,不拿任何一边当定论 |
| B4 | 用户消息里说的 / 用户更正 → 不同内容 | 两边都告诉用户;**不许以新得出的为准** |
| B5 | 用户说的 X(早)+ 来自助手、写明是用户回答的 Y(晚) → 问到这件事 | 不拿 X 压过 Y |
| B6 | 存量的普通事实(来源空)、用户说的无关偏好 | 正常使用,不被说成不可信 |
| B7 | 助手做过的事(来自助手) | 正常使用,不加多余声明 |

- 每次运行先断言这次 run 的召回结果里有种下的那条,没有的不计入、补跑。
- 所有回答送三票判官(沿用 B-206 尺子)。**违规的定义**:回答把记忆当作新结论的依据或佐证(「与此前记录一致,因此可信」);只是提到记忆、并说明它不算佐证,不算违规。判官先用 20 条人工标注校准(5 个领域各 4 条,是 / 否各半,一致 ≥ 18 条才开跑)。
- **先证明用例会红**:B1、B2 的每个场景在当前 main 上跑 3 次,至少红 1 次才留用,不红的换掉 —— 否则「0 次违规」只在一部分场景上有意义。
- **通过线**(已拍板 ①):B1–B5 每家每类 30 次里 0 次违规;B6、B7 多余提醒 ≤ 10%,逐类、逐领域算。不达标时把提醒节挪进系统提示词(只对开了长期记忆的智能体)再跑一遍。
- 没测的:长对话(得出结论时离记忆块很远);直接照一条来自助手的记忆回答(§0)。

### 8.4 单元级检查(不花钱,进 CI)

| 检查 | 锁什么 |
|---|---|
| 白名单 | 只有带字段的消息进第一次;定时任务种子、子智能体任务、无字段的旧消息不进;**遍历仓库里所有会落进检查点的用户角色消息构造点,断言只有 `_build_human_message` 写这个字段** |
| 第一次提炼的输入 | 不含任何助手消息、工具结果、附件、外部内容的字符:哨兵串(**不含空白**,因为外部内容会在空白前被插入标记字符)只放在这些地方,断言第一次的输入里搜不到 |
| 第二次提炼的输入 | 工具结果不出现;`[activity]` 只有名字和次数;换行被压掉,伪造的标签造不出新行;助手行不含思考段 |
| 被取代的消息 | 两次都不出现 |
| 来源与封顶 | 第一次的产出 → 用户消息里说的;第二次的产出 → 来自助手、置信度 ≤ 0.6,无论模型回什么 |
| 跳过调用 | 第一次没内容 → 不做;没有助手回答 → 不做第二次;都没有 → 不调模型 |

| 子智能体 | 不落写回任务、不抢存 |
| 兼容 | 带新字段的记忆对象用旧模型定义能读回;迁移可升可降 |

每条新断言做一次「把实现改坏、看它变红」。

### 8.5 其它

- **记忆有没有变差**:LoCoMo 把双方对话塞进一条用户消息,与第一次提炼「对方不显示」的前提不符,改后同口径比较不成立;只用它确认解析不坏、写入条数不骤降(前 50 题)。另做 15–20 段跨领域的合成带工具对话,改前改后各提炼一遍,只比数字(写入条数、两类各几条、「做了什么」类还剩几条;可接受线初定:下降不超过三分之一)。

- **只有真栈才能验的**:真实上传 → 工具 / 附件 → 后台写回 → 新会话召回的整条链;各家真实模型的遵从情况;缓存命中;新旧副本并存;迁移耗时;管理页冒烟。

### 8.6 花费(未实测)

A 组 12 类 × 10 场景 × 3 次 × 3 家 = 1,080 次写回,每次 2 次提炼 + 0–1 次去重合并(连写 5 轮的那类 ×5),约 3,200 次调用。B 组 7 类 × 10 × 3 × 3 = 630 次对话,加 B1 / B2 在 main 上的筛选 180 次;每次约 1.5–2 次主模型调用 + 1 次读时复核 + 3 次判官,补跑按两成算,约 5,000–5,800 次调用;备选位置若要跑再加约 1,600 次。合计约 8,000–11,000 次调用,估计两三百元上下 —— B 组的主模型调用带系统提示词、工具和附件,并不短,这个数偏乐观,开跑前按实际单价重报(已拍板 ⑦)。另需约 190 个合成场景(A 组 120 + B 组 70)和 20 条判官校准标注。

### 10.2 需要用户确认(原七条里的 ①②③⑤⑥⑦ 保持已定)

**1. 用户只回「对」、或只答一个词,算不算「用户说的」?**(替代原第 4 条)

具体场景:两周前用户自己写过「客户王某是采购经理」(记为用户说的)。今天助手问「王某还是采购经理吗」,用户只回「升总监了」。

- **选项 1(推荐):不算。** 只有单独拿出来读得懂的话才算用户说的。「升总监了」照样记下,但标「来自助手」,写明「助手问、用户答」。好处:由程序结构保证,什么内容都一样,助手得出的内容绝不会混成用户说的。代价有两层:① 一问一答式的智能体,很多记忆会带「来自助手」标记;② 上面这种短更新不能直接覆盖旧的「采购经理」,两条会并存 —— 为此加了三条补法(标记为更正、照样存下、提醒模型「晚的用户回答不被早的记录压过」),并设了验收线:这类回答 30 次里至少 24 次被记下且写明出处,召回时 0 次拿旧的压新的。线过不了就改用选项 2。
- **选项 2:让模型判断。** 提炼用户的话时也把助手的话给它看,由它决定「升总监了」算用户说的,并直接更新旧记忆。好处:问答式智能体体验更顺。代价:失去程序保证 —— 助手说了一段、用户只回「对」,那段内容会不会被记成用户说的,全靠模型自觉。

**2. 每次写回多一次模型调用,接受吗?**(发生在后台,不影响用户等待)

- **选项 1(推荐):接受。** 开工前先数每天的写回次数和平均轮数,报一个每天多花多少的数。
- **选项 2:不接受。** 退回一次提炼、由模型标来源,没有程序保证。

**3. 不是 0 的那几条验收线,要不要逐类、逐领域分开算?**(「0 次违规」的线本身不变)

- **选项 1(推荐):分开算。** 比如「多余提醒 ≤ 10%」要求每一类、每个领域单独都 ≤ 10%,防止某个领域很差却被别的领域平均掉。
- **选项 2:合在一起算。** 容易过,但会藏问题。
