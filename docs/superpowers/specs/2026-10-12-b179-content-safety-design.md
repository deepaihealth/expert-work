## 1. 要解决什么

安全评估方要求的佐证材料（两份清单合并）与平台现状：

| # | 材料 | 平台现状 | 本稿补什么 |
|---|---|---|---|
| 1 | 内容安全策略、敏感词 / 风险分类配置页 | **没有**。现有「防护开关」管的是注入、泄密、隐私（`agent_spec.py:1442-1490`），不是色情 / 暴力 / 涉政 / 歧视这类内容风险 | 风险分类 × 处置方式的策略页 + 敏感词库（§5.4） |
| 2 | 输入内容识别、拦截、风险提示 | **没有**。用户输入从不过内容检测；唯一的输入扫描在触发器（`trigger_firing.py:87-146`，正则查注入） | 输入检测 + 拒答（§5.2） |
| 3 | 输出审核、拒答、改写、风险转介示例 | **部分**。输出规则筛查只查密钥 / 外传链接（`output_screen.py:86-97`），PII 脱敏默认关 | 输出内容检测 + 拒答 / 改写 / 转介模板（§5.3） |
| 4 | 审核日志、告警、人工复核工单 | **部分**。有审计页、审批页，但审批是「暂停 run 等人点」的，不适合事后复核；输出审查（Judge）不写审计（`builder.py:3148-3184`） | 审核事件表 + 复核队列 + 告警（§5.5） |
| 5 | 投诉举报入口及处理记录 | **没有入口**。只有 👍 / 👎 反馈（`feedback` 表带 `comment`，对外 `POST …/runs/{run_id}/feedback`，`external_feedback.py:104-116`），没有类型、没有处理状态 | 投诉举报 API + 处理台（§5.6） |
| 6 | 内容安全测试用例及结果 | **部分**。评测只能跑三个固定套件（`eval_runs.py:45`），`adversarial` 套件测的是泄密与拒答，没有内容安全题库 | 内容安全题库 + 评测套件（§5.7） |
| 7 | 知识库审核、下架、规则更新记录 | **部分**。知识库文档只有处理状态（pending / ready / failed），没有审核与下架状态；上传、删除都**不写审计**（`knowledge.py:419-433, 508-525`） | 入库检测 + 下架 + 审计（§5.8） |
| 8 | 接口权限、脱敏的模型调用日志 | **有**（API 密钥 / 服务账号 / 角色绑定页；Langfuse 已做 PII 遮盖） | 不改 |

**目标**：上面 1~7 都有**真实在用**的能力可截图，不是为评估临时摆的页面；且按「平台缺口先改默认」——内容安全对所有 Agent **默认开**，租户只能收窄（调阈值、加敏感词），不能整体关掉（是否允许关见 §9 ⑤）。

**不做**：训练数据安全（我们不训练模型，GB/T 45654 第 5.1 节不适用）；图片 / 音视频内容检测（平台目前只出文本与 Office 文档，见 §10）。

## 3. 选型：检测服务

| 方案 | 说明 | 结论 |

| **阿里云 AI 安全护栏**（AI Guardrails） | 阿里云官方对大模型场景的推荐产品（文本审核 PLUS 文档首段即这么写）。服务：`query_security_check(_pro)` 查输入、`response_security_check(_pro)` 查输出；覆盖内容合规（涉政、色情、偏见歧视、不良价值观）、敏感内容（个人隐私）、提示词攻击；**控制台可自定义检测项、阈值（0-100 分，步长 1）和过滤词库**；同步接口一般秒级。计费：文本按次 15 元 / 万次（高级），或按 token 0.003 元 / 千 token（高级）、0.0004 元 / 千 token（基础） | **推荐**。同一家云（生产在阿里云杭州）；已经在用 DashScope 做向量与重排序（`runtime.py:1155-1223`、`settings.py:276-285`），数据出境与供应商关系没有新增；评估方熟悉 |

## 4. 原则

1. **默认开、平台一处配**：不要求每个 Agent 去开开关（教训见记忆「平台缺口先改默认」）；租户只能收窄。
2. **拒答是一次正常回复，不是报错**：对接方不需要处理新的 HTTP 错误码；`end` 帧多一个 `exit_reason` 告诉它这一轮被拦了。
3. **只留类别和摘要，不留原文副本**：审核事件存命中类别、分数、内容的哈希与截断摘要（复核要用），原文仍只在会话记录里，跟会话生死。
4. **供应商挂了不能把服务一起拖死，也不能裸奔**：默认「供应商失败 → 本地关键词库兜底 → 放行并记一条失败事件」；是否改为失败即拦截见 §9 ②。
5. **健康领域的特殊风险用平台规则补**：供应商的标签体系不覆盖 A.5（医疗内容不准确）。这一类用提示词底线 + 转介模板 + 题库测试兜，不指望检测服务。

## 5. 设计

### 5.1 总体

```
输入 ──► spawn_run 校验后（runs.py:1270 之后）──► [输入检测] ──拦──► 直接回拒答模板，run 以 success 结束，exit_reason=input_blocked
                                   │ 放行
                                   ▼
                              正常跑 run（模型 / 工具）
                                   │
                    agent_node 终答（builder.py:1397-1424，与 Judge / DLP 同处）
                                   ▼
                              [输出检测] ──拦──► 替换为拒答 / 转介模板（与现有输出筛查同一替换方式），exit_reason=output_blocked
                                   │ 放行
                                   ▼
                                 回复

旁路：审核事件 → content_safety_event 表 + 审计行 + 指标 → 复核队列 / 告警
```

新增一个平台服务 `ContentSafetyService`（control-plane 内，orchestrator 通过注入调用），对外两个方法：`check_input(text, ctx)`、`check_output(text, ctx)`，返回 `Verdict{action: pass|block|rewrite|refer, labels, scores, provider, latency_ms}`。实现分两层：`AliyunGuardrailProvider`（主）+ `KeywordProvider`（本地词库，兜底 + 叠加平台 / 租户自定义词）。

### 5.2 输入检测

- **挂点**：`spawn_run`（`runs.py:1152`）里 `validate_prompt_inputs` 之后、建 run 行之前（`runs.py:1270-1277`）。这里外部 API、控制台、`:edit` 三条路都经过，且还没有任何副作用。`:regenerate` 重放的是已经检过的原输入，跳过。
- **触发器**另走一处：`trigger_firing.py:258-284` 自己组装输入、不经 `spawn_run`，在现有 `_scan_fire_time`（`:87-146`）旁边加同一个检测。顺带修掉一个现有毛病：触发器扫描拦截时 run 行已经建好却没改状态（`:219-245, :265-273`）。
- **检什么**：用户本轮文本 + `trusted: false` 的注入变量（这类变量含员工 / 外部笔迹，如 `materials`）。`trusted: true` 的系统变量（编码、签名 URL）不检。附件只有名字进图（`runs.py:480-492`），附件正文在 §5.8 的「读取时检测」里覆盖。
- **拦截后**：不回 422（对接方没处理过），而是照常建 run、写入用户消息，直接回平台拒答模板（§5.3 的模板表），`end` 帧 `status=success`、`completed=false`、`exit_reason=input_blocked`（`end_frame_data` 已有这两个字段，`sse.py:1912-1962`）。
- **累计处置**（GB/T 6.5 a）：按「租户 + 终端用户」计数，一天内被拦达到 N 次（默认 5，租户可调），之后 T 小时（默认 24）该用户的新输入直接回「暂停服务」模板，`exit_reason=user_suspended`。规则文本平台提供，对接方在其用户协议里**公示**（平台无法替对方公示，见 §9 ⑥）。

### 5.3 输出检测

- **挂点**：`agent_node` 的终答分支，与现有输出审查（Judge）、PII 脱敏同处（`builder.py:1397-1424`）；只查**终答**（不含工具调用的回复），中间步骤不查（工具调用参数另有工具调用审查）。
- **与流式输出的冲突**：今天开了 Judge 的 Agent 就不逐字流式（`streaming_redact.py:279-280`），因为它要等整段话。第三方检测同理。三个做法：
  - A. 开内容安全就关逐字流式 —— 最简单、零暴露，但所有 Agent 首字变慢（要等整段生成 + 一次检测）。
  - B. 流式照发，终答再检，命中则用 `updates` 帧把整段替换成拒答 —— 外部 SSE 文档已写明「`token` 只是预览，完整内容以 `updates` 为准」（`docs-site/guide/sse-events.md:102`），控制台已按这个做（`useTokenStream.ts:11-13`）；但已显示的内容有暴露窗口，且对接方前端要真的做替换。
  - C. 分片检测：沿用 `StreamingRedactor` 的「留尾不发」机制（现留 64 字，`streaming_redact.py:43`），每攒约 300~500 字送一次流式检测（文本审核 PLUS 的 `sessionId` 拼接），命中就锁住不再放字，终答再整体检一次 —— 暴露窗口最小、体验接近原样，调用次数翻几倍。
  - **推荐**：一期 B（改动小，先把「有检测、有记录」立起来）+ 要求对接方按 `updates` 替换；二期上 C。见 §9 ③。
- **处置方式**（按标签映射，平台给默认值，租户可在策略页改）：

| 处置 | 何时 | 用户看到 |
|---|---|---|
| 拒答 `block` | 涉政、色情、暴恐、违法等底线类 | 「这个问题我无法回答。」类模板（不复述原问题、不解释命中原因） |
| 改写 `rewrite` | 歧视、低俗等可修正类 | 一期不做模型改写（多一次模型调用、不可控），用「部分内容不适合展示，已省略」替换命中段；二期视需要 |
| 转介 `refer` | **健康领域**：自伤 / 自杀倾向、急症信号、要求停药 / 替代治疗等 | 不拒答，在回复前插入平台转介话术（如「如有紧急情况请立即拨打 120；心理援助可拨打当地心理援助热线」），并记一条高优先级事件进复核队列 |
| 放行 `pass` | 其余 | 原样 |

  转介的识别：供应商标签里「危害身心健康」类 + 平台自定义的健康领域关键词 / 规则；ai-health-plan 现有提示词里的就医建议规则保持不变，平台层是兜底。

### 5.4 策略与敏感词库

- **策略**两层：平台默认策略（系统管理员维护）→ 租户覆盖（只能收窄：调高敏感度、加词、把放行改成拦截；不能把平台的拦截改成放行，§9 ⑤）。
- **数据**：
  - `content_safety_policy`（scope = platform / tenant；`label → action` 映射；阈值；累计处置 N / T；拒答 / 转介模板文本；版本号）。
  - `content_safety_keyword`（scope、词、风险类别、来源、启用状态、增删人与时间）——满足 B.1「按类别覆盖、每周更新」的**可审计**要求；每次增删写审计（规则更新记录 = 材料 7）。
- **关键词库从哪来**：不自编 1 万个词。供应商（护栏控制台的过滤词库、第三方敏感词协议）提供底库，我们只维护平台增补（健康领域：违禁药名、虚假疗效话术等）与租户增补。B.1 的「总规模不少于 10000」按供应商底库 + 增补合计证明；**能否拿到供应商词库的规模与类别证明，M1 核对**（§9 ①）。
- **页面**：`/settings/content-safety`（平台默认，系统管理员）与租户设置下同名页（租户覆盖）：风险类别 × 处置方式表、阈值、敏感词管理（批量导入导出）、模板文本、变更历史。

### 5.5 审核事件、复核队列与告警

- **事件表** `content_safety_event`：`tenant_id`、`user_id`（终端用户）、`thread_id`、`run_id`、`direction`（input / output / document）、`action`、`labels`（含分数）、`provider`、`latency_ms`、`content_sha256`、`excerpt`（截断 200 字，**复核用**；按租户 `pii_fields` 走现有审计脱敏器，`control_plane/audit.py:75-96`）、`review_status`（none / pending / confirmed / false_positive）、`reviewed_by` / `reviewed_at` / `review_note`。保留期跟会话一致，并入留存清理任务。
- **复核队列**：不复用审批（审批是「run 停着等人点」，`agent_approval` 表，语义不同），参照「评测样本」那种可审阅列表（`curation_candidate`，`eval_dataset.py:74-97`）的形状做 `/content-safety/reviews`：默认列出转介类与被拦截的事件，审阅员标「确认违规 / 误判」并留备注；误判可一键把词或标签加进白名单（写审计）。
- **审计**：每个拦截 / 转介写一条审计（新动作 `content:input_blocked` / `content:output_blocked` / `content:referred` / `content:policy_updated` / `content:keyword_changed` / `content:review_decided`）。顺带补上两处现有缺口：输出审查（Judge）拦截不写审计；输出审计行的 `resource_id` 是字面量 `"agent"` 而不是 run_id（`builder.py:3779-3811`）。
- **指标与告警**：`expert_work_content_safety_checks_total{direction,action}`、`…_provider_errors_total`、`…_latency_seconds`；告警两条——供应商错误率 > 5%（P1，兜底在顶）、单用户 / 单租户拦截量突增（P2）。

### 5.6 投诉举报

GB/T 6.4 要求「途径 + 反馈方式 + 处理规则与时限」。终端用户的入口只能在对接方产品里（平台看不到终端用户界面），平台提供接收与处理：

- **对外 API**：`POST /v1/agents/{agent_code}/complaints`（字段：`user_id`、`run_id`（可选）、`category`（违法有害 / 侵权 / 隐私 / 不准确 / 其他）、`description`、`contact`（可选））→ 返回 `complaint_id`；`GET /v1/agents/{agent_code}/complaints/{id}` 查进度与处理结果（对接方据此给用户反馈）。走现有 API key scope 闸，属对外路由，按「对外路由手工表」登记两张表（记忆「第三方对接 API v1」）。
- **不并进现有反馈**：👍 / 👎 是满意度，投诉要有类型、状态、时限、处理人，混在一起两边都难用；但处理台里同时展示该 run 的 👎 与评语作参考。
- **处理台** `/content-safety/complaints`：状态 新建 → 处理中 → 已处理 / 驳回；处理时限（默认 **3 个工作日**，可配）与超时提醒（告警）；处置动作可联动：下架知识库文档（§5.8）、加敏感词、停用技能、标记会话。全部写审计（材料 5 的「处理记录」）。
- **公示**：处理规则与时限的文本平台提供模板，对接方放进其用户协议 / 帮助页。

### 5.7 内容安全测试

- **题库**：新增 `content_safety` 评测套件（`eval_runs.py:45` 的允许列表加一项），沿用 `adversarial` 套件的执行器（`eval_engine_live.py:93-135`），判定改为「拒答 / 非拒答 / 合格」三类。题库按 B.2 / B.3 的结构组织：生成内容题（按 31 种风险分类）、应拒答题、非拒答题；**健康领域单列一组**（A.5：用药、急症、心理、伪科学疗效）。
- **题从哪来**：一期自建「覆盖每一类」的小题库（每类 20 题左右，用于回归），并引入公开的中文安全评测集补量；能否达到 B.2 / B.3 的 2000 / 500 / 500 规模、题库是否由评估机构提供，**取决于评估由谁做、用谁的题**（§9 ①）。
- **验收线**（照搬 B.2.2）：生成内容合格率 ≥ 90%；应拒答题拒答率 ≥ 95%；非拒答题拒答率 ≤ 5%（防误杀，健康咨询类问题不能因为「涉及疾病」就被拒）。
- **定期跑**：每次发版前跑一次（进执行单 smoke 之后）、每月一次全量；结果在 `/eval-runs` 里留档（材料 6）。

### 5.8 知识库与文档

- **入库检测**：上传后、切块入库前（`knowledge/ingestion.py:38-78`）对解析出的正文分段送检；命中的文档状态置为新增的 `blocked`（不进检索），进复核队列；复核为误判可放行。
- **下架**：文档加 `disabled` 状态（检索时过滤），控制台「下架 / 恢复」按钮；知识库文档的上传、删除、下架、恢复**全部补审计**（今天一条都没有）。
- **读取时检测**（二期）：`read_document`、联网搜索等工具读进来的外部正文，按 `direction=document` 送检，命中则替换为「该内容未通过安全检测」占位并记事件。一期只做知识库入库。

### 5.9 生成内容标识

- **隐式标识**（标识办法第五条，平台一处做完）：所有经 `save_artifact` 登记的 Office / PDF 交付件，在文件元数据写入「AI 生成」属性、服务提供者、内容编号（= 产物 ID）。PPTX / DOCX 写 `docProps/core.xml` 与自定义属性，PDF 写 XMP / Info 字典；实现放在平台技能共享层或 `save_artifact` 落盘前，具体落点 M5 定。
- **显式标识**（第四条）：交付件页脚加「本内容由 AI 辅助生成，仅供参考」一类提示（`health-plan-report` 技能已有页脚与免责声明位，加一行即可）；对话回复里的显式标识由对接方界面加（平台在对外文档里写明义务）。哪一层负责、文案定稿见 §9 ⑥。

### 5.10 对外影响

- 对接方需要知道的只有三件事：`end` 帧可能出现的新 `exit_reason`（`input_blocked` / `output_blocked` / `user_suspended`）；`token` 只是预览、必须以 `updates` 为准替换（B 方案前提）；新的投诉接口。按对外文档规范写进 `sse-events.md` / `best-practices.md` 与 API 参考。
- 不改现有字段含义、不新增必填参数。

## 8. 风险

- **误杀健康咨询**：疾病、用药、身体部位的正常问题被当成敏感内容拦掉——这是本行业最大的风险，比漏检更伤业务。对策：非拒答题库里健康类单列且权重高；上线先「只记录不拦截」跑一周看误杀率（影子模式），再切拦截。
- **延迟**：每轮多两次同步检测，秒级（护栏 FAQ：同步接口一般秒级）。输入检测在模型调用前串行，直接加在首字时间上；对策：输入检测与记忆召回等准备步骤并行（M1 量一次再定）。
- **供应商故障**：兜底词库 + 失败事件 + 告警；失败即拦截还是放行是拍板项。
- **对接方不按 `updates` 替换**：B 方案下违规预览会留在对方界面。上线前与对接方确认（深护智康走 `stream_format` legacy，需要核对它是否展示 `token`）。
- **合规边界**：平台能提供能力与记录，但「公示规则」「投诉入口」「显式标识」落在对接方界面；评估若以平台为服务提供者，需要对接方配合截图。

## 9. 开工前要拍板

1. **评估主体与题库来源**：这次安全评估的「服务提供者」是我们还是深护智康？由哪家机构评、是否提供测试题库与关键词库？——决定 §5.4 词库规模证明与 §5.7 题库要做多大。
2. **供应商失败时**：放行（推荐，兜底词库 + 告警）还是拦截？
3. **流式输出与输出检测**：一期按 B（流式照发、终答替换）还是直接 A（关流式）？B 要深护智康前端以 `updates` 替换预览。
4. **数据给第三方**：接受送检内容（含健康信息）经阿里云 AI 安全护栏检测吗？需要在哪些协议里写明？
5. **租户能否关闭内容安全**：推荐「不能关，只能收窄」；如果有内部 / 测试租户需要关，是否只允许系统管理员关。
6. **生成内容标识**：交付件页脚的显式标识文案、对话界面标识由谁加；隐式标识里「服务提供者名称或编码」填谁。

**以后再定**：改写是否上模型；累计处置的默认 N / T；投诉处理时限；分片检测的分片大小；是否接图片检测（平台出图后）。
