# B-315 结构化输出：表单视图支持多层结构编辑

日期：2026-11-18 · 状态：设计待确认

## 1. 问题

智能体配置页的「结构化输出」只认「一层平铺的字段」：每个字段只能是文字、数字、是/否，或者文字 / 数字列表，而且不能带任何限制。只要多一点东西，整块就只剩一句「已配置（复杂结构）——请到 YAML 视图编辑」，结构看不到，也改不了。

健管师就是这种情况。它的输出结构是：

| 字段 | 类型 | 限制 |
|---|---|---|
| `messages` 回复消息 | 文字列表 | 最多 4 条；每条 1～300 字，不能全是空白 |
| `media` 素材编号 | 整数列表 | 最多 3 个、不重复；每个 ≥ 1 |

它没有更深的嵌套。被判成「复杂」，是因为用了条数、长度、格式、不重复、最小值这些限制，还有「整数列表」这个类型。别的客户的智能体还常有「列表里每项是一个对象」的结构，比如 `[{标题, 链接}]`。

## 2. 目标 / 不做

**做**
- 表单视图按层级显示结构化输出，并且能增、删、改。
- 字段类型：文字、数字、整数、是/否、对象（下面再挂字段）、列表（每一项可以是以上任意一种，包括对象和列表）。
- 每个字段能设：名字、类型、必填、说明、可选值（文字 / 数字类型）。
- 常用限制：
  - 文字：最短 / 最长字数、格式（正则）；
  - 数字 / 整数：最小值、最大值；
  - 列表：最少 / 最多几项、不重复。
- 层级最多 5 层。超过 5 层的部分只读显示。

**不做**（这些写法照样能用，只是在表单里只读显示，要去 YAML 视图改）
- 「几选一 / 全满足」类结构（`oneOf` / `anyOf` / `allOf`）、引用（`$ref` / `$defs`）、`const`、一个字段允许多种类型（如 `["string","null"]`）、`patternProperties`、条件结构（`if/then/else`），以及下面没列到的其他写法。
- 只读的是「这个字段的结构」：它的「必填」改的是上一级对象，照样能勾；整个字段也能删。

**不显示、但原样保留**（表单照常可编辑，这些键写回时不丢；改类型时，跟旧类型相关的会一起去掉）
- 根上的 `$schema`、`$id`。
- 文字的 `format`。
- 数字 / 整数的 `multipleOf`、`exclusiveMinimum`、`exclusiveMaximum`。
- 字段名不符合命名规则的（比如中文名、带连字符），只锁住名字，字段本身照常可编辑。
- 不改后端，也不改 YAML 视图。

## 3. 怎么做

**数据模型**（`form_model.ts`）
- 把 JSON Schema 读成一棵「字段树」，每个节点记：名字、类型、必填、说明、可选值、限制、子节点（对象）或列表项（列表）。
- 碰到第 2 节「不做」里的写法，**只把这一个节点**标成「只读」，原样保存它的原始内容；同级和上级的其他字段照常可编辑。
  - 现在的做法是只要有一处不认识，整块就全部只读。改成按节点只读，影响范围最小。
- 超过 5 层的只读部分注明「超过 5 层，请到 YAML 视图改」，其他只读部分注明「用了表单不支持的写法」。
- 节点上的说明类附加信息（`title`、`default`、`examples`、`$comment`）原样保留，表单不显示，写回时也不丢。改类型时去掉 `default` / `examples`（旧值多半不再合法），`title` / `$comment` / 说明保留；改成整数时，最小值向上取整、最大值向下取整。
  - 数字和整数互换时，`multipleOf`、`exclusiveMinimum`、`exclusiveMaximum` 保留（其他类型之间切换才去掉）。改成整数时，开区间的界按「能取到的整数不变」取整：`exclusiveMinimum` 向下取整（> 0.5 等价于 > 0），`exclusiveMaximum` 向上取整（< 9.5 等价于 < 10）；不是整数的 `multipleOf`（如 1.5）原样保留——它放在整数类型上仍然合法，能取到的整数也不变（1.5 的倍数里的整数就是 3 的倍数），取整反而会改掉规则。
- 写回时：
  - 对象节点保留原来的 `additionalProperties`；新建的对象默认写 `false`；
  - 不改动的字段写回后和原来完全一样，字段顺序也不变。
  - **核心保证：只读不改时，「读进来再写回去」的结果和原文一字不差。**

**界面**（`OutputSchemaEditor.tsx`）
- 用可展开的树形表格展示，每行是一个字段：名字、类型、必填、说明，以及一个「限制」按钮。点按钮弹出小面板，按类型显示能设的限制。
- 对象 / 列表行可以「加子字段」。列表行下面固定挂一个「每一项」子行，用来定义列表里每项的类型。
- 只读节点灰显，注明「这部分用了表单不支持的写法，请到 YAML 视图改」。
- 名字校验沿用现有规则：同一层不能重名，不能为空，要符合命名规则，另外不能叫 `__proto__`。
- **有任何名字问题，就报错并且不让保存，由人去改名：**
  - 每一行有问题的字段都标红，重名的两行都标红；只读字段、名字被锁住的字段和别的字段重名，也一样标红。
  - 结构化输出的顶部显示提示「有字段名重复或不合规，改好后才能保存」。
  - 这期间的改动（改名、改说明、改限制、勾必填）只留在表单里，不写回配置；配置保持上一次合法的状态。
  - 名字全部改好后，把整棵字段树一次写回，写回的保证不变（没改动的部分一字不差，键的顺序不变）。
  - 配置页的「保存草稿」「发布」和新建智能体的「创建」按钮不可用，模板表单点保存会被拦下并提示。做法：结构化输出编辑器通过一个表单错误通道（`form_errors.ts`）向配置编辑器报告「有错误」，配置编辑器再通过 `onValidityChange` 告诉宿主页面。
  - 有名字问题时也不能切到别的配置分组或 YAML 视图（切走会卸载编辑器、丢掉没写回的改动）：点了会被拦下，提示「结构化输出里有字段名问题，先改好再切换」，不弹确认框。
  - 被禁用的「保存草稿」「发布」「创建」按钮悬停时显示原因（表单里还有错误，改好后才能保存）。
  - 有问题的字段如果在已折叠的父行下面，这一支会自动展开，改好后再按原来的折叠状态收起。
  - 「放弃草稿」、保存后的刷新、「重置」会让配置编辑器换上一份新读进来的配置。这时结构化输出按新内容重新读，暂停中的改动和红色提示一起清掉——哪怕新内容和改动前一模一样也是如此。判断「是不是自己刚写回的」靠对象是不是同一个，而不是内容是否相同；其他字段的修改只做浅拷贝，结构化输出那块对象不变，所以不会误触发重新读取。重新读取后，名字没变的字段保持原来的折叠状态。
- 「添加字段」「加子字段」时给新字段一个默认名字 `field_1`、`field_2`……（同一层取第一个没被占用的），默认名字符合命名规则，所以点「添加」不会进入「暂停写回」的状态。
  - 为什么这样改：之前的做法是重名时自动挑一个字段保留、把另一个拿出写回。挑选规则先后改了三轮，每轮审查都还能找到反例（会悄悄丢掉用户没动过的字段）。改成「报错、不让保存、由人改名」，就不存在挑错的问题。
- 限制面板：最小值大于最大值时在行内提示（不拦保存）；数字类可选值里填了不是数字的，提示没加进去的是哪些。
- 可选值的输入：数字 / 整数可以用逗号一次填多个；文字类型不把逗号当分隔符（文字值里可能本来就有逗号），每个值按回车确认。

**严格模式提示**
`strict: true` 时，部分模型厂商要求「每层的字段都必填、不允许多余字段」。这时如果有非必填字段，表单在字段旁显示提醒，但不拦保存。理由是平台在其他调用路径上会自己校验，而厂商规则也在变化。

## 4. 测试与验收

- **单元测试**（vitest）：
  - 「读进来再写回去」一字不差：健管师的结构；含对象列表、5 层嵌套、只读节点、附加信息的样例各一个。
  - 每类限制的读写各一条。
  - 每条断言都要能失败：先在实现里故意改坏一处，确认这条测试会变红。
- **组件测试**：加字段、加子字段、改类型（会清掉不适用的限制）、删字段、只读节点不能编辑、名字校验。
- **e2e**：现有的结构化输出用例要能跑过；再加一条「健管师结构：在表单里把 messages 的最多条数从 4 改成 3 → 切到 YAML 视图，看到 maxItems: 3」。
- **测试环境验收**：打开健管师配置页，结构能看到，改一处限制保存后生效，再改回去。

## 5. 工作量与风险

- 前端约 2～3 天，含测试。只改 admin-ui，不改后端，不改数据库。
- 风险是写回时把手写的配置改坏，靠 §3 的核心保证和对应测试兜住。
- 一个 PR。按老规矩：先独立审查，没有中危以上的问题再开 PR；合并前跑全量；测试环境验收通过才算完成。
