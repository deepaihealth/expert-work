### 2.1 对照表

### 2.2 读下来最该记住的三点

1. **「编号存在」和「编号可引用」是两回事**(WeKnora)。目录里、历史里、标题清单里出现过的都有编号,但不能当依据。
2. **流式预览不是权威**(RAGFlow)。我们的对外文档本来就要求客户端拿到 `updates` 后整段覆盖预览(`apps/admin-ui/docs-site/guide/sse-events.md:346-350`)。
3. **两家都没有防「编号是真的、说的却是别的东西」**。T1 治不了,验收时单独数(§5.2「引对了」)。

#### 3.1.2 方案:编号指什么、怎么核对

**一个编号 = 显示给模型的那一段文字。** 检索和读文档同一口径:

| | 显示的是什么 | 标头 | 这一段登记哪些段号 |
|---|---|---|---|
| `knowledge_search` 的一条结果 | 一个大段的文字(放不下时只显示命中的子段,仍算同一段) | `[D12#7]`(7 = 排名最高的子段) | 7,以及同一大段里其它上榜的子段号 |
| `knowledge_read` 的一段 | 一个大段的文字 | `[D12#7-9,41]` | 7、8、9、41 |
| `spawn_worker` / 具名子智能体的结果 | 子智能体的回答文字(里面带它引用过的编号,见下) | — | 子智能体最终回答**真正引用了**的那些段登记的段号 |

- 回答里的编号 `D12#n` **认得** ⇔ 本轮有某一段登记过「文档 12 的段号 n」。它指向那一段(不是指子段 n 本身)。
- 区间写法 `[D12#7-9,41]` 先展开成 7、8、9、41,**每一个都要认得**,否则整个编号不认。通常它们指向同一段 → 记成一个出处;指向几段就记几个。
- 例:检索显示了 `[D12#7]`,同一大段里 8 号子段也上榜了,模型写 `[D12#8]` → 认得,指向同一段。8 号没上榜、也没被读过 → 不认得。(第 1 版这里前后矛盾,以本条为准。)
- 只写文档号(`[D12]`)一律不认 —— T3 标题清单里的文档号因此天然不能当出处。
- 没有文档号的标头(`[文件名#段号]`)不能引用:编号里带租户文字。迁移已给存量文档全部补号,这种标头只会在读文档记录失败时出现(`knowledge.py:905` 的 `(unknown)` 分支);数量应为 0,上线前数一次(§7.3)。

> 取舍一:用现有编号,还是每轮另编 1、2、3?
> - 支持用现有的:模型已经在看它、`knowledge_read` 已经在用它;旧结果压成的引用行里列的也是它;`meta["refs"]` 已经在记「显示过哪些」;少一张对照表。
> - 反对:它长期有效,模型可能凭记忆写、或顺手改个数字(WeKnora 用请求内临时编号就是为了让「凭记忆写」必然失效)。→ 用「只认本轮显示过的」来挡。
> - 反对:比 `[1]` 长。`[D12#7]`、`[D128#43]` 在 o200k_base 下都是 5 个 token。
> - 是否验证过:模型原样抄回的比例**未验证**(§5.2)。

**认哪些写法**(宽进):半角或全角方括号;一个括号里用逗号、顿号写多个;`#` 可以是全角;区间写法。裸写在句子里、没有括号的 `D12#7` 不算出处,原样留着。圆括号不认。

**什么算「本轮」**:从本轮起点(最后一条真实用户消息)到当前这一步。上一轮显示过的段不算(拍板口径,WeKnora 同);上一轮的结果被压成引用行后编号仍然看得见,模型要引就得 `knowledge_read` 重新读。

**核对的结果**(一个不做 IO 的纯函数;输入:模型原始回答 + 本轮消息;输出如下):

1. **干净正文**:所有编号连同紧挨在前面的空格、制表符一起拿掉(认得的、不认得的都拿掉)。
2. **出处清单**:认得的编号指向的段,按第一次出现的顺序,不重复。
3. **位置**:每个认得的编号原来在干净正文里的位置(第几个字符之后)和它对应清单里的第几个出处。
4. **两个计数**:不认得的编号里,「本轮和历史都没显示过」几个(疑似编的)、「上一轮显示过」几个(过期的)。

放在 `agent_node` 里、现有三道改写之后、写入状态之前(`builder.py:1594-1692`),并且是**最后一道**改正文的:位置是按最终正文算的,后面再改正文位置就错。每一条有正文的助手消息都过一遍。评测脚本像取答前核对那样直接取这个函数(`tools/eval/kb_agent_prod_prompt.py:1-13`)。

> 与响应缓存的先后**未验证**:缓存里应当存模型的原始回答(带编号),每次命中都重新核对。实现时用测试钉住。

**门控**:只有构建里有 `knowledge_search` 才启用;另设一个平台开关(同 `kb_first_routing`,`knowledge.py:139-144`),关掉时文本与行为和今天逐字节相同。**开关默认关。** 核对(A1a)合进去之后模型就会开始写编号,而把编号从预览和子智能体回传里拿掉的是后面的 PR(A1b),对外字段是 A1c;在 A1b、A1c 都合完并过了各自的真栈用例之前,测试环境也不许打开,否则 `[D12#7]` 会出现在对接方的逐字预览里。生产等统一评测过了再开。

**子智能体**(动态的 `spawn_worker` 和具名的都一样,同一个回传函数):

- 子智能体自己的图里照常核对,它存下来的回答也是干净正文 + 位置。
- 回传给父级的那段文字,按位置把编号**插回去**(父级模型需要看见编号才能照抄);同时在工具元数据里带上这些编号对应的出处(只有子智能体最终回答真正引用的,不设条数上限 —— 它不会比回答里的编号多)。
- 父级核对时把它们算作「本轮显示过的段」。父级看到的「那一段文字」是子智能体的转述,不是原文;出处对象仍指向原文那一段。这一层转述没有程序核对,记为风险 R11。

> 顺带发现:`spawn_worker` 给父级模型看的说明还写着子智能体「no knowledge-base search」(`tools/spawn_worker.py:70-80`),而实际默认继承。建议随子智能体那个 PR 一起改;因为是提示词文本,要过评测(§7.2 第 6 条)。

**结构化输出**:配了输出格式的智能体,编号可能落在 JSON 字符串里。照常拿掉编号、记出处清单,但**不给位置**(JSON 里的字符位置对对接方没有意义);拿掉编号不会破坏 JSON,正文被改过后已解析的结构要像脱敏那样作废重算(`builder.py:1625-1626`)。**未验证**,真栈用例覆盖(§6)。

**同一段显示了两次**(检索显示一次、读文档又显示一次,或两次检索都搜到):文档相同、登记的段号有重叠,就是同一段 —— 合并成一个,段号取并集,标头编号用先显示的那个;出处清单里只出现一次。

**截断显示**(字数预算不够,检索结果只显示了命中的子段,`tools/knowledge_results.py:82-87`):出处对象仍指向整个大段(指纹也按整段算),另加 `partial: true`;评测的「引对了」按**模型实际看到的那部分文字**核 —— 引文落在没显示的部分里不算引对。

#### 3.1.3 数据模型 / 协议变更

**存储**(不加表、不加列):

- 助手消息正文 `content`:**干净的,不带任何编号**。
- `AIMessage.additional_kwargs["citations"]`:

```json
{"version": 1,
 "content_len": 412,
 "sources": [
   {"ref": "D12#7", "doc_seq": 12, "chunk_indexes": [7, 8, 9],
    "title": "文档标题", "filename": "原文件名",
    "heading_path": ["第三章", "3.2 退货"],
    "locator": [{"type": "pdf", "page": 14}],
    "fingerprint": "9f2c41d07ab3e655"}
 ],
 "marks": [{"at": 37, "source": 0}, {"at": 120, "source": 0}],
 "dropped": {"unknown": 0, "earlier_turn": 0}}
```

- `sources[i]` 描述的是**那一段显示过的文字**:`ref` 是它的标头编号,`chunk_indexes` 是它登记的段号,`heading_path` 和 `locator` 是这一段(大段)的。没有页码就没有 `locator` 这个键。
- `fingerprint`:这一段文字(整个大段:标题路径 + 正文)的 SHA-256 取前 16 位十六进制。不可还原成原文;用来判断「后来取到的还是不是当时那一段」(§3.1.5)。重新入库会重排段号,`D12#7` 之后可能指向另一段文字 —— 没有指纹就分不出来。
- `marks[].at`:干净正文里第几个字符之后(按 Unicode 码点数;前端按码点换算)。`content_len` 是算位置时正文的码点数 —— 哪个出口动过正文(长度对不上),就只给 `sources`、不给 `marks`,宁可没有角标也不画错位置。
- **位置只对「正文是一个字符串」的消息给。** 助手消息的正文也可能是分块列表(思考块 + 文字块;`tools/_child_run.py:906-914` 的注释),各处读者拿的是拼起来的文字(`control_plane/transcript.py:110` 的 `turn.text`),而拼法不由我们定;现有的脱敏也只处理字符串正文(`builder.py:3650-3652`)。分块正文的处理:逐个文字块拿掉编号、照常记 `sources` 和计数,**不给 `marks` / `content_len`**。哪些厂商的模型会产生分块正文**未验证**。
- **不带任何内部 id、不带库名**。对外的知识库 API(R1)还没设计,这里不先把内部标识放出去;控制台按「文档号 + 段号」去取原文。(读文档工具的元数据今天已经带着文档 id 和段 id 出现在对外帧里,`knowledge_read_reader.py:406-416,494-502` —— 那是已有的,不在本批改,记给 R1。)
- 一条消息既没有认得的编号、也没有丢过编号时,`citations` 键不出现。
- 工具元数据新增 `sources`(同上对象的列表,检索和读文档都加);子智能体结果的元数据新增 `knowledge_sources`。

- 规则:
  1. 遇到空格 / 制表符,或 `[` / `【`,开始扣。

**层 1 的两种做法**:

| | 甲:把行号和页界带进切段(主方案) | 乙:事后把段落文字对回每页文字(后备) |

| 没有原文件的文档 | 补不了,留空 | 补不了,留空 |

**开工第 0 步(不花钱)**:拿合成 PDF 和开发集里的 PDF 各若干,比较「整篇取」和「按页取再拼」的 Markdown 是否相同,只报「相同 N 份 / 不同 M 份」。

- 相同(或差异只在空白):全用甲。
- 不同:有扫描页的 PDF 用甲(它们本来就是按页取的);纯文字 PDF 二选一 —— 用乙近似补页码,或等它们下次重新入库。由用户定(§7.2 第 2 条)。

**原则**:错的页码比没有页码更糟。任何一步不确定就留空。

**补算**:照 `backfill_profiles.py` 的先例做成手工跑的命令:先空跑,只打印「多少文档、多少段能对上、各种原因跳过多少」(只有数字);`--apply` 才写。

「不调模型、不嵌入」不是天然成立的,要靠护栏:

| 重新解析 / 切段时可能花钱的地方 | 护栏 |
|---|---|
| 扫描页要识别结果。只有识别缓存命中才不花钱,而缓存键里有模型和渲染参数(`persistence/models/knowledge.py:329-335`)—— 平台换过识别模型或参数就不命中 | **只读缓存**;有一页没命中,整份文档跳过并计数 |
| 语义切段要调嵌入找断点(`knowledge/ingestion.py:815-833`),除非这份文档的断点记录还在 | 断点记录在才做;不在就跳过并计数 |
| 图片描述是模型写的 | 只读缓存;没命中就跳过并计数 |
| 按内容哈希把新切的段和库里的段对上:重复的条款、表头、页眉会一对多 | 哈希在这份文档里(新切的一侧或库里的一侧)不唯一的段,**留空** |

实现上给补算命令的解析 / 切段环节**不接任何模型客户端**(识别、嵌入、看图都不给),任何一步想调模型都会直接失败 → 归入「跳过」。这样「不花钱」是结构上保证的,不是靠约定。

**语义切段那条路**(`ingestion.py:824`)也要把行号带出来;它和结构切段是否共用同一段分块代码**未验证** —— 不共用的话那条路先留空,不为它单独做。

**不做**:其它文件类型的位置(Word 没有固定页;表格行号在解析时已经丢了;幻灯片页号是否留在正文里**未验证**)、页内坐标高亮、点开原文件定位到页。

#### 3.1.5 界面

**角标**:控制台按 `marks` 在干净正文的对应位置画小角标,显示序号(`sources` 里的第几个 + 1)。悬停:文档标题、标题路径、页码(有才显示)。点击:右侧抽屉显示**这一段**(大段)的原文,并把被引用的子段号标出来;复用分段预览抽屉,加「按文档号 + 段号定位」的入参。回答下方一行「来源」,列出本条回答引用过的文档。

- 渲染:送进 Markdown 之前,在 `marks` 的位置插入一个内部链接写法,再用链接的自定义渲染画成角标。`content_len` 对不上就不插,只显示来源行。
- 原文按「文档号 + 段号」现取,取到后**先比指纹**:和快照里的 `fingerprint` 一样才显示原文;不一样(重新入库后段号指向了别的文字、段被改过)或取不到(文档已删),只显示快照(标题、路径、页码)并提示「原文已变更」。指纹由取段接口算好一起返回,前端只做比较。
- 权限:看原文需要知识库读权限(与检索记录里看段落原文同一口径);没有权限的人只看到快照。

**没有出处的段落(D1)**:只标不删。

- 单位是 Markdown 的块(段落、列表项、表格行),不拆句子 —— 拆句要分语言。
- 只在「这一轮知识库结果显示过段落」的回答上标;标题、代码块、12 个字以内的短块不标。
- 样式:块左侧一条淡色细线,悬停提示「这段没有标出处,可能是推断或通用说明」。不用红色、不用警告图标。
- 整条回答一个出处都没有时,不逐块标,只在回答下方一行「本回答没有标出处」。
- 调试台里另外显示被丢掉的编号个数(两类分开)。
- 界面判断不了一句话是不是「事实句」。所以标的是「没有出处的段落」,不是「没有出处的事实句」(§7.2 第 4 条)。

#### 3.1.6 边界情况

| 情况 | 处理 |
|---|---|
| 模型写了本轮没显示过的编号 | 丢掉,计入 `unknown` 或 `earlier_turn` |
| 给过 `[D12#7]`,模型写了 `[D12#8]` | 8 号是同一大段里上榜的子段(或本轮读文档显示过)→ 认得,指向那一段;否则不认得 |
| 模型原样抄了读文档的区间标头 | 展开后每个段号都认得 → 一个出处 |
| 一句话后面写了多个编号 | 各自核对;位置相同 |
| 编号写在句子前面、或全堆在回答最后 | 照常记录位置;不纠正。「堆在最后」的比例进评测 |
| 用户问的就是编号本身(「`[D12#7]` 是什么意思」) | 回答里带括号的编号也会被拿掉。绑了知识库的智能体才有这个副作用;记为已知限制 |
| 检索结果因字数预算只显示了命中的子段 | 照常可引;指向同一段 |
| 输出筛查把回答换成了拒答文案 | 没有编号,`citations` 不出现 |
| 回答被用户停止 / 输出被截断 | 已有文本照常核对;文末半截编号丢掉 |
| 重新生成 / 编辑后重答 | 新的一次运行,重新核对 |
| 审批暂停后恢复 | 恢复后的步骤仍在同一轮,暂停前显示过的段仍算本轮(真栈用例覆盖) |
| 文档事后被改名、重新入库、删除 | 消息里存的是回答当时的快照;界面按 §3.1.5 提示 |
| 智能体没绑知识库却写了 `[D12#7]` | 不处理(门控关着) |
| 触发器投递的回答 | 干净正文,无编号(§3.1.3) |

#### 3.1.7 不做什么

- 不按相似度事后补出处。
- 不删、不改没有出处的句子(D1)。
- 不核对「这一段是否真的支持这句话」—— T4。
- 不做 PDF 以外的精确位置、不做页内高亮。
- 不新增 SSE 事件、不加请求参数。
- 不做「每个智能体自己开关出处」的配置项,只有一个平台开关。
- 不改读文档工具元数据里已有的内部 id(留给 R1)。

**目录里四个重排模型的分数刻度**:

第 1 版写「只给 `normalized` / `sigmoid` 的模型填默认值」—— 按这张表,**四个模型一个都填不了**,T3 的默认值等于没做。本版改为下面的规则。

#### 3.3.2 方案

**① 默认值放在模型目录里**:`RerankCaps` 加可选字段 `default_score_floor`。能不能填,按刻度:

| 刻度 | 能不能填默认值 |
|---|---|
| `normalized` / `sigmoid` / `logit`(过 sigmoid 后) | 能,标定后填 |
| `relative` | **默认不能**。只有标定的第 0 步(见 ④)量出来「同一对问题和段落,放在不同候选集里,分数基本不变」,才能填,并把测量日期和结果写在目录注释里 |
| 没声明 | 不能 |

所以:**在当前平台默认模型(`qwen3-vl-rerank`)上,T3 的默认值可能上不了。** 第 0 步通过 → 标定出值 → 上;不通过 → 这个模型没有默认门槛,行为和今天一样。无论哪种,下面 ②③⑤ 都照样上:三态设置、自定义下限的「降一次」、单独的「没找到」结果、0 不绑模型。第 0 步不通过时还有一条路是把平台默认换成分数可比的模型 —— 那是另一个决定(换模型要过检索闸门),不在本批(§7.2 第 3 条)。

**② 库上的设置变成三种状态**(不加列):

| 库上的值 | 今天 | 改后 |
|---|---|---|
| 留空(`None`) | 不过滤 | **跟随平台默认**(当前重排模型有 `default_score_floor` 就用它,没有就不过滤) |
| `0` | 不过滤;但会被绑到当前模型,换模型后「暂停」 | **明确关闭**。不绑定模型、永不「暂停」、不退回平台默认。实现:写入 0 时绑定模型记空;判断「暂停」时把 0 排除(改 `knowledge_rerank_threshold.py:36-42` 和 `protocol/knowledge.py:434-438`) |
| 大于 0 | 自定义,绑定模型 | 不变;因换模型而暂停时,退回新模型的平台默认(今天是退回不过滤) |

不这么改的话:租户填 0 关掉门槛 → 平台换重排模型 → 这个 0 被判「暂停」→ 退回平台默认 → 门槛被悄悄重新打开。

去重分组(`knowledge.py:473-484`)今天按「库上的值 + 绑定模型」分;改后「留空」的库归一组(它们用同一个平台默认),0 的库归一组。

> 已有的库怎么办:**一起拿到默认值**(留空的含义变了)。
> - 支持:今天所有库都是留空,不是租户主动选的「关」;只给新库开,最需要它的老库永远没有。
> - 反对:已有库的行为在发布那一刻变了。
> - 缓解:默认值按「有答案题零误挡」标定;全不过线先降一次;平台开关可一键关;想保持原样就填 0。
> - **这属于哪类变更**:知识库设置接口只对控制台开放,不在对外接口的更新记录范围内;但对租户是「字段不变、含义变了」,和 `changelog.md:13` 说的「行为变化」同性质 —— 按那一类处理:提前告知租户,发布说明里写明。
> - 上线前必须去数:测试 / 生产各有多少库已经填了非空下限。**未数**。
> - 要用户确认(§7.2 第 3 条)。

**③ 降一次(D2)。** 一次检索里所有有分数的候选都被各自库的下限挡掉时,把每个库的下限乘一个系数再过滤一次(同一批分数,不重新调重排)。还是一条不剩 → `below_threshold`。只降这一次;**不做**「只留最好的一条」。结果里记 `floor_degraded`。命中测试里手填的临时下限不降(那是在标定)。平台默认和自定义下限都降。系数和默认值一起标定,起点取 0.7(WeKnora `rerank.go:33`;我们 B-175 设计 `docs/superpowers/specs/2026-10-10-b175-knowledge-base-v2-design.md:265` 当时写的也是 0.7)。

> 10-22 不做降级的理由是「资料确实没写时会把低分段落塞回去」。这个风险仍在,所以只降一次,并且离题题集上要同时报「降之前挡住几题、降之后还挡住几题」。

**④ 默认值怎么定:标定,不拍数。** 只跑检索,不跑智能体。

- **第 0 步:量跨请求可比性**(每个要填默认值的模型都做;`relative` 的模型不过这一步就到此为止)。判据在量之前定死,写在这里:
  - 量的分数是**线上用的那个**:带标题打一次、对前 20 条只看正文再打一次,0.7 × 带标题 + 0.3 × 只看正文(`tools/knowledge.py:97-105`)。不是单次请求的原始分。
  - 先在开发集上取两个数:`G10` = 有答案题「含答案的段里最高分」的第 10 百分位;`O90` = 离题题「最高分」的第 90 百分位。**间隔** = `G10 − O90`。间隔 ≤ 0:这个模型上没有可用的门槛,到此为止(不用再量波动)。
  - 再量波动,只取**门槛会落在的那一带**的「问题 + 段」:含答案的段里分数最低的四分之一,和离题题最高分里最高的四分之一。同一对,放进 4 种不同的候选集里各按线上的方式打一次分(和它原本那次检索的候选一起、换掉一半候选、换掉全部其它候选、只和 19 条随机段一起)。每一对的**波动** = 4 个分数的最大减最小。
  - **通过** ⇔ 波动的第 90 百分位 ≤ 间隔的四分之一。
  - 「四分之一」「第 10 / 第 90 百分位」是我事先选的,不来自数据;要改请在量之前改。拿「含答案的段」和「明显无关的段」两堆整体比是不行的 —— 它们永远离得很远,判据会空过。
  - 花费 = 这些重排调用。
- 第 1 步:在**开发集**(主集 + 真实问法集)上回放检索,拿到每个问题**每个候选**的重排分。现有脚本只输出最后返回的那几条的分数(`tools/eval/kb_eval.py:1319`),被排在后面的含答案段拿不到 —— 标定脚本要自己在重排之后、过滤之前把全部候选的分数导出来(只在评测里)。
- 第 2 步:每道有答案题取「含答案的段里最高的那个分」;每道离题题取最高分。
- 第 3 步:候选下限 F 的约束:降一次之后,**有答案题里没有一道**因为门槛丢掉全部含答案的段。满足约束的最大 F,再乘 0.9 留余量。
- 第 4 步:报告:这个值下两档离题题各被挡住多少;有答案题误挡几道(应为 0);两堆分数的重叠情况。
- 第 5 步:**在留出集上验收**(`<name>.holdout.yaml`,`tools/eval/datasets/kb/README.md:15`「只在一波收尾时跑一次」):用开发集定的值,到留出集上数误挡。标定和验收不用同一批题。
- 挡住的比例很低就如实报:默认值照样可以上(无害),但要说清它几乎不起作用。
- 每换一个平台默认重排模型,重做一遍;没做的模型不填默认值。

界面上现有的 0.70 口径不同(没有「降一次」、没做第 0 步),**不直接沿用**。

**⑤ 单独的「没找到」结果。** `below_threshold` 时工具返回:

围栏内(可以有租户文字 —— 标题):

```text
[no passage was relevant enough to the query: 37 passages were retrieved and none passed the relevance floor]
Nearest documents (titles only):
- D12 示例产品手册
- D7 示例售后政策
```

围栏外的提示(固定文本,92 token;今天的通用提示是 41):

```text
[knowledge_search: no passage passed the relevance floor, so no passage text is shown.
The titles listed are metadata that says which documents exist: a title states no
fact, supports no claim and is not a reference. knowledge_read with a document's
number shows its text. Documents may word a fact differently from the query, so a
search in their terms can find what this one missed; if that finds nothing either,
the knowledge base does not cover this.]
```

- 标题取被挡掉的候选里排名最靠前的不同文档,最多 5 个;只给文档号和标题。
- 文档号不带段号、也没登记过任何段,所以**不能当出处**(§3.1.2)。真去读了,读到的段才可引。
- 这条结果不算「显示过段落」,不触发答前核对(`answer_check.py:68-81`)。
- 用 `bases` 缩小范围后全不过线:沿用现有的「只搜了选中的库」提示(`knowledge.py:1235-1258`),同样附标题清单。
- 有检索路径失败时:沿用「这次检索不完整」的提示,不说「知识库不覆盖」。

> 给不给标题清单?支持:WeKnora 这么做;模型能告诉用户库里有哪几份可能相关的文档。反对:11-05 的追踪里模型曾经凭文件名、标题下结论(`knowledge_read_reader.py:92-95`)。缓解:提示里明说标题不是事实;标题不可引。**未测**:离题题集上数「凭标题下结论」的题数,不为 0 就去掉清单,只留一句话。

#### 3.3.3 数据模型 / 协议变更

- `RerankCaps.default_score_floor: float | None`(新增可选字段)。
- `KnowledgeBase.rerank_score_threshold` 字段不变、取值范围不变,含义按 ② 改;字段说明重写。不需要数据库迁移。
- 库详情接口 `retrieval_config` 多三个只读字段:`rerank_floor_effective`、`rerank_floor_source`(`default` / `custom` / `off` / `none`)、`rerank_floor_default`。
- 检索结果 / 命中测试 / 检索记录多 `floor_degraded`;`below_threshold` 的工具元数据多 `titles`(个数)。检索记录的 `params` / `flags` 是 JSON 列,不用迁移。
- 界面:下限输入框占位文字改成「留空 = 跟随平台默认(当前 X / 当前模型没有默认值);填 0 = 不过滤」。
- 平台开关一个(关 = 今天的行为)。

#### 3.3.4 边界情况

| 情况 | 处理 |
|---|---|
| 库关了重排 / 平台没配重排模型 / 凭据取不到 / 模型不支持 | 没有分数 → 没有门槛(不变) |
| 重排调用失败、限流、超时 | 用融合顺序,没有门槛(不变) |
| 双视图只成了一半 | 不带分数 → 没有门槛(不变) |
| 聊天模型当重排 | 没有分数 → 没有门槛 |
| 模型目录里没填默认值 | 留空的库不过滤;自定义的照旧 |
| 一次搜多个库,下限各不相同 | 各按各的过滤;全部被挡才算全不过线,降的时候各自乘系数 |
| 多个库里有一个填了 0 | 那个库的候选都留下,这次检索不会「全不过线」 |
| 填 0 之后平台换了重排模型 | 仍然是关,不暂停、不退回默认 |
| 重排只判了前 100 个候选 | 没被判的没有分数,不被门槛挡(`knowledge_threshold.py:55-62`) |
| 命中测试手填了下限 | 用手填的,不降;结果里标明来源是 `override` |
| 自定义下限因换模型暂停 | 退回新模型的默认值(没有就不过滤);界面照旧提示重新标定 |

**必须写明的一条**:这个门槛**挡不住「相关但没回答问题」的段落**。T3 的验收只看离题题,不看那 27 题。

#### 3.3.5 不做什么

- 不做「只留最好的一条」。
- 不做按库自动标定、不做界面上的标定向导(B-298 的范围)。
- 不在全不过线时直接结束对话或回固定话术。
- 不给向量相似度阈值加默认值。
- 不为这件事另调一次模型;不在本批换平台默认重排模型。

### 3.4 T4 答后独立核对(只留草图,**暂缓**)

**做不做的条件**:T1~T3 评测后,资料没写的题仍有编造,或「引对了」的比例明显低于「带出处」的比例,才做。

| 项 | 草图 |
|---|---|
| 什么时候触发 | 本轮知识库结果显示过段落,且这一步是最终回答。省钱的收窄:只在回答里有带出处的句子时才核 |
| 核什么 | ① 答的是不是问的那件事(对象对、属性对、版本 / 时间对);② 带出处的句子里,每个数字、名称在它引的那段里有没有。②先用不花钱的文字比对,比不出来的才交给模型 |
| 怎么核 | 另调一次模型,只给:问题 + 回答 + 回答引用的那几段原文(T1 的出处正好用来取段)。不给对话历史 |
| 不过怎么办 | 把核对理由作为平台段贴上,重答一次;只重答一次 |
| 流式 | 照常预览、以权威帧覆盖(对外文档已经这么要求);或这类轮次不出预览(像开了判官那样,`streaming_redact.py:305-310`)。倾向前者 |
| 费用 / 时延 | 每个有出处的回答多一次模型调用:输入约为「问题 + 回答 + 被引用的段」(上限是一次检索的 1 万字符预算),输出很短;被打回时再加一次完整作答。具体数等立项时量 |
| 核对模型答非所问时 | 按「通过」处理并记日志(RAGFlow 的取舍,`agent.go:1086-1090`) |

**为什么是先答再核,而不是答之前先判「资料够不够」**:

- RAGFlow 量过并否决了后者:「Judging the page BEFORE answering was measured and rejected: with no answer to commit to, the model answered "is the page enough?" too harshly, refusing five questions whose facts were all on the page」(`internal/agentic_rag/agent.go:940-945`);「Verification runs AFTER the answer, not before it … it can look for the failure that actually happens here: the right subject, the wrong fact」(`agent.go:1139-1146`)。
- 我们的数据方向一致:27 题全都正确地说了「没写」,错在后面追加的内容 —— 那只有看到回答才能核。
- 我们自己的答前核对(`answer_check.py:21-27`)当初选「搭在已有步骤上、不多调一次」是为了避开这笔费用;T4 是它留的位置(`answer_check.py:40-43`)。

### 3.5 T5 默认返回条数

#### 3.5.1 现状

- 库设置 `retrieval_top_k`:默认 5,范围 1~50(`protocol/knowledge.py:355-360`;接口 `api/knowledge.py:115,136`)。
- 读它的只有命中测试(`api/knowledge.py:1431`)。
- **写它的不只设置页**:命中测试页的「存为默认」会把当时试的条数写进这个设置(`apps/admin-ui/src/pages/knowledge_detail/saveDefaults.ts:62-63`、`SaveDefaultsButton.tsx:28`)。所以不是 5 的库可能比想的多 —— 那些值是为命中测试调的,调的人并不知道以后会影响智能体。
- 智能体工具:默认常量 5、上限 20(`knowledge.py:95-96`),模型不传 `limit` 就是 5(`knowledge.py:1309-1312`);参数说明写死「default 5」(`knowledge.py:1116-1121`)。
- 界面说明:「knowledge_search 默认返回多少条结果。」(`zh-CN.ts:809`;英文 `en.ts:4646`)—— 与实际不符。
- 一次检索实际能显示多少条还受 1 万字符预算限制(`tools/knowledge_results.py:27`)。

#### 3.5.2 方案(D3:让设置生效)

优先级,从高到低:

1. 模型这次调用传的 `limit`(夹在 1~20)。
2. 库设置(多个库取**最大值**),夹到 20。
3. 都没有 → 5。

- 「多个库」指这次实际搜的库(用了 `bases` 缩小范围就只看选中的)。
- **取最大值的副作用**:绑了三个库、其中一个设成 20,那么不缩小范围的每次检索都返回 20 条,其余两个库的段也跟着多显示;条数是这次检索的总数,不是每库各自的。备选是取最小值(调大永远不生效)或取中位数(难解释)。取最大的理由:把某个库调大的人是想多看;总量由 1 万字符预算封顶。
- 实现位置:条数在检索器里、解析出库之后才定(今天是工具在调用检索器之前就定了)。
- 工具参数说明改成不带数字:`Max results (default: the knowledge base's setting, at most 20).`
- 实际用的条数和它的来源(`model` / `base` / `platform`)记进工具元数据和检索记录。

界面说明改为:

> 智能体每次检索默认返回多少条结果。智能体可以在单次检索里自己指定(最多 20 条);这里填的超过 20 时,智能体按 20 算。一次检索搜多个库时,取其中最大的一个。命中测试不填条数时也用这个值(最多 50)。实际显示条数还受单次结果的字数上限限制。

命中测试页「存为默认」的确认框里加一句:「这个条数也是智能体检索的默认条数」。

#### 3.5.3 协议变更

无新字段。`retrieval_top_k` 的字段说明更新;工具元数据多 `limit_source`。

#### 3.5.4 边界情况

- 库设成 50:智能体按 20;命中测试仍可到 50。
- 设置调大后 token 变多:由 1 万字符预算封顶。
- 已经不是 5 的库(含通过「存为默认」写进去的):发布后开始影响智能体。上线前数一次有多少(**未数**),发布说明写明;数量多的话先通知这些租户。

#### 3.5.5 不做什么

- 不把上限从 20 提到 50;不按智能体单独设条数;不改命中测试的行为。

## 4. 对现有行为的影响与兼容

### 4.1 对接方

| 变化 | 默认是否可见 | 说明 |
|---|---|---|
| 回答正文 | 不变 | 存的就是不带编号的正文 |
| `citations` / `sources` / `knowledge_sources` | 多出可选字段 | 客户端按约定忽略不认识的字段(`changelog.md:17`) |
| 事件种类、请求参数 | 不变 | — |
| 回答的说法(T2) | 会变 | 被问的事实资料没写时不再主动给结论;模型行为,不是接口变化,更新记录里写一句 |

| 改过「返回条数」的库(T5) | 会变 | 设置开始生效 |

深护智康的对接不需要改代码。要显示来源,读 `citations`。

### 4.2 已存的对话

- 老消息没有 `citations` 键:界面不画角标、不做淡标,和今天一样。
- 老回答里碰巧有 `[D12#7]` 字样:不处理(只处理新产生的回答)。
- 检查点和事件记录多一个可选键,不需要迁移。**回滚**:用平台开关(停止产生出处),正文本来就是干净的,老版本前端读到多出来的键会忽略。

### 4.3 每轮多花多少 token

只用 o200k_base 算过,各厂商分词没量:

| 位置 | 现在 | 改后(T2) | 再加 T1 | 什么时候付 |
|---|---|---|---|---|
| 工具说明里的作答规则 | 75 | 181 | 238 | 有知识库的智能体的**每次**模型调用;在可缓存的前缀里 |
| 答前核对 | 66 | 86 | 111 | 本轮显示过段落之后的每一步 |
| 读文档结果后的提示 | 76 | 82 | 82 | 每次读文档 |
| 「没找到」的提示 | 41 | 92 | 92 | 只在全不过线时;另加最多 5 个标题 |
| 工具元数据里的 `sources` | — | — | 0 | 不发给模型 |
| 回答里的编号 | — | — | 每个约 5(输出) | 每处引用;不进后续轮次的历史(正文是干净的) |
| 子智能体回传里插回的编号 | — | — | 每个约 5(父级输入) | 子智能体引用了几处就几个 |

举例:一轮三步(检索 → 读文档 → 作答),输入多 3 × 163 + 2 × 45 + 6 = **约 585 token**,其中 489 在可缓存的前缀里;一条带 6 处出处的回答,输出多约 30 token。没绑知识库的智能体:0。

### 4.4 时延

- 核对是纯内存的正则 + 查表。
- 流式:只有碰到空格或 `[` / `【` 才扣,下一个字符不像编号就立刻放,最多扣 64 个字符。
- T3:不多调重排。
- 页码补算:手工命令,不在请求路径上。

## 5. 评测与验收

### 5.1 这套评测量得到什么、量不到什么

沿用 `tools/eval/kb_agent_*`(真模型答题 + 3 票判分 + 按断言判,`kb_agent_judge.py:1-28`)。它的答题循环是**单轮**的、自己写的循环(每题最多 3 次检索、3 次读文档,`tools/eval/kb_agent_answer.py:33-37,190-204`),直接取产品的工具说明、答前核对和(新增的)核对函数,**不经过 `agent_node`**。所以:

| 这套评测能量 | 只能在真栈上验(§6 的用例,结果是过 / 不过) |
|---|---|
| 模型抄不抄编号、抄得对不对 | 流式预览里看不到编号、预览与权威正文一致 |
| 核对函数的输入输出 | 对外四个出口的字段 |
| T2 措辞的效果 | 子智能体回传后父级能引 |
| T3 检索层的挡与不挡 | 响应缓存命中后的出处 |
| | 旧结果被压成引用行(#1972)之后的行为 |
| | 多轮:上一轮的编号被丢、追问时多出来的读文档次数 |
| | 审批暂停恢复、触发器投递、重新生成 |

多轮指代集在 `tools/eval/behavior_coref.py`,是对着测试环境跑的行为评测,**不在评测 PR 里交付**;多轮的两个数(因为是上一轮的编号而被丢的题数、追问时的读文档次数)在发测试后用它跑,写进验收手册。

### 5.2 新指标

**统计脚本直接算、不花判分钱的**(结果行里新增:模型原始回答、干净正文、`citations`):

| 指标 | 定义 | 分母 |
|---|---|---|
| 带出处比例 | 回答里至少有一个认得的出处 | 有答案题里没有拒答的题次 |
| 出处指向含答案段的比例 | 被引用的段(显示给模型的那一段文字)里至少有一段含本题标准答案的原文片段(现有的文字投影比对) | 带出处的有答案题次 |
| 假编号 | 被丢掉的编号个数、涉及的题次;两类分开 | 全部题次 |
| 写法不规范 | 靠规范化才认出来的编号个数 | 全部编号;分模型 |
| 出处堆在最后 | 全部编号都在回答最后一个块里的题次 | 带出处的题次 |

**判分看的是哪份文字**:原有的全部指标(编造、夹带推断、误拒、答对、「原文写了」等)在两臂上都看**干净正文**(用户实际看到的那份),**判分模板不改** —— 改动前那一臂的判分缓存继续有效,老结果不用重判。只有下面的「引对了」另做一遍判分,看的是带编号的原始回答,只在新的一臂上做。

**另做一遍判分才有的**(新模板,只在新一臂上跑,多一轮判分费):

| 指标 | 怎么得到 |
|---|---|
| 引对了 | 给判分模型看带编号的原始回答,让它列出每条事实性结论、抄一句支持它的原文、并抄下这条结论后面跟着的编号。统计脚本核对「那句原文是不是在被引的**那一段**文字里(按模型实际看到的部分)」:在 = 引对了;在别的段里 = 引错段;没编号 = 没引 |
| 没有出处的事实结论 | 判为事实性(不含「不需要出处」「标明了的推断」)却没有编号的结论数 |
| 推断是否标明 | 现有两类,口径不变 |

**原有三个数照旧盯**:资料没写题的编造、夹带推断、有答案题的误拒。

**建议类题(新增,10 题,合成)**:资料里有依据、问的是「我该怎么做 / 怎么安排」。这 10 题用一段**「给建议的角色」系统提示词**跑(合成的、不含租户内容,只在评测里)—— 评测现在的通用提示词是「客服助手,先查知识库再回答」(`tools/eval/kb_agent_answer.py:30-32`),没有角色,量不出「角色该给的建议」有没有被压住。看改动前后「给出了建议」的题次。

**每题跑两次**;报告按题次合计,并给逐题配对的变好 / 变坏数。

**分模型冒烟**(GLM / DeepSeek / Qwen 各跑同样 20 题,只看格式类指标)。

**页码**:① 合成的多页 PDF(纯文字、扫描、带重复页眉页脚、跨页段落、带表格各若干),已知每段在哪页;② 真实资料:评测集的 `page` 字段现在全是空的(`datasets/kb/README.md:95`),要先人工给开发集里 30 道 PDF 题标上页码,才有真实对照 —— 这是人工活,不花模型钱。审查意见说「用带 `page` 字段的真实用例验」,字段有、值没有,所以要先标。

### 5.3 必须变红的对照(证明指标咬得住)

全部在已有结果行上离线重算,不调模型:

| 对照 | 做法 | 必须看到 |
|---|---|---|
| 注入假编号 | 给每条原始回答末尾加 3 个本轮没显示过的编号,重跑核对函数 | 「假编号」正好多出 3 × 题次;进入出处清单的为 0 |

| 换成没显示过的段 | 把每个位置的出处换成**别的题**显示过、本题没显示过的一段 | 「引对了」降到 5% 以下(引文不可能在那一段里);不到就说明指标不咬,结果作废、先修指标。(第 2 版是「换成本题显示过的另一段、降一半」:本题只显示了一段、或好几段都含答案时会误判,已改) |
