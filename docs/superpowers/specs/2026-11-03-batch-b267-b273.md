## B-272 数组 / 对象参数被写成字符串

**现状**(main `b164af88e`):

- `ask_image.region` 的 schema 是 `anyOf[字符串 "auto", 4 个 0–1000 的整数数组]`
  (`services/orchestrator/src/orchestrator/tools/vision.py:1131-1143`);`read_page.region` 是纯数组(`read_page.py:1458-1467`)。
- 所有工具的参数都在一处校验:`_invoke_tool` → `_validate_tool_args`(`graph_builder/builder.py:4517-4589`,
  Draft 2020-12),不合格 `[invalid args] arguments failed schema validation: $.region (anyOf)`、不调工具、不重试。子代、MCP 工具同一路径。
- 平台没有任何「把字符串化的数组还原」的处理;provider 只 `json.loads` 顶层 `arguments`(`llm/providers/openai.py:883-895`)。
- 同样暴露的参数:`read_page.units`、`update_plan.steps`、`edit_file.edits`、`manage_task.by_day/time`、`knowledge_search.bases`、
  `http.headers`、每个带数组 / 对象参数的 MCP 工具(没有观测到 glm 在这些上出错,是结构性暴露)。

**方案**:在校验层统一处理,只在**已经校验失败**时尝试:

1. 对每个出错路径的**顶层**键 `k`,若 `args[k]` 是字符串且 `json.loads` 得到 list / dict,在**副本**里替换。
2. 用**同一个 schema** 重新整体校验;全部合格才用副本调工具,否则返回**原来的**错误文本(不回显值)。
3. 只还原顶层、不递归;不改模型看到的 schema;记计数 `expert_work_tool_args_coerced_total{tool}`。
4. 轨迹 / 审计记录模型原样给的参数(还原前)—— 写进说明。

**为什么不改 schema**:只修 `region` 两处 schema 会让钉 schema 形状的测试变红,别的工具照样暴露。

**测试**:`test_tool_arg_validation.py` 新增:字符串数组被还原并调用;还原后仍不合格 → 原错误、不调用;非 JSON 字符串
(`"0,0,100,100"`)仍拒;本来就接受字符串的参数不被改写;错误文本不含值。每条先破坏实现确认变红。

## B-268 看文档页来回重看

**现状**:

- `FIGURE_KEEP_RECENT = 3`(`graph_builder/figure_block.py:46`,注释写明借自 hermes / openclaw、没测过),`_window` 只留最新 3 个
  `(doc_sha, unit, region)` 槽位;`read_page` 一次最多 3 页(`MAX_PAGES_PER_CALL = 3`)—— 4 页文档永远不能同时在视野里。
- 退出提示(`figure_block.py:223-226`)写着「需要重看就调用 read_page」。
- 主代、子代同一段代码;子代每次 `sub_thread_id` 新起,`viewed_figures` 从空开始。同一 run 重看同一页 ref 不变,**没有计数**。
- 每张图在压缩预算里按固定 1,300 token 计(`IMAGE_BLOCK_TOKEN_COST`);生产那一步 7 万 token 大头是历史回执 + 思考,窗口是**触发器**不是体量。
- **防循环兜不住**:`LoopDetectionMiddleware`(`expert_work/runtime/middleware/loop_detection.py:184-192`)只在最近 N 次工具调用
  **完全相同**时触发;轮换 `units` 的调用永远不相同,所以只能跑到步数 / token 上限才停 —— 这就是「一轮几十分钟」。

**评测结果(E2,11-03,¥3.80,8 次,测试环境,合成纯图片季度销量表 PDF,子代 / 主代 glm-5.3-flash 直接看图)**:

| 次 | 页数 | read_page 次数 | 看页顺序 | 结果 |
| --- | --- | --- | --- | --- |
| r4a | 4 | 12 | [1,2,3] [4] [1] [2] [3] [4] [1]… 严格轮转 | 12 分钟被截停;**Q3 整列编造**(写的时候第 3 页已退出) |
| r4b | 4 | 10 | [1] [2] [3] [4] [1] [2]… | 第 10 步把抄录写进文件后才停,答对 |
| r3a | 3 | 18(2 整页 + 16 局部) | 局部图挤掉整页,反复 | 子代答错:Q2 整列编造 |
| r3b | 3 | 20(3 整页 + 17 局部) | 同上 | 截停;编出不存在的商品行 |
| r6f1 / r6f2 | 6 | 11 / 8 | [1,2,3] 与 [4,5,6] 交替 4 轮 | 写进文件后才停,答对 |
| r6a / r6b | 6 | — | 主代改走 OCR,没走看图 | 不计 |

结论:

1. **窗口是触发器,已确认**:4 页、6 页都按「最早那页退出 → 重看」严格轮转;模型在思考里直接引用退出提示作为重看理由
   (「第 1 页的图已退出上下文,重新渲染查看」)。**退出提示本身是诱因**:点名一页并告诉它怎么取。
2. **不只是浪费,还会答错**:写到某页时它已不在视野里,数字就**编出来**(r4a / r3a / r3b)。原因:glm-5.3-flash 的思考
   不回放到下一步,「我已经记下来了」只有写进回复或文件才成立;**所有答对的 run 都先把抄录写进了文件**。
3. **局部图占整页的位置**:槽位含 `region`,3 张局部图就把 3 页整页全挤掉;3 页文档照样抖。退出提示还会在局部图仍在时说
   「编号 1-3 已退出」,误导。
4. **防循环兜不住**:轮换 `units` / 换 `region` 永不相同,`no_progress` 一次都没触发。
5. 旁见(不属 B-268):没有看图能力的 glm-5.3 主代不信子代的结果,花比子代更多的钱自己验证(装 OCR / 手搓字形比对)。

**方案(评测后定)**:

1. **窗口按「正在读的那份文档」放宽**:最近 `read_page` 的那份文档的**整页全部保留**,上限 **6 页**;别的文档照旧「最近优先」。
   若真实页面图 token 很大,再加一个图片 token 上限(候选约 12 万),先到先停。
2. **局部图单独一条道**:最多 2 张、最新优先,只挤局部图、不挤整页。
3. **重看回执**(同一 run 再读同一页 / 同一局部时追加,照常渲染):
   > 第 {n} 页这次任务里你已经看过(第 {k} 次读取)。这份文档第 {a}–{b} 页现在都在你眼前,不用再取。注意:你思考过程里记下的
   > 数字不会保留到下一轮——需要的数字请直接写进回复,或用 write_file 记到工作区文件里,之后以文件为准。
4. **退出提示改写**(超上限退出时;不点名「下一个该取哪页」):
   > 编号 {ranges} 的图因同时可见页数上限({cap} 页)已退出上下文。你之前写进回复或文件里的内容仍然有效,不要为了「全部同时
   > 核对」而轮流重看。只有确实缺某个数字时,再调用 read_page 取那一页。
5. **超上限预告**(首次读一份超过上限的文档):「这份文档共 {N} 页,超过同时可见上限 {cap} 页。请边看边把数字写进工作区文件,
   再基于文件计算。」
6. **熔断**:按 run 计 `(文档, 页, 局部)` 读取次数 —— 第 4 次读同一页**不渲染**,返回「这一页本次任务已读取 3 次,不再渲染。请根据
   已写下的内容完成任务;确实缺数据就在答复里说明缺什么。」;同一文档渲染次数超过 `2 × 页数 + 3` 同样处理;拒绝计入防循环次数,
   让 `DEFAULT_LOOP_TRIPS_PER_RUN = 2` 能收尾。依据:正常 run 每页最多重看 1 次,r4b 最后核对才到第 3 次,不会被误伤。
7. 计数要按 run(主代 `viewed_figures` 跨轮累积,ref 带 run 段),不能挡后续轮次的正常重看。

**改后验证**:同一套 3 / 4 / 6 页任务复跑(发测试后),判据:没有轮转、不编造、`read_page` 次数 ≤ 页数 + 2。

## B-273 切条在整体类问题上误报 `found`

**现状**(`tools/tile_reading.py`):

- 条上提示已写明「需要数整张图 / 跨图比较的问题回 not_found」—— 只靠提示,豆包没守住。
- 分组只比值、不比字段名;**1 组(不论几条)= `single` → 用条上读数**;2 组以上 = `conflict` → 整图兜底(标不确定)。
- 整图那一次本来就和条并行在跑,改走整图**不多花钱**,代价只在小字准确率(整图 44%、密集化验单整页约 2–6/24)。
- 已有测量回算(`vlm-measure` 当前切法):整体题 10 组里 2+ 条不同值 3 组(都靠冲突兜住),2+ 条同值 0 组;
  具体值题 44 组里 2+ 条同值 3 组,全是**相邻两条重叠部分看到同一行**;密集化验单 24/24 只有 1 条 found。
  旧切法数据里有 1 组整体题「2 条同值、字段名不同、值是错的」—— 正是这个隐患。

**评测结果(E1,11-03,¥12.44,1,249 次调用,测试 pod 里直接调生产的切条 / 聚合函数)**:

- 新造 30 张触发切条的合成整体类图(聊天提醒记录 / 长表 / 长列表 / 高柱状图,19 张是「几条各看到相同局部数」的隐患形状)
  + 已有 7 道整体题 = 37 题 × 3 遍;具体值题 38 道(化验单 24 + 通用 14)× 2 遍。
- **真正的隐患不是「多条同值」,而是「只有一条说找到」**:现行规则下整体题错且未标不确定 54/111,其中 45 次只有 1 条 found
  (38 次是带标题 / 表头的第 1 条;14 次报的是 0)。多条 found 的规则(R1 / R2 / R3)最多只能消掉 9 次。
- 整体题上条的答案 55 次只对 1 次、整图对 54 次;具体值题反过来,化验单 / 照片上整图只对 8/56 —— **该按问题类型分流,
  不该拿整图去交叉核对**。

| 规则 | 整体题准确率 | 整体题错且未标 | 具体值准确率 |
| --- | --- | --- | --- |
| R0 现行 | 51.4% | 54 | 92.1% |
| R1 多条 found 一律整图 | 58.6% | 45 | 89.5% |
| R2 只认相邻两条同值 | 56.8% | 47 | 92.1% |
| R3 整图里有同一个数才认 | 52.3% | 53 | 89.5% |
| **V1 按措辞分流(推荐)** | **99.1%** | **1** | **92.1%** |
| V2 计数题条上报 0 视为没找到 | 60.4% | 44 | 92.1% |
| 「第 1 条单独 found 就走整图」(全量) | 86.5% | 14 | 77.6% |

**方案(评测后定)**:

1. **按措辞分流(V1)**:`region="auto"` 时先看问题文字,像整体类问题(计数 / 合计 / 平均 / 最高最低 / 排名 / 哪些 / 趋势 /
   差值,中英两套词)就**不切条、直接用整图**(同小图 `gated`,`meta.auto=whole_question`),否则照旧切条。
   - 防误判:引号里的词不算;「合计 / 最高 / 平均」后面紧跟「一栏 / 一行 / 一列 / 字段 / column / row」不算;「最X」只在后面是
     「的 / 是 / 为 / 值 / 标点 / 句末」或问题里有「哪」时才算 —— 「最高血压是多少」「最大摄氧量那一项」仍切条。
   - 词表 75 道测量题 100% 准、另 79 道查值题 0 误判;**部分是在同一批题上调出来的,偏乐观**,改后要用新写的题再验一次。
2. **保留 R2 兜底**(多条 found 只认「相邻两条、字段名一致或为空」),**V2**(计数类问题条上报 0 视为没找到):免费,
   只在词表漏掉时起作用;字段名条件这次测不出差别(两条 found 的情形字段名都一致或为空),保留。
3. **不做**:拿整图交叉核对单条答案(具体值题会标掉 56/76)、第 1 条单独 found 一律走整图(化验单丢 11/76)。

**残留风险(写进说明)**:不含词表词的整体问法(「谁的分数第一」「有没有超过 100 的」、其它语言)仍走切条,落到 R2 + V2
(该数据上 37/111 错且未标);分流后的整图答案不标不确定(合成图 110/111 对,真实模糊页会更差);词表是语言相关的,
扩语言要补词。

## B-269 排队的新消息看不到原因

**现状**:

- 同一会话一次只跑一个 run(B-139):`thread_queue.admit` 只返回 `ahead`(前面几个),**丢掉了前面 run 的 id 和开始时间**
  (`services/control-plane/src/control_plane/thread_queue.py:71-89`)。
- 流式:只有一帧 `queued {run_id, thread_id, ahead}`,之后只有 `: heartbeat` 注释;这一帧不进 `run_event`,重连 / 幂等重放看不到。
  队列模式:202 只有 `{run_id, thread_id, status}`。对外 run 列表没有开始时间 / 心跳 / 排在谁后面。
- `agent_run` **没有开始时间列**,只有 `updated_at`(进 RUNNING 时写,但终态 / 孤儿接管会再改)和 `heartbeat_at`。
- 已有取消接口(对外 `…/runs/{id}:cancel`、控制台 `…:cancel`),对接方现在就能「列运行中 → 取消 → 再发」。

**方案(只加信息字段)**:

1. 新列 `agent_run.started_at`(可空):`set_status` 进 RUNNING 时 `COALESCE(started_at, now())`(孤儿接管不覆盖);老行不补。
2. `Admission` 带上「领头 run」(第一个 running / pending,否则最早的 busy)。
3. `queued` 帧加可选字段 `ahead_run_id`、`ahead_status`、`ahead_started_at`;队列模式 202 加 `ahead` 与同样三个字段。
4. 对外 run 列表(`external_runs.py:479`)、控制台 run 列表 / 详情:加 `started_at`、非终态加 `heartbeat_at`;
   `status=queued` 的行加 `queued_behind {run_id, status, started_at}`(按会话一次 `list_inflight_by_thread`)。
5. 控制台排队气泡:「排队中,上一轮已进行 N 分钟」。
6. 文档:`sse-events.md`(queued 帧字段)、`chat.md`(上一轮还没结束时 + 202 示例)、`query.md` §5.4、`changelog.md`
   「新增可选字段」—— 不需提前通知,随发布记录。

**不做**:事件流新事件、`if_busy=interrupt`(行为变化 + 新旧两轮重叠写检查点的风险,另立)。

## B-270 长任务没有进度

**现状**:进度素材都已落库,只是没汇总 —— `run_event` 里有 `updates.agent.step_count`、每次工具结果、`worker` 起止帧、`plan` 快照;
`agent_run` 有 `heartbeat_at`;控制台只显示「运行中…」。

**方案(只加信息字段)**:

- 进度对象(不含内容):`{elapsed_s, step, tool_calls, active_workers, current: {node, tool} | null, last_event_at, plan_done?, plan_total?}`。
- 在 run 读接口(对外 run 列表、控制台 run 详情 / 列表)对**非终态** run 返回 `progress`,由 `run_event` 按 `(run_id, seq)` 主键
  一条聚合查询算出(跨副本一致,不新增跟踪);`elapsed_s` 用新列 `started_at`。
- 控制台运行中气泡显示「已进行 N 分钟 · 第 S 步 · 调用工具 T 次 · 子任务 W 个在跑」。
- 文档:`query.md` §5.4 字段表、`changelog.md`「新增可选字段」。
- 风险:极长 run 的聚合查询代价 —— 实现时量一条生产量级 run 的耗时;超标再改为心跳时顺带写一列。

5. 行照样软删(对用户的到期语义不变);I/O 失败跳过、明天再试(维持)。
6. 已经被旧作业软删过的行(若发布前有)由一次性补扫处理 —— 发布前在生产只读统计 `deleted_at IS NOT NULL` 行数,0 则不需要。
7. 迁移后留在 agent 根的原件(P3 复制而非移动):本批写明不处理,另立。

**测试**:夹具按真实位置放文件(老布局 / 对话布局各一),含「两行共用一个文件」「文件被改过」「会话已删」;每条断言先破坏再验红。

## B-267 绑了知识库却去搜网

## 实现记录(11-04)

各组实现后都经过独立审查,MEDIUM 以上清零才并入批次分支。与上文方案不同、或方案没写到的地方如下。

### B-272

- 只还原顶层、且只在校验已失败后;`json.loads` 的 `RecursionError` 与超过 100 万字符的字符串按原错误处理。

### B-268

- 视野:正在读的那份文档最多 6 页;**其它文档合计仍按原来的 3 页**(审查指出若一并放宽,之后每一步都多带约 6 千 token 不进缓存的图片)。局部图单独一条道,最多 2 张。
- 熔断:同一单元第 4 次读取不渲染;**「同一文档渲染超过 2×页数+3」改为「重看次数超过本轮已读单元数 + 3」**,第一次读某个单元永不拒绝 —— docx 的单元是图、不是页,按页数算会拒掉第一次读。局部图另有每份文档每轮 12 张的额度。一次请求里只有部分单元超额时,其余照常渲染并附说明;整次都没渲染才计一次防循环。
- 计数按「本轮的首个 run」(审批续跑换了 run_id 也接着算);子代各自独立。
- 拒绝说明放在平台提示位置(`notice`),不进被当作文档数据的正文;提示文字用 read_page 参数的「unit」称呼。

### B-273

- **V2(计数题条上报 0 视为没找到)删除**:它与 V1 用同一套词表,凡是计数题都已被 V1 送去整图,V2 永远走不到。
- 词表加了通用防误判:检验项目名 / 字段名里的「平均 / 总 / count / total / mean」(如「平均红细胞体积」「platelet count」「total cholesterol」)、`number of the <名词>`、数字后的 `min`、带「每 / per / a day / each」的计数问法(用药剂量类,如「每天最多吃几次」「How many mg per tablet」)都按查具体值处理,仍走切条。
- **整图答案的兜底**:命中词表时切条照跑(花费与改前切条路径相同),优先用整图答案;只有当切条在一个**带字段名**的格子上一致读到某个值、而整图答案里没有这个值、且不是计数题时,才附上中性说明「某条把字段 X 读作 Y,若问题问的是图上印着的值,请放大该字段核对」。
- 离线复算(E1 原数据,不花钱):

  | 规则 | 整体题准确 | 整体题错且未标 | 答对却被标 | 具体值准确 |
  | --- | --- | --- | --- | --- |
  | R0 改前 | 57/111 | 54 | — | 70/76 |
  | 词表 + 防误判 + 兜底(上线版) | 110/111 | 1 | 5 | 70/76 |

  把全部具体值题强行当整体题走:无兜底 50 次错且未标,有兜底 2 次。审查新写的 19 种易误判问法全部按查具体值处理。
- 残留风险:不含词表词的整体问法(「最大的柱子」「峰值」「有没有超过 100 的」)仍走切条,靠 R2;「合计金额是多少」这类印着的合计会走整图,只有带字段名的条读到不同值时才提示;词表偏中英两种语言。改后要用新写的题在测试环境再验一次。

### B-269 / B-270

- `started_at` 用写 `updated_at` 的同一应用时钟(`set_status` 与 `claim_queued` 两条进入 RUNNING 的路径);审批续跑是新的 run_id,有自己的 `started_at`。
- 会话空闲时 202 形状不变;重复提交(幂等重放)的 202 不带 `ahead*`。
- 对外 run 列表的 `queued_behind` 只列同一用户的 run,挡在前面的是别人的 run 时为 `null`(实时 `queued` 帧与 202 不做这层过滤,文档已写明)。
- `progress` 由一条按 `(run_id, seq)` 的聚合算出,每条帧只解压一次,按租户过滤,2 秒语句超时;任何一个字段查询失败只省略该字段,列表照常返回。本地 158 MB / 50 个 run 的一页约 0.1 秒;**上生产前在生产库只读量一次最大 run**。`active_workers` 只算最近一次执行尝试(最新 `metadata` 帧之后)里开始且未结束的子任务。
- 控制台:运行中的气泡用自己收到的事件算进度,不再请求接口;排队气泡每 30 秒刷新、页面隐藏时暂停、切换租户查看时不刷新(否则每次都写一条切换租户审计)。

### B-271

- 按会话当前的 `agent_name` / `workspace_layout` 找真实位置;用目录句柄逐层打开(`O_NOFOLLOW`),删除前核对是同一个文件,杜绝中途把目录换成链接而删到别人的文件。
- 用户目录内的路径打不开(链接、无权限、特殊文件):行照常过期、文件保留、计数;临时性错误次日重试,过期 7 天后仍失败则放弃(行过期、文件保留)。
- 租户 / 用户这一级目录打不开:只跳过该用户本次的行;超过 3 个用户同时出问题、或存储根目录打不开,整段停下;一次运行里要放弃的行涉及超过 3 个用户时一律暂不处理。任一情况作业以退出码 3 结束,让人来看。
- 没有 sha256 的老行:从上传审计记录里取回 sha256(唯一匹配才用),否则只比大小;上传清理因此改到审计清理之前执行。

### B-267

- 总开关 `EXPERT_WORK_KB_FIRST_ROUTING` 默认开;关 = 规则、单库目录、画像、探测全部不生效,也不花钱。
- 搜网替身:`EXPERT_WORK_WEB_SEARCH_FIXTURES_DIR` 只在测试环境配置(挂载评测夹具),生产选了夹具会构建失败。评测智能体只用接口 / YAML 配置,打分时校验每次搜网都走了替身(控制台表单关再开 web_search 会丢掉 `fixture`)。
- 画像:只用文档标题 / 小标题 / 开头生成,全部标题都列入、24 份抽样细看;内容不变不调用;每次一次带输出上限的调用(辅助模型 glm-5.3-flash,关思考)。**只在用户确认过费用的入库之后刷新**;删除 / 停用文档会立刻隐藏画像(不花钱),等下次确认入库再生成。老库补画像:命令默认只预演,执行必须带预演出的总额,先报用户。
