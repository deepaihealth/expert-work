## 3. 业界做法(读原文,2026-10-21)

- **默认就能处理扫描件的开源知识库只有 RAGFlow 和腾讯 WeKnora**;Dify / FastGPT / MaxKB / Onyx / Open WebUI 默认对扫描页输出空,要手动开插件或换解析器。
- **都逐页判**:WeKnora 图面积 ≥ 0.5,或 < 10 字且图 ≥ 0.1(`docreader/parser/pdf_parser.py:75-83, 175-185`);RAGFlow 前 200 字私有区 / CID 乱码 ≥ 30% 强制 OCR(`deepdoc/parser/pdf_parser.py`)。按整份判的(Unstructured、AnythingLLM、我们)都有混合文档漏页问题。
- **中文 OCR**:约 10 亿参数的文档专用模型最好(OmniDocBench v1.6,2026-09-11:PaddleOCR-VL-1.6 96.3 / MinerU2.5-Pro 95.8 / GLM-OCR 95.2,高于 Gemini 3 Pro 92.9;榜单由 MinerU 团队维护);Tesseract / EasyOCR 中文编辑距离 0.40~0.55,不可用。
- **图片**:先过滤再描述,保留原图。一篇生产论文(arXiv 2604.23276)样本里 logo + 水印 439 张、真内容图 176 张;描述分「图表转数据 / 其他逐字抄图中文字」两种(RAGFlow `vision_llm_figure_describe_prompt.md`);加描述后端到端 +3~6 分(UniDoc-Bench 0.619→0.654),图表题差距最大(OHRBench 图表证据召回理想 70.3、MinerU 16.5)。
- **以图搜页(ColPali 类)不做**:pgvector 没有 MaxSim、阿里云 RDS 不提供 VectorChord;英文基准上好的文字流水线 + 重排(63.6)不输视觉检索;中文无对照。
- **工程**:olmOCR 逐页重试(最多 8 次、逐次升温打断复读;`finish_reason != stop` 判失败;失败页回退文字层);Onyx 上传时卡图片数(每文件 500 / 每次 1,000)。

**WeKnora(本机 v0.8.3)借鉴 / 不借鉴**

| 借鉴 | 不借鉴(原因) |
|---|---|
| 逐页判定;扫描页 200 DPI、长边 2,000 px、JPEG 85 | 删掉文字页里所有 1~3 位数字的行、连续 ≥ 3 行纯数字行(`pdf_parser.py:148-162, 229-279`)—— 化验单 / 报表数字会丢 |
| 系统固定的 OCR 提示词,租户自定义指令不进 OCR | 插图挪到整页文字之后(`:1732-1741`)—— 图与描述它的段落可能分到两段 |
| 输出校验:空话列表、复读检测、HTML → Markdown、截断即失败(`ocr_sanitizer.go`) | OCR 文字整页一个块、不切分、不带标题(`image_multimodal.go:395-411`) |
| MarkItDown `keep_data_uris=True` 再把 data URI 抽成独立图片 —— 正好修 Word 占位符 | 没有 OCR 缓存,重解析全额重付 |
| 图片过滤:≥ 80 px、≥ 页面 1%、≥ 50% 页面重复视为 logo、同页去重、每份 50 张 | 没有页数上限、没有预算 |
| 「先观察再决定要不要 OCR」(`image_pipeline_smartocr.go`) | 看图模型默认关,关着时扫描 PDF 静默「成功」 |
| 单张图失败不拖垮整篇、按模型限并发、可重试 / 不可重试分类 | caption 成功就不再重试 OCR(扫描页的 OCR 才是正文) |

## 5. 设计

### 5.1 流程

```
上传 → 解析(按格式)
         ├─ PDF:逐页判定(§5.2)
         │     ├─ 文字页:现有 pymupdf4llm 文字 + 本页插图(§5.4)
         │     └─ 扫描页:渲染 → OCR(§5.3)→ 识别文字(带页码)
         ├─ docx / pptx:MarkItDown 保留图片 → 抽出图片(§5.4)
         └─ 其它格式:不变
       → 按页拼回 Markdown(图片描述插回原位置)
       → 现有切分(带文档名、标题路径、页码)→ 嵌入 → 索引
```

识别文字与图片描述都是**普通正文**,走同一条切分 / 嵌入 / 检索 / 重排路径,检索侧零改动;B-206 的父子块、预算、厂商中立都直接适用。

### 5.2 逐页判定

每页算三个信号,任一成立即判「要识别」,并把**判定结果与原因**记进逐页记录(§5.6):

1. **几乎没字且有图**:去空白后字数 < 50,且页内有图片对象或非矩形矢量路径(纯空白页不判)。
2. **整页是图**:图片覆盖面积(放置框并集,裁到页面内)≥ 0.8。阈值高于 WeKnora 的 0.5 —— 语料实测 0.5 会把「文字压在背景图上」的模板页判进来(623 页),多花钱且识别文字反而不如文字层。
3. **文字层是乱码**:私有区 / U+FFFD / CID 字符占比 ≥ 30%(RAGFlow 同款);中文 PDF 字体映射错位常见。

**隐藏文字层**(扫描件自带的不可见 OCR 层,语料 114 页):默认**保留**,不重识别(省钱;质量差的会被信号 3 抓到)。

一页判了「要识别」就**整页识别**,不和文字层混拼(避免同一句话出现两遍)。

### 5.3 扫描页识别

- **渲染**:PyMuPDF,200 DPI,长边上限 2,000 px,JPEG 85。
- **调用**:按平台配置的识别模型(§5.7)。两类接口各一个薄适配:
  - `layout_parsing`(glm-ocr):`POST /api/paas/v4/layout_parsing`,`{"model":"glm-ocr","file":"data:image/jpeg;base64,…"}`;不收提示词,自带版式模型去页眉页脚;回 `md_results`(表格是 HTML)+ `layout_details`(每块带标签与 bbox);无 `finish_reason`。
  - `chat_vlm`(qwen3.7-flash 等 OpenAI 兼容看图模型):图片走 `image_url` data URI,提示词为系统固定的扫描页 OCR 提示词(WeKnora `vlmOCRScannedPDFPrompt` 改写:阅读顺序、表格 Markdown、忽略页眉页脚页码、不翻译、不猜、无字回固定句),温度 0.1、关思考、`max_tokens` 8,192。
- **输出清洗**:去代码围栏;HTML 表格转 Markdown 表(含 `colspan` 展开、实体解码);去掉模型的固定空话(「No text content.」等,含出现在正文末尾的情况);LaTeX 包裹的纯文本还原。
- **校验 → 失败**:空输出;截断(`finish_reason=length`);复读(长周期重复占 ≥ 80%);字数远低于版面预期(版面块数 × 下限)。失败的页**换兜底模型重识别一次**;仍失败 → 该页标记失败(§5.6),不阻塞整份入库。
- **并发与重试**:按厂商限并发(glm-ocr 默认 2);429 / 5xx / 超时指数退避(0.5 s × 2ⁿ,上限 8 s,最多 3 次,同 B-206 K-7);4xx(非 408 / 429)不重试。

### 5.4 文档内图片

- **提取**
  - PDF 文字页:PyMuPDF 取本页图片对象及其放置框(`page.get_image_info(xrefs=True)`),按纵坐标找到它在本页文字中的位置,**插在原位置**(不挪到页尾)。
  - 扫描页:glm-ocr 返回的 `layout_details` 里标为 image 的区域(`![](page=0,bbox=[…])`)按 bbox 从渲染图裁出,同样走过滤与描述。
  - docx / pptx:MarkItDown `keep_data_uris=True`,再把每个 data URI 抽成独立图片(WeKnora `MarkdownImageBase64` 同款),正文里换成图片引用 —— **顺带修掉 Word 占位符**;pptx 的 WMF / EMF 先栅格化。
- **过滤(所有格式同一套,按顺序)**:任一边 < 80 px;PDF 里占页面 < 1%;压缩后 < 10 KB;同一份文档里出现在 ≥ 3 页(或 docx 里 ≥ 3 次引用 / 在页眉页脚);同一租户 ≥ 3 份文档出现(按像素哈希);每份最多 50 张(按面积从大到小保留),被截掉的数量记进逐页记录、管理端可见。
- **小图不抄字**:短边 < 400 px 的图只要描述、不要图中文字(§4.1:所有模型在低清小图上都会编字)。
- **描述**:一次看图调用「先观察再描述」(WeKnora smartocr 的属性表思路,厂商中立):返回 `含文字:无 / 少 / 大段`、`是否图表`、一两句描述。大段文字或图表 → 再走一次 OCR(§5.3 的模型)拿图中文字;图表用「图表转数据」写法(标题 / 轴 / 图例 / 数据点),其他逐字抄。提示词系统固定,用文档的语言写,不翻译、不臆测。
- **落位**:在原图位置插入一段引用块,例:`> 〔图〕<描述>` + `> 〔图中文字〕<OCR 文字>`;原图存对象存储(`expert_work.runtime.storage`,与工作区同一套),引用块里带图片 id,分段预览和检索测试能显示原图。不给模型看图片本身(检索结果里只有文字)。
- **矢量图表 / 流程图**:不是图片对象,本期不处理;后续可按「页内矢量路径密度」判整页渲染后描述(记入 §11)。

### 5.5 缓存与重跑

- 缓存键 `sha256(送模型的图片字节) + 模型 + 提示词版本 + 渲染参数`,值为清洗后的结果;**按租户隔离**(⑩;共享缓存会暴露「别的租户上传过同一页」,代价是两个租户传同一份资料各付一次)。
- B-206 批 2 重新切分、同一文件重传、补识别都先查缓存,**同一页不重复付费**。
- 表:`knowledge_parse_cache(tenant_id, key, kind = page_ocr | figure_desc | figure_ocr, model, result, created_at)`(B-175 设计 §3 已预留此表名)。

### 5.6 状态与「不允许静默空页」

- 逐页记录(新表 `knowledge_document_page`,或文档上的 JSON 列,实现时按数据量定):页码、判定(文字 / 识别 / 空白)、原因、识别模型、成败、字数、图片数(提取 / 过滤后 / 描述)。

- **识别模型没配 / 厂商不可用**:不跳过 —— 扫描页记为「待识别」,文档带「N 页待识别」标记;配好后一键「补识别」只处理这些页(走缓存)。
- 整份全是扫描且全部失败:沿用 `parse_failed`,错误信息写明失败页数与原因。

## 7. 厂商中立

- 能力写在模型目录(`ocr_caps`、`vision`),换厂商不改代码;两种接口形状各一个适配(`layout_parsing` / `chat_vlm`),目录里新增其它厂商的识别模型只加条目。
- 降级顺序:主识别模型 → 兜底模型 → 该页标失败(可补识别)。本期不做本机 CPU OCR(RapidOCR / PP-OCR)这一档 —— 中文质量明显低一档(OmniDocBench 约 86~87 vs 95),等真有「完全不能调外部模型」的部署再加。

## 8. 不做(带理由)

| 不做 | 理由 |
|---|---|
| 单独上传的图片文件 | 用户 10-21 拍板 |
| 按页计费的解析服务(DocMind / 百度) | 用户 10-21 拍板;贵 10~40 倍,提示词与重试不可控 |
| 以图搜页(ColPali / 多模态向量) | pgvector 无 MaxSim、RDS 无 VectorChord;中文无证据(§3) |
| 自建 GPU 跑开源识别模型 | 量小,包月显卡闲置成本远高于托管调用(约 ¥3,200 / 月 vs 本批 ¥3) |
| 删除纯数字行等「清洗」 | WeKnora 的坑,化验单 / 报表会丢数 |
| 手写签名识别 / 遮挡 | 模型会编名字,不可靠;靠逐页视图人工核 |
