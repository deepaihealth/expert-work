# B-314-00 Dify「健管师」迁移到 Expert Work —— 总览

> 状态:草稿 v1,与 01~08 一起逐个过。本文件是这次迁移的唯一总图:模块清单、已拍板、待拍板、先后顺序都以这里为准,各模块细节看对应文档。

## 0. 一句话

把深护智康在 Dify 上的「健管师」智能体(企微里给客户做健康管理的 AI 健管师)迁到 Expert Work:业务流程不变(客户在企微发消息 → 智能体回复 → 员工企微号发给客户),内部换成「一个智能体 + 深护 MCP 工具 + 知识库」,同时补上长期记忆,并把人机混合(AI 关闭期间真人接手)做成平台原生能力。

## 1. 现在是怎么跑的

```
客户企微消息
  → 深护数字人服务(攒几秒、各道开关、同一客户一把锁、新消息打断旧轮)
  → 深护项目服务 → Dify「健管师」(127 个节点、17 个大模型节点)
       ├ 每轮拉企微最近 30 条聊天
       ├ 并行预取客户档案 / 健康方案 / 表单
       ├ 意图判断 → 提醒增删 / 天气快递 / 课程与推广固定话术
       ├ 改档案、上报健康数据、化验单(写表单)
       └ 健管师大模型输出 {answer, attachments}
  → Dify 反过来回调数字人服务 /receive-answer
  → 员工企微号发给客户(文字 + 运动视频)
```

Dify 里没有知识库(资料写在环境变量里),也没有用 Dify 自己的对话记忆(上下文全靠每轮拉最近 30 条)。

## 2. 迁移后怎么跑

```
客户企微消息
  → 数字人服务(攒消息、开关、锁、打断 —— 原样保留)
  → 项目服务调 Expert Work(本轮客户消息 + 身份;03 落地后再带上数字人服务查出的「会话里还没有的消息」)
  → Expert Work「健管师」智能体(user_id = wx:{项目}:cus:{客户编号};会话 = 客户 + 智能体,私聊和各群共用,空闲 N 小时换新)
       ├ 会话本身保存 AI 参与过的对话;不再每轮拉企微历史
       ├ (03,最后做)平台先把补来的消息写进会话,模型看到完整时间线
       ├ 长期记忆(B-300)按客户召回
       ├ 调深护 MCP:查档案 / 方案 / 表单,写表单,提醒增查删
       ├ 调平台高德 MCP:天气
       ├ 查知识库「公司与服务」
       └ 按固定格式输出:几条文字 + 视频编号 + 是否附带固定话术
  → 项目服务取回最终回复,视频编号换链接、话术标记换原文 → 数字人服务按现有方式发出
```

## 3. 威胁模型(所有安全相关设计的判据)

- **防**:客户在企微里诱导智能体查 / 写别的客户的数据;同一笔写操作被执行两次;深护接口被未授权访问;密钥与客户隐私外泄到日志、文件。
- **不防**:Expert Work 与深护的系统管理员、员工(可信)。
- 超出这个范围的风险,在各文档里只列出、不做。

## 7. 先后顺序(粗)

0. **v0(明天交测试,做基础测试)**:智能体本身(提示词、模型、输出格式、长期记忆)+ 深护 MCP 现有只读工具(查字段结构、查最新值、按时间查提交,身份参数照样平台绑定)+ 平台高德天气 + 「公司与服务」知识库草稿。写工具(提醒、表单)与企微端到端随后。
1. 并行可做:B-300 上生产(进行中);04 深护 MCP 新工具;08 安全整改的必做项(其中 pad 竞态修复从 03 里单独提前);05 知识库源文件整理;07 的取样授权、脱敏、评测脚本,深护调用记录先加「正常完成 / 耗时」攒 Dify 基线。
2. 依赖上面:01 / 02 业务方改造(要 04 的工具定义)、06 智能体配置定稿。
3. 07:测试环境对比测 → 影子运行 → 按员工逐步切换 → Dify 下线。
4. 最后:03 人机混合(补消息、未送达、消息时间;平台 PR-1~3 + 深护 S-1~S-12)。
