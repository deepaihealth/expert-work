## 0. 一句话

把深护智康在 Dify 上的「健管师」智能体(企微里给客户做健康管理的 AI 健管师)迁到 Expert Work:业务流程不变(客户在企微发消息 → 智能体回复 → 员工企微号发给客户),内部换成「一个智能体 + 深护 MCP 工具 + 知识库」,同时补上长期记忆,并把人机混合(AI 关闭期间真人接手)做成平台原生能力。

## 1. 现在是怎么跑的

```
客户企微消息
  → 深护数字人服务(攒几秒、各道开关、同一客户一把锁、新消息打断旧轮)
  → 深护项目服务 → Dify「健管师」(127 个节点、17 个大模型节点)
       ├ 每轮拉企微最近 30 条聊天
       ├ 并行预取客户档案 / 健康方案 / 表单
       ├ 意图判断 → 提醒增删 / 天气快递 / 课程与推广固定话术
       ├ 改档案、上报健康数据、化验单(写表单)
       └ 健管师大模型输出 {answer, attachments}
  → Dify 反过来回调数字人服务 /receive-answer
  → 员工企微号发给客户(文字 + 运动视频)
```

Dify 里没有知识库(资料写在环境变量里),也没有用 Dify 自己的对话记忆(上下文全靠每轮拉最近 30 条)。

## 2. 迁移后怎么跑

```
客户企微消息
  → 数字人服务(攒消息、开关、锁、打断 —— 原样保留)
  → 项目服务调 Expert Work(本轮客户消息 + 身份 + 本批消息 id;03 落地后再带上数字人服务查出的「会话里还没有的消息」)
  → Expert Work「健管师」智能体(user_id = wx:{项目}:cus:{客户编号};会话 = 客户 + 智能体,私聊和各群共用,始终一段不换新;每轮时限 300 秒)
       ├ 会话本身保存 AI 参与过的对话;不再每轮拉企微历史
       ├ (03,最后做)平台先把补来的消息写进会话,模型看到完整时间线
       ├ 长期记忆(B-300)按客户召回
       ├ 调深护 MCP:需要时一次取齐客户资料(档案 / 方案摘要 / 今日饮食 / 现有提醒),查 / 写表单,提醒增查删,查更早聊天
       ├ 需要同事接手时调深护 MCP 转人工:MCP 直接通知同事,按配置决定本轮回不回、之后还回不回
       ├ 调平台高德 MCP:天气
       ├ 查知识库「公司与服务」
       ├ 客户明确要视频时调深护 MCP 素材清单,挑最多 3 个
       └ 按固定格式输出:几条文字(课程 / 方案推广话术按原文写在里面)+ 素材 id
  → 项目服务取回最终回复,素材 id 查深护智能体素材表校验、按类型取链接(失败时拼兜底话术)→ 数字人服务按现有方式发出
```

## 3. 威胁模型(所有安全相关设计的判据)

- **防**:客户在企微里诱导智能体查 / 写别的客户的数据;同一笔写操作被执行两次;深护 MCP 被未授权访问;迁移新代码把密钥与客户隐私外泄到日志、文件。深护存量接口与日志的问题(调试豁免头等)不属于 B-314,列在 08 的深护安全待办。
- **不防**:Expert Work 与深护的系统管理员、员工(可信)。
- 超出这个范围的风险,在各文档里只列出、不做。
