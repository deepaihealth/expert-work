## 0. 一页看懂

**问题**:对接方每一轮通过变量 `attachment_urls` 把客户发来文件的原始链接传给平台,但**只有那一轮有**。智能体按规矩要先问客户「这份报告是您的吗」,等客户下一轮确认了才写表单 —— 到那时 `attachment_urls` 已经没了,而且这个链接本来就从没出现在模型看得到的文字里。结果表单里的附件栏是空的。

**做法**(一个 PR,约 3 人天):

| 步 | 做什么 |
|---|---|
| ① 记住 | 每一轮开头,平台把这一轮模板变量里出现的每个 `http` / `https` 链接(不管变量叫什么、在列表还是对象里多深)记进**这段对话自己的链接登记**,每条一个编号,形如 `expert_work://link/3f9a1c2e-1`(前 8 位取自对话 id,后面是本对话里的顺序号),记下哪个变量第几项、什么时候收到、扩展名、同一轮还收到了哪些上传文件。原链接只存在对话的检查点里 |
| ② 告诉模型 | 登记不空、且智能体有 MCP 工具时,每一步在平台段里加一小段「本对话收到的链接」:**最近 10 条**的编号和上面那些事实,**没有链接本身** |
| ③ 发出前换回 | 模型调 MCP 工具时,参数里任何位置、任何字段名,只要某个值**整段等于**本对话登记里的一个编号,平台在**派发前的最后一步**(审批门之后)换成原链接。编号不是本对话的、不存在、或拼在一句话里 → 这一条不发,返回一条看得懂的工具错误 |
| ④ 结果遮回 | MCP 工具的返回里出现登记过的链接(原样、JSON 转义、百分号编码几种写法),在截断和交给模型之前换回编号;轨迹里记的也是编号版的参数和遮过的结果 |

**这次事故会怎样**:第 1 轮记下 `…/3f9a1c2e-1`(`attachment_urls` 第 1 项,`.pdf`,同一轮还收到文件 `uploads/attachment-9.pdf`);第 2 轮客户确认后,模型在 `fields[].value` 里写这个编号,表单服务收到的是对接方原来那条链接(含签名参数,一字不差)。测试环境已证实深护的表单服务收 `fields[].value` 里的链接(§1.2 第 27 条)。

**用户会感觉到的变化**:

| 项 | 变化 |
|---|---|
| 对接方 | 接口不用改。**建议**深护健管师智能体去掉 `attachments ← attachment_urls` 这条绑定,同一轮和之后的轮次都由模型写编号,免得同一个附件写两遍(§4.5;这是智能体配置的改动,按规矩不由我们自动改,§8 第 14 条) |
| 等待 | 每轮开头多一次纯内存计算,无网络调用;不可感知 |
| 费用 | 有链接的对话,每次模型调用多约 30~40 token / 条,最多显示 10 条,封顶约 400 token(这段在提示词尾部,不进前缀缓存) |
| 数据去向 | 原链接只多存一份在对话检查点里(它本来就在本轮的 `system_prompt` 帧和排队输入里);只发给模型调用的那个 MCP 服务。**不进**审批单、审批帧、动作筛查判官、轨迹(Langfuse)、日志、指标 —— 这些地方都只见编号(§4.7) |
| 开关 | 不加配置项。对所有声明了模板变量的智能体生效;模型不写编号就什么都不发生 |

**不做的**:平台自己签链接;方案 (a);`http` 工具不换(参数里出现编号直接拒绝,§4.4);沙箱代码不换;「抄得接近的原链接」本版只计数、不拦;平台不检查链接还能不能打开。

## 1. 背景

### 1.1 事故经过(11-20,测试环境,协调人提供)

1. 客户在企业微信里给健管师发了一份 PDF。
2. 对接方(深护)从自己的 OSS 下载这个文件,用 `POST /v1/agents/{code}/uploads` 上传给平台,文件名 `attachment-9.pdf`;平台存为 `uploads/attachment-9.pdf`,这一轮的用户消息里留下一行 `[file attached: uploads/attachment-9.pdf]`。
3. 同一轮,对接方在模板变量 `attachment_urls` 里传了原 OSS 链接(一个只含 1 条链接的 JSON 数组)。
4. 智能体按提示词先问「这份报告是您的吗」,这一轮没有写表单。
5. 下一轮客户确认。智能体调 MCP 工具 `form_save_customer_values`,在 `fields[]` 里给字段 `field_PE_report_attachment`(上传类字段,值是一个链接)填值。这一轮对接方没有传 `attachment_urls`;链接也从没出现在模型看得到的文字里。**附件栏最后是空的。**
6. 另一次同一轮就要写表单的看图案例里,模型是违反提示词、用 `exec_python` 读 `inputs.json` 才拿到链接的。

同类的事以前也出过:健管师 154 轮里有一次把字面量 `$attachment_urls` 直接写进了 MCP 表单工具的参数,对方服务收到的就是这串字(`input_literal_guard.py:3-5` 的注释记着)。

### 1.3 为什么现有机制接不住

- **绑定**只认顶层参数、只认本轮;而且被绑参数从 schema 里去掉了,之后的轮次模型想用也用不了(事实 8)。这次要填的是 `fields[]` 某一项的 `value`(嵌套)、而且是下一轮。按字段名配置的扩展管不住第三方字段名(前提 2)。
- **「本轮输入」段**零值、只说本轮(事实 10)。
- **让模型看到链接自己抄**:手抄必错;用户也要求链接不进上下文。

## 2. 目标与不做

### 2.1 目标

1. 对话里任何一轮通过模板变量收到的链接,之后任何一轮都能被模型交给 MCP 工具,对方收到对接方的原链接,一字不差。**B-330 是跨轮次交链接的唯一机制**;同一轮也走它。
2. 原链接不出现在模型看到的文字(平台写的部分)、工具结果、轨迹、日志、指标里。
3. 不依赖变量名、字段名、工具名;对接方接口不改;不加配置项。
4. 编号只在本租户、本对话里有效;别的对话的编号被带进来会被拒绝,不会悄悄换成本对话的另一个附件。

### 2.2 不做(各一句)

- 平台签链接、方案 (a):用户定了以后做(§4.10)。
- `http` 工具:出网白名单为空时就是公网(#994 起是黑名单模式),被注入诱导就能把链接 POST 出去;`url` 参数换成真链接还会让平台自己去下载对接方的文件。本版不换,出现编号直接拒绝。
- 沙箱代码不换编号:代码要文件就用预下载的输入文件或上传文件。
- 抄得接近的原链接不拦,只计数(§4.4):现有近似判定对「同一目录下的兄弟链接」会误拦。
- 不检查链接能否打开。
- 不处理租户模板自己把链接渲染进系统提示词的情况(事实 11,§4.7 例外)。

## 3. 业界做法

来源是 11-20 的调研笔记。「调研标注」一栏照调研笔记自己的标注写:「已核实」= 调研时打开过原文或源码;「转述」= 取自二手说明。下表各行调研时都已核实;调研里标「转述」的只有 Salesforce Agentforce(`ContentDocumentId`)与 Coze 云版 7 天留存两条,本设计没用到。

| 产品 | 做法 | 对本设计的启发 | 调研标注 |
|---|---|---|---|
| ChatGPT GPT Actions `openaiFileIdRefs` | 动作的参数声明成文件引用;模型只写文件 id,平台填成 `{name, id, mime_type, download_link}` 发出,链接 5 分钟有效。<https://platform.openai.com/docs/actions/sending-files> | 「模型写引用、平台填真值」是主流做法;但它要求工具声明哪个参数是文件,我们管不了第三方 schema | 已核实 |
| OpenAI Apps SDK `_meta["openai/fileParams"]` | 同上思路,由工具元数据标出文件参数 | 同上 | 已核实 |
| Anthropic Files API / MCP connector | 文件以 `file_id` 引用;文档明说「不要接受终端用户给的 file_id」 | 引用必须按归属校验:编号只认本对话登记里的(§2.1 第 4 条、§4.4) | 已核实 |
| MCP SEP-2356 草案 `io.modelcontextprotocol/files` | 参数用 `x-mcp-file` 标出,客户端负责填,「字节和上传地址都没进入它的上下文」 | 方向与我们一致;草案未定、第三方服务器也没实现,不能指望 | 已核实(连同 MCP 规范 2025-11-25 的 tools 一节) |
| Langdock MCP 文件输入 | 模型写文件名 / 路径,平台在发出前拦下并替换。<https://docs.langdock.com/en/using-langdock/guides/integrations/mcp/mcp-file-input> | 最接近本设计的「发出前按模型写的引用替换」;我们换的是编号而不是文件名(文件名可能重名、也可能本来就是要发的文字) | 已核实 |
| Coze Studio `x-assist-type` + `AssembleFileURIToURL` | 按参数类型把平台文件 URI 转成 URL;`http(s)` 的值原样放过、不检查 | **反例**:原样放过等于模型抄什么就发什么 | 已核实(源码 `backend/domain/plugin/service/tool/invocation_args.go`) |
| Dify | 文件 `transfer_method=remote_url` 保留原链接;`message_files` 跨轮保留文件;Agent 模式会去掉 FILE 类参数 | 「原链接跨轮保留」是常见需求;Dify 的 Agent 模式自己也没解决 | 已核实(源码,2025-04 的 `f6305858a5`,较旧) |
| FastGPT | 每轮把 `<file><name><url>` 列给模型,让模型自己抄链接 | 唯一这样做的;正是我们要避免的(长串手抄、链接进上下文) | 已核实(源码 `3fa17bea0`) |
| openclaw | 记录里写 `[media attached: media://inbound/<id> (mime) \| 原始url "名"]`,来源留在对话记录里 | 「平台给媒体一个短的内部地址」与我们的编号同一思路;它把原链接也写进了记录,我们不写 | 已核实 |
| LibreChat / open-webui / LangChain `ToolRuntime` | 平台侧注入的值模型看不到(用户身份、令牌之类) | 与 B-61 绑定同一类 | 已核实 |
| Copilot Studio | 文件输入不能「由 AI 动态填写」,只能确定性绑定 | 与我们「编号 → 原链接由平台换」一致:值由平台给,模型只选哪一个 | 已核实(learn.microsoft.com,pass-files-to-connectors) |

**结论**:主流是「模型写一个平台引用,平台在发出前换成真值」,而且引用要按归属校验。各家都靠工具 schema 标出哪个参数是文件;我们不能要求第三方改 schema,所以改成**按值认**:任何位置的值整段等于编号就换。这比按参数标注宽,所以 §4.8 专门分析误换和被利用的可能,并把范围收到 MCP。

### 4.2 每一轮开头怎么记

**谁来记**:新加一个开头节点 `link_registry`,纯计算、不碰沙箱,挂在 inputs 节点同一位置(`builder.py:2573-2576`)。门:智能体声明了模板变量(不要求接沙箱 —— 只有 MCP 的智能体也要能用,事实 5)。委派子 run 跳过(用父经 config 传下来的登记)。

**怎么找链接**:**新写一个遍历,不复用** `_walk` / `linked_sites` / `candidates_from_inputs` —— 它们跳过列表里的裸字符串,正是事故形状(事实 6)。只复用两个判定函数:

- 字符串:先按 `parse_json_value` 试着解析(B-314 的对接方客户端把 inputs 当 `Record<string, string>` 传,`attachment_urls` 很可能是 JSON 数组**字符串**,`04-mcp-tools.md:507`);能解析按解析结果走。
- 列表、对象:逐层往下,有递归上限(超了跳过这个变量)。对象里叫 `local_path` 的键跳过(`inputs_doc.py:422-429` 同一理由)。
- 叶子:`http_url_in` 拿到的、且 `urlparse` 的 `netloc` 不为空的才算(第 4 版,代码审查 M1:`https://` 这种空壳登记进来,结果里所有链接的开头都会被遮成编号)。查询串原样保留,不规范化、不解码。
- 顺序号取已有登记里最大的顺序号 + 1,不取条数 + 1(第 4 版:读检查点时清洗掉的坏条目会让条数变少,条数 + 1 会和一条还在的编号撞上)。

**每条记什么**:

| 字段 | 内容 | 给谁看 |
|---|---|---|
| `id` | `expert_work://link/<对话 id 前 8 位>-<顺序号>` | 模型 |
| `url` | 原链接 | **只在平台这边** |
| `variable` / `where` | 变量名;整个值 / 第几项 / 某个字段(键名是租户数据,不写,同 `inputs_block.py:63-66`) | 模型 |
| `ext` | 链接路径最后一段的扩展名(`[A-Za-z0-9]{1,5}`);untrusted 变量不写(P16) | 模型 |
| `received_at` | 第一次收到的时间,按平台时区写成「11-20 14:05」(事实 29) | 模型 |
| `run_id` | 第一次收到那一轮的首个 run | 平台 |
| `turn_files` | 同一轮还收到的上传文件名(`turn_documents`)与图片张数 | 模型(只是事实,不说「这就是那个文件」) |

**去重**:链接原文完全相等就是同一条,保留第一次的记录。对接方重新签名的同一个文件是另一条链接、另一个编号。

**上限**(代码常量):每对话 200 条,满了新来的不登记、不挤掉旧的(旧编号可能已写在历史里),平台段说一句「已满 200 条,之后的没有编号」;每轮新登记最多 64 条;单条长度本来就被单值上限卡住(事实 4)。

**编号为什么带对话 id 前缀**(审查 M2):编号可能被长期记忆、智能体笔记、智能体根目录里的文件带进**另一段对话**。纯顺序号 `link/1` 在 B 对话里会悄悄换成 B 的第 1 个附件 —— 写错附件、还不报错,是最坏的错误。带上前缀后,别的对话的编号在这里不在登记里,一律拒绝。前缀取对话 id(随机 UUID)的前 8 位十六进制:够短、好抄;同一租户两段对话前缀相同的概率约四十亿分之一,即使撞上也还要顺序号也落在登记里才会错。**前缀从哪来**(复审 N4):取**根对话**的 id,即 `ctx.workspace_thread_id or ctx.thread_id`(`tools/_child_run.py:1033-1035` 同一取法),由开头节点在根对话里生成编号时写进每条登记;子代、孙代只拿种进来的登记,**绝不**用子 run 自己新建的 `sub_thread_id`(`_child_run.py:240`)。判定「别的对话的编号」(`foreign`)的唯一依据是**不在本对话的登记里**,而不是「前缀 ≠ 自己的 thread id」—— 后者在子代里会把父对话的合法编号误判成外来的。错误文字区分两种情况只为说得清楚:前缀与登记里的前缀不同 → 说「不是本对话的」;前缀相同、序号不在 → 说「没有这个编号」;两种都不发。

### 4.3 告诉模型:平台段里的一小段

**位置**:`_append_tail_human_message` 加一段尾部文字,随 B-162 合进 `<platform-context>`(事实 23),每一步按登记重新生成 —— 压缩丢不了,子代也有。

**什么时候出现**:登记不空,**且**这个智能体(或子代)有 MCP 工具。

**显示多少**(审查 M7):**最近收到的 10 条**;更早的写一行「另有 N 条更早的链接,编号仍然有效」。少列既省钱,也减少模型在无关的轮次里顺手把旧附件挂上去。

**样子**(示意;措辞开发时按 B-317「只陈述事实」再定):

```
[本对话收到的链接]（平台自动生成；链接地址由平台保管，这里只有编号）
MCP 工具的参数值整段是下面某个编号时，平台在发出前把它换成原链接；编号对客户没有意义，回复里写了客户也打不开。
- expert_work://link/3f9a1c2e-1：attachment_urls 第 1 项，.pdf，11-20 14:05 收到；同一轮还收到文件 uploads/attachment-9.pdf
```

第二行是平台行为的事实陈述,不是命令;后半句针对「模型把编号写进给客户的回复」(审查 L8)。

**前缀缓存**:这段在提示词视图最末尾,下一步就挪走(`platform_context.py:22-23`),从不在被缓存的前缀里。仍让它对同一份登记逐字节稳定,便于排查。

### 4.4 发出前换回

**在哪一步**(审查 L3、L5 后改为**审批门之后**,§8 第 5 条):`tools_node` 里所有守卫都过完、就要派发的那一刻,对要派发的每个 MCP 调用换一次。审批续跑走同一处。好处:

- 只有一处,不碰绑定填参(`builder.py:1957`、`:2078` 不动),RT-6 的审批摘要算的是编号版参数,前后自然一致;
- 原链接不进审批单、审批帧(事实 20)、动作筛查判官(事实 21),只进真正发出的那一次调用;
- 仍早于参数 schema 校验(事实 17):对方 schema 若要求 `format: uri`,校验的是真链接。

代价:审批人在审批卡上看到的是编号,不是原链接。审批写表单时人关心的是字段和数值,链接本来就是对接方自己给的。复审 N5 建议在审批卡上编号旁边显示平台段那一行说明(变量名、第几项、扩展名、收到时间、同一轮的上传文件名,不含链接):审批卡的文字来自 `_action_summary`(`_approval.py:151-162`),它同时是审批单稳定 id 的哈希输入(`:127-135`)和老裁定的核对依据,而它现在只拿得到这一条调用、拿不到登记 —— 要改三处函数签名,碰的是 RT-6 那一块。所以本版不做,列为 §8 第 5 条的可选项。

**只对 MCP 工具换**(审查 M3)。`http` 工具和平台自己的工具都不换。

**怎么换**(纯函数:参数 + 登记 → 新参数、换了哪几个编号、错误):

1. 复制参数,不改 AIMessage 身上那份(`arg_bindings.py:302-306` 同一规矩)。
2. 走遍所有字符串叶子(**字典的键也算**,第 4 版),不管字段名和深度:
   - 去掉首尾空白后整段等于一个编号形态 `expert_work://link/…`:在本对话登记里 → 换成原链接;不在 → 错误。
   - 以 `[` / `{` 开头、能解析成 JSON 的字符串:在解析结果里同样找,换完再序列化回去(`ensure_ascii=False`),只往里走这一层。
   - 字符串里**含有**编号但不是整段相等(「附件见 …」、`"…-1;…-2"`):错误 ——「一个值只能是一个编号」。
3. 平台绑定填的参数、固定值参数不参与(它们是平台的值)。

**拒绝**(审查 L4,复审 N1 改):编号的检查**放在审批门之前**(检测路径),但**不改审批目标的挑选**:续跑时 `apply_resume_decision` / `_approved_target` 会对检查点里整批调用重新跑 `find_approval_target`(`graph_builder/_approval.py:416`、`:488`、`:528`),绑定摘要要求两次选中同一条(`:180-188`)。如果检测时跳过坏调用去挂后面那条,续跑会重新选中坏的那条 → 摘要漂移被否决,或者批错调用。所以做法是:检测路径发现本批有任何编号错误,**这一步不挂任何审批** —— 坏的那条得到错误结果,本批其它调用得到现成的「没有执行」结果(与动作筛查 block 同一做法,`builder.py:2117-2141`),模型重新发起。下一步重发的整批不再带坏编号,审批照常挂、目标照常选。审批续跑时(人用「修改」改了参数)再检查一次,命中计入现有的「批准后被拦」计数。拒绝与字面量守卫同一形状(`builder.py:4450-4495`):不派发、合成错误工具结果、审计 `TOOL_BLOCKED`(原因 `link_id_unknown` / `link_id_foreign` / `link_id_embedded` / `link_id_http`,details 只有编号),并加进不进文件账和 `ran_calls` 的那组条件(事实 15)。三处检查与换回用同一个纯函数。

错误文字(都不含链接):

- 不在登记里:「这个编号不是本对话收到的链接」+ 本对话最近 10 条的说明;登记为空时说「本对话没有收到过链接」。
- 拼在长串里:「一个值只能是一个编号;要传多个链接,请写成数组、每项一个编号,参数只收一个字符串时一次只传一个」(审查 L6:`attachments` 这类参数收「;」拼接的串,不能拼编号)。
- `http` 工具里出现编号:「编号只在 MCP 工具里会被换成链接,http 工具收到的就是这串字」。

**模型自己写了原链接**(审查 M4):原文与登记一致 → 放行(发出去的就是对的),计数;**抄得接近的不拦,只计数**(用 `find_retyped_url` 的判定,候选从登记构造,不从 inputs 构造 —— 审查 L2)。现有近似规则允许最多 3 个字符的差(事实 13),同一目录下的兄弟链接、MCP 结果里别的链接、人审批时改过的值都可能被误判;等上线后看计数再定拦不拦。

**审计与轨迹**(审查 M1):审计 details 加 `rewritten_links`(只有编号)。轨迹 span 记**模型写的那份参数**(编号版),不是换回后的:`_dispatch_tool` 多收一个「记录用参数」,`_record_tool_io`(`builder.py:4106`)用它。

### 4.5 与 B-314 `attachments ← attachment_urls` 绑定的关系(审查 H1)

- 这条绑定只在同一轮有值;之后的轮次参数被删、又不在 schema 里,模型用不了(事实 8)。所以**跨轮次只能靠 B-330**;已证实深护服务收 `fields[].value` 里的链接(事实 27),模型按表单的上传类字段写编号即可。
- 绑定留着的话,同一轮里平台把链接填进 `attachments`,模型又可能把编号写进 `fields[]` 的上传字段:服务端会把 `attachments` 并进**第一个**上传字段并去重(`04-mcp-tools.md:276`),但 `fields[].value` 与 `attachments` 在同一次调用里会不会去重、写进的是不是同一个字段,没核实(§10)。
- **推荐**:深护健管师智能体去掉 `attachments ← attachment_urls` 这条绑定(`04-mcp-tools.md:796-800` 那份配置),同一轮也让模型写编号,只有一条路。这是**现有智能体配置的改动**,按项目规矩不由我们自动修改,列在 §7「需要改的智能体配置」与 §8 第 14 条,由用户决定、对接方确认。
- 平台这边对绑定**不做任何特殊处理**:绑定参数照旧填、不参与换回。留着绑定也能工作,只是可能重复。

### 4.6 工具结果里的原链接:换回编号(审查 M5)

**在哪**:`McpTool.call` 里,拿到服务端结果后、`_middle_trim` 截断**之前**(`tools/mcp.py:1438-1439`),对完整内容做。截断之前做,半条链接就不会因为截断边界漏出去;`full_content`(溢出写进工作区的那份)和 span 记的结果也随之是遮过的。登记通过 `ToolContext.conversation_links` 传进来(委派往下传也读这个字段)。

**认哪几种写法**(第 4 版补齐):原样与「服务端把百分号解码后回显」的那份,各自再按下面几种变换(可以叠加):

1. JSON 转义:`json.dumps(url)[1:-1]`,`ensure_ascii` 真假两种(中文路径会变成 `\uXXXX`);
2. `&` 写成 `\u0026`(Go `encoding/json` 的默认)或 `&amp;`(HTML 片段,复审 N4);
3. 斜杠转义 `\/`(一些 JSON 序列化器默认这样写);
4. 百分号编码:`quote(url, safe="")`、`quote(url)`,以及 `encodeURIComponent` 的写法(`!'()*~` 不转义);
5. 百分号编码的十六进制位大小写不限(文字和写法都先归一成小写,长度不变)。

**怎么找**(第 4 版,代码审查 M2:原来把所有写法拼成一个大正则,200 条链接编译 3 秒、峰值上百 MB,还常驻在 `re` 的全局缓存里):先按主机名做子串预筛(主机名在原样、JSON 转义、`\/`、`quote(safe="")` 里都原样保留);只给命中的链接生成写法(按链接缓存,有上限),用 `str.find` 找。MCP 结果放到 `asyncio.to_thread` 里遮,不占事件循环。新模块 `tools/link_masking.py`。

**结尾边界**(第 4 版,代码审查 M1):找到的位置后面紧跟的还是链接的一部分(字母数字、`-_~/?#%=&+`,`.` 后接字母数字,`\/`、`\u0026`)就不算 —— `…/a.pdf` 不会把 `…/a.pdf.bak` 的开头遮掉,`https://shenhu.com` 不会把 `https://shenhu.com/docs/b.pdf` 遮坏;句末的 `.` `)` `,` 不挡。重叠的命中取长的。代价:一条更长的、以登记链接开头的链接整条不遮(它本来就不是同一个地址)。

**边界按写法分开判**(第 4 版复审):完全百分号编码的写法(`quote(safe="")`、`encodeURIComponent`、`quote(url)`)里不会有原样的 `& # = ? +`,它们出现就是外层的分隔符(`?src=<编码链接>&page=2`、`…#p2`),所以这几种写法只把字母数字和 `-_.~%` 当「还在链接里」(`encodeURIComponent` 另加 `!'()*`,`quote(url)` 另加 `/`);原样和 JSON 转义这类写法用上面那条规则。同一串字出现在几种写法里时按原样那种算。

**已知认不出的写法**(原样交给模型,对外文档里也写了):JSON 套两层转义、`ensure_ascii` 的非 ASCII 再套一层、HTML 数字实体(`&#38;`)、服务端只回显半截链接。另外两种因为和「更长的另一条链接」分不开,有意不遮:原样写法的链接后面紧跟 `&`(`?src=https://…/a.pdf?sig=x&page=2`),以及百分号编码的链接后面紧跟同样编码过的分隔符(`%26`、`%22`)。

只对 MCP 结果做;纯子串替换,没有模式匹配。

**出错路径也要遮**(复审 N3):MCP 服务报错时异常不经过 `McpTool.call` 的正常返回,而是在 `_invoke_tool` 里被 `_format_error(exc)` 写成工具结果(`builder.py:5150-5170`),错误摘要的前 200 字还会写进 span 状态(`_record_tool_error`,`:4028-4035`)。服务端的错误信息常常回显收到的参数(「链接无效:https://…」)。所以对 MCP 工具,`_format_error(exc)` 的文字先过同一个遮回函数,再生成工具结果和 span 状态。

| 本轮 `system_prompt` 帧、排队模式的 `enqueued_input` | 有(今天就有,不是本功能新增) |
| 模型看到的平台段、**MCP** 工具结果 | 没有 |
| 沙箱里的 `inputs/<run>/inputs.json` | 有(今天就有,不是本功能新增):接了沙箱的智能体用 `read_file` / `bash` / `exec_python` 读得到。所以「工具结果里没有原链接」只对 MCP 结果成立(第 4 版补) |
| SSE `updates` 帧、`run_event`、调试台原始视图、对接方事件流 | 没有:`conversation_links` 在 `sse._INTERNAL_STATE_KEYS` 里,发帧前剥掉(第 4 版,代码审查 C1:开头节点的写入原来会整份进 `updates` 帧) |
| 子代 / 孙代的检查点 | 没有(登记走 config,不进子代状态,见 §4.1;第 4 版,代码审查 M3) |
| 检查点里的 AIMessage 参数、SSE 工具调用帧 | 没有(是编号) |
| 审批单 `proposed_args`、审批帧、动作筛查判官 | 没有(换回在审批门之后) |
| 轨迹 span | 没有(记编号版参数、遮过的结果) |
| 日志、指标、审计 | 没有(只有编号与计数) |

**例外**(事实 11):如果**租户自己的系统提示词模板**引用了这个变量,而它是 `render: raw` 或只含裸链接的列表,原链接今天就会被渲染进系统提示词。这是租户模板的选择,本功能不改它;测试 T5 专门有一例:模板引用了变量时,平台**自己写的**部分(平台段、工具结果、错误文字)仍不含链接。对外文档写一句:不想让模型看到链接,就别在模板里引用这个变量。

### 4.8 安全

- **不新增 SSRF**:平台不请求这些链接;`http` 工具不换(否则 `url` 参数会让平台自己去下载)。
- **租户与对话隔离**:只查当前对话状态里的登记;别的对话的编号不在登记里就拒绝(§4.2)。T4 钉住。
- **提示注入**:文档、网页、工具结果里写着编号是无害的,换回只发生在本对话模型自己发出的 MCP 参数上。能被诱导把链接带去的地方只有这个智能体已配置的 MCP 服务;`http` 工具收到编号直接拒绝。今天同样的注入就能让模型把上下文里的报告全文发给这些服务,所以不是新的一类风险;多出来的「签名链接」能打开的也是同一份客户文件。拼进长串的编号不会被换,而是被拒。
- **untrusted 变量**里的链接照样登记(客户发来的东西才要记住),平台段不写扩展名(P16)。

### 4.9 沙箱代码工具与现有守卫提示(审查 M6)

- 沙箱代码里的编号不换、代码输出不遮;要文件就用预下载的输入文件或上传文件。
- **字面量守卫的两句提示要改**(`input_literal_guard.py:172-189`):今天对 MCP 参数里的本地路径说「请用绑定或原始链接」,对 `$变量名` 说「请写出要传的实际内容」—— 都会把模型往「去找原链接」上引。改为:这个变量在登记里有链接时,提示写对应的编号(列出编号,不列链接);没有时保持原句。
- **手抄守卫的提示不改**(`input_url_guard.py:248-262`):它只管沙箱代码,代码里要的是真文件或真地址,编号在沙箱里没用,改成编号反而会让代码坏掉。

### 4.10 以后接方案 (a)

换回函数的入参是「模型可写的引用 → 原值」对照表。本版表里只有编号;(a) 往里加「带来源链接的上传文件路径」。判定、拒绝、审计、结果遮回都复用。(a) 要另想的是:路径本身也可能是对方要的正文,是否「整段等于上传路径就换」要单独设计。

### 4.11 可观测性(审查 L9:并成三个计数)

| 名字 | 标签 | 含义 |
|---|---|---|
| `expert_work_link_registered_total` | `outcome=added\|dropped_cap\|dropped_depth` | 登记 |
| `expert_work_link_use_total` | `event=rewritten\|verbatim\|near_copy\|result_masked\|id_in_reply` | 换回、模型自己写原链接、抄得接近(只计数)、结果遮回、最终回复里出现编号(只计数,审查 L8) |
| `expert_work_link_refused_total` | `reason=unknown\|foreign\|embedded\|http\|empty` | 拒绝 |

日志:每轮开头一行(新增条数、总条数);拒绝一行(编号、原因、工具名)。上线后看:`refused{foreign}` 不为 0 → 编号确实被带进了别的对话;`near_copy` 不为 0 → 再决定拦不拦;`id_in_reply` 不为 0 → 再决定要不要在回复里自动替换(§8 第 15 条)。

### 4.12 失败与边界

| 情况 | 结果 |
|---|---|
| 对接方的链接过期 | 平台不知道;MCP 服务报错,模型照常看到。平台段写了收到时间 |
| 登记计算出异常 | 永不让 run 失败:跳过本轮登记、记异常类型(不记值) |
| 换回或检查出异常 | 这一条按「不派发 + 错误结果」处理,不原样发出编号 |
| 回滚到旧版本 | 旧代码不读这个通道,模型写的编号原样发出(与今天模型乱写一样坏,不更坏);再升级回来登记还在(T16) |
| 模型写「链接 1」而不是编号 | 不换;平台段写的是编号形态,上线后从对方报错里看 |
| 定时任务(trigger)跑出来的 run | 它在自己的临时线程里跑(`control_plane/trigger_delivery.py:1-10`),登记是空的:从对话里建的提醒用不了那段对话的链接。这是安全的一侧 —— 写了编号会被拒,错误文字说「本对话没有收到过链接」 |
| 一个上传字段要放多个附件 | `fields[].value` 只收字符串,一次只能放一个编号;多个附件要么分几项、要么分几次,服务端怎么合并未核实(§10) |

## 5. 否掉的做法

1. **提示词规则**:用户已否;模型也拿不到链接。
2. **让模型看到链接自己抄**(FastGPT):手抄必错;用户要求链接不进上下文。
3. **扩展绑定(嵌套路径 + 记住上一次)**:要按字段写配置,第三方字段名管不住;与「平台缺口先改默认,别设计成让人去配」相反。
4. **按字段类型自动填**(看到上传字段就填最近的附件):要懂第三方 schema;一轮两个文件就会静默选错。
5. **新建数据库表**:迁移 + 三条清除路径的删除联动 + 将来 RLS;本版不需要图之外查。
6. **每轮从 `system_prompt` 帧重算**:帧可能丢,丢了编号错位。
7. **纯顺序号编号**(第 1 版的做法):被记忆或文件带进别的对话会悄悄换成别的附件(审查 M2)。
8. **随机编号**:更长更难抄;带对话前缀的顺序号已经解决了跨对话问题。
9. **与绑定同一处换回(审批门之前)**(第 1 版的做法):原链接会进审批单、审批帧、判官,续跑还要在两处重换(审查 L3、L5)。
10. **`http` 工具也换**(第 1 版的做法):公网出口 + 平台自己下载(审查 M3)。
11. **抄得接近就拒绝**(第 1 版的做法):现有近似规则对兄弟链接误判(审查 M4)。
12. **平台签发自己的下载链接**:用户定了不在本版。

### 6.2 真栈验收(测试环境,合并并随测试发布之后)

- **用平台自己的测试智能体**,不碰任何客户对话:声明 `attachment_urls`(可选,JSON 数组)与 `note_url`(可选),接一个只把收到的参数原样记下的回显 MCP 服务,**工具名与 schema 照 B-314 的 `form_save_customer_values`**(`fields[]` 对象数组、上传字段收字符串)。测试环境有没有现成的回显服务未核实;没有就在测试命名空间里起一个最小的,用完删。不配 `attachments` 绑定(按 §8 第 14 条的推荐);另跑一遍配了绑定的,看重复。
- 用例:
  1. 事故形状两轮(第 1 轮带链接 + 上传文档,第 2 轮无变量,用户说「是我的,存进去」)→ 回显服务收到原链接;
  2. 同一轮带链接直接写;
  3. 第 3 轮再写一次更早的那条;
  4. 审批工具一次(审批卡上是编号,批准后收到原链接);
  5. 委派一次;
  6. 用户消息里写一个别的对话的编号 → 看到拒绝、模型改口;
  7. **反向回归**(审查 M7):有链接登记之后,隔几轮报一次血压(「今天血压 125/80」)→ 回显服务收到的 `fields[]` 里**没有**任何链接;连续 3 次无关上报都检查。
- 看:轨迹里的换回与拒绝计数;调试台原始请求和轨迹里搜不到原链接;日志搜不到。
- **费用**:7 个用例约 20 轮、约 60 次模型调用,每次约 8k 输入 token;测试智能体用 deepseek-flash 级别粗估 **¥1~3**,换 qwen4-max 粗估 ¥5~10。没有 `quote_id`,开跑前单独报价、批了再跑(§8 第 12 条)。

§4.11 的计数;B-314 测评脚本里「先确认、下一轮写附件」用例的附件栏非空率;无关上报里带链接的次数(应为 0)。
