# B-236 三层工作区:对话目录、开场复制、agent 记忆

日期:2026-10-30 · 状态:已拍板,随 B-236 一起发布

## 这份文档回答什么

- 一个对话里,模型写的文件落在哪、能看到哪些文件。
- 存量 agent 根下的模板 / 风格锚 / 脚本,在新对话里怎么还能按老路径用。
- agent 怎么「记住」跨对话的东西,记在哪,谁能改,改坏了怎么找回。

## 用户拍板(10-30)

| 项 | 决定 |
| --- | --- |
| 过渡期映射(compat:只读 bind + 截止日) | 整个删掉,改成开场复制 |
| 开场复制上限 | 每个对话合计 20 MB;超出的目录整个不复制,告诉模型它在 `/agent/<目录>/` |
| 记忆规矩的写法 | 写**类别**,不写关键词 |
| 版本保留 | 每个文件留最近 20 份(review 10 起:在每个 agent 自己的版本字节预算之内,见第三层) |
| 每个(用户, agent)的版本字节预算 | 100 MiB —— 用户 10-30 拍板 |
| 发布 | 与 B-236 同一次发布 |

## 第一层:每个对话一个 `/workspace`(B-236 原有,不变)

- 对话视图里 `/workspace` = `agents/<key>/threads/<conv>/work/`,`/agent` = agent 根。
- 老对话(发布前开的)仍是老视图:`/workspace` 与 `/agent` 是同一个目录。
- exec 脚本按 fd 挂载、`shared/` 只读、tmpfs 盖住、嵌套 user namespace —— 全部保留。
  删掉的只有过渡期目录那一段(`$4` 个数 + 名字、校验、只读 bind 循环),两份脚本仍逐字相同。

## 第二层:开场复制(取代过渡期映射)

**什么时候。** 对话第一次 run 开始时,图的入口节点 `conversation_seed`(与 `inputs` /
`workspace_ingest` 并列,agent 等它做完)。只在对话视图做;委派子代(`child_run`)不做。

**复制什么。** agent 根下已有的一级**目录**,跳过点开头的名字和保留名(`threads` `uploads`
`inputs` `.tool_results` `skills` `shared` `agents`)。根下的单个文件不复制。本对话 `work/`
里已有同名条目就不覆盖。

**怎么保证只复制一次。**

1. 按对话加锁(Postgres advisory lock,新 classid 8624,键 `{tenant}:{conv}`;不是按用户的
   写锁)。锁外先看一眼标记,锁内再看一次。
2. 标记 `threads/<conv>/.seeded` 在就什么都不做。
3. 每个目录先复制进 `threads/<conv>/.seed-tmp-<随机>/<目录>`,再改名进 `work/<目录>`,
   目标名已存在就不动。
4. 标记最后写。
5. 失败:不写标记、清掉临时目录、记日志(只记异常类型),run 照常;下一次 run 重试,
   已经搬进来的目录按「同名不覆盖」跳过。
6. run 被取消:等着复制的协程置停止标志,**仍持锁**等复制线程在下一个名字处停下再放锁
   (最多再写完手上那一个文件);停下按失败处理。选「持锁等停」而不是只靠停止标志:后者会在
   线程还在写时就放锁,下一个持锁者可能看到写到一半的临时目录。等的期间再来的取消一律吞掉
   接着等,但最多等 120 秒;真到上限记一条日志放锁,不让一个卡住的 NAS 把取消永远挡住。
   「等手上那个文件写完」是有意的,不改成立刻放手。

**标记被载荷删掉。** 标记在沙箱够得着的 `threads/<conv>/` 下。删了它,下一次 run 会再复制本对话
`work/` 里**没有**的目录。接受这一点,不把标记挪到沙箱外:再复制从不覆盖、单次仍受 20 MB 上限与
配额闸约束,载荷自己用 `cp` 也写得出同样多的字节;挪出去只换来更多要跟着清理的地方(清除用户、
留存作业)。标记里还有认「原样副本」用的复制清单(见下):载荷伪造或改它,影响的只是这个用户
自己这个对话的列表与快照段。

**配额。** 复制前先只量不读算出这次要复制多少字节,问用户的工作区配额(与上传同一道闸:
已用 + 这次 > 上限就拦)。拦下:一个目录都不复制,照样写标记(每个对话只问一次),状态里
`seed_quota_blocked` 置位,快照段写明是配额满了、去 `/agent/<目录>/` 用;复制了字节之后触发
一次配额重算。配额拦下时也写标记、之后不再复制,是有意的:每个对话只问一次,不会在之后某一轮
空间腾出来时突然多出一批目录。

**安全。** 宿主侧经 NAS store 自己的防穿越闸拿 agent 根的目录 fd,一路
`openat(O_RDONLY|O_DIRECTORY|O_NOFOLLOW)`;文件 `O_RDONLY|O_NOFOLLOW|O_NONBLOCK` 后 `fstat` 核对
是普通文件;符号链接、FIFO、设备、socket、编码不成 UTF-8 的名字跳过并计数;目标端在钉住的
目录 fd 上 `mkdirat` / `O_CREAT|O_EXCL|O_NOFOLLOW`。保留 mtime。

**上限(依据测试环境 2,079 个 agent 根的实测)。**

| 闸 | 值 | 实测 |
| --- | --- | --- |
| 总字节 | 20 MB(拍板) | p99 0.53 MB,最大 25.5 MB,只有 1 个根超过 |
| 条目数(文件 + 子目录) | 500 | 每根最多 77 个文件,p99 22 |
| 深度 | 12 层 | 最深 5 层 |
| 看过的名字数(量 + 复制两遍、全部目录) | 2000 | 两遍合计不到 200 |

先只 `lstat` 量一遍,放不下的目录整个跳过(不读它的字节);复制时再按同一组数守一次。跳过的
名字(符号链接、特殊文件、编码不成 UTF-8 的)同样占条目数,量过又放弃的目录同样算「看过」——
一个种满符号链接或塞满小文件的 agent 根不能让开场做无上限的 `lstat`。名字数到顶之后剩下的
目录不再看:目录项类型(读目录时一并拿到,不另发系统调用)是目录的记成「太大」。「太大」的目录名
在报告 / 状态 / 标记里最多记 20 个,再多只记个数(review 9:一个塞满几万个一级目录的 agent 根
不能让标记与内存跟着涨)。

**模型看到什么。** 工作区快照段里,原样未改的副本在本对话那一节只占一行(「unchanged copy of
/agent/<目录>/」),不占 30 行展开预算;改过的副本照常展开。超出上限没复制的目录在本对话那一节
末尾一行写明 `/agent/<目录>/`(名单存在状态 `seed_skipped_dirs` 里,不对外推送;最多记 20 个、
每个最多 120 字符)。这一行最多列 8 个目录、其余写「and N more」,名字截到 60 字符,控制字符与
换行转义成 `\xNN` —— 名字是沙箱起的,不能在块里另起一行。超过 20 个、只记了个数的那些(状态
`seed_skipped_more`,同样不对外推送)也算进「and N more」(review 10)。

**浏览列表不列原样未改的副本。** 文件列表(控制台 `/v1/workspace/files`、对外
`/v1/agents/{code}/workspace/files`、会话 `/v1/sessions/{id}/workspace/files`)默认剔掉开场复制
进对话、之后没被碰过的副本,也不列 `.seeded` 标记 —— 否则每个对话都带着 agent 全部文件的一份,
几十个对话就把 2000 条上限占满,真正的产出被截掉。**先剔再截** 2000 条。

判据(review 9,取代 review 8 只看时间的做法):复制时把**真正写进 `work/` 的每个文件**记进标记
的清单 —— `(work/ 相对路径, 大小, 写完之后的 ctime)`,ctime 取在保留 mtime 的 `utime` 之后;标记
照旧最后写。一个文件是原样副本,当且仅当它在清单里、且现在的大小与 `st_ctime_ns` 都与清单相同。
之后对它的任何写入、改权限、`touch` 都会让 ctime 对不上;ctime 由文件系统设(NFS 上是服务端),
用户态改不回去。

- 不在清单里的从不藏:复制失败之后模型自己写的(`reports/q3.md`)、改了名的(`mv customers
  clients`,新名字下的路径不在清单里)都照常列。
- 不跟 `/agent` 的现状比:源文件之后被改,老对话的副本照样不列;对话自己的产出被 `cp -a` 进
  `/agent`,对话里那份照样列。
- 标记的 mtime 不再用:把它的时间改到将来也藏不住任何东西。
- 清单受开场复制的 500 条目上限约束;标记读到 256 KiB 为止。没有标记、不是普通文件(FIFO)、超过
  上限、读不动、解析不了(含嵌套极深、`json` 抛 `RecursionError` 的 `[[[…`,review 10)—— 一律当
  没有清单,什么都不藏:认副本只为少列,出错的方向必须是多列。目录链的错误仍是 store 自己的异常
  类型,标记文件本身的错误不往外抛裸 `OSError`。
- 清单在沙箱够得着的地方:伪造它只影响这个用户自己这个对话的列表与快照段。

**列表怎么读清单(review 10)。** 遍历时只记下见到了标记的对话目录,不读;遍历完,只给**这次真走到
了 `work/` 下文件**的对话读标记(对话作用域的列表,标记在遍历之外,也按这条:先看走到了什么再读)。
对话目录名必须是规范写法的 UUID,载荷在 `threads/` 下随手建的假目录(`f00000`)里的标记不读。每份
清单只留这次走到的那些路径,不整份留在内存里;一次列表读标记的字节合计最多 4 MiB,超了之后的对话
按没有清单处理(多列,不多占内存)。目录链按 fd 走(`_open_scope_dir_fd`)。实测 400 个 256 KiB 的
假标记(100 MiB)下,一次用户根列表 0.2 秒、内存只涨约 7 MiB,与 10 个时持平。

会话的文件列表在对话视图里只列它自己的 `threads/<id>/work/`,`path` 写成 agent 相对
(`threads/<id>/work/…`,本会话的下载 / 删除端点按这种写法投影);老视图的会话不变。工作区快照段
要认出副本,只取一份全量清单(`include_seed_copies=True`,列表项带 `ctime_ns`,不参与相等比较、
不进对外视图),再经存储读一次标记拿到整份清单,按同一个判据(`is_pristine_seed_copy`)认原样副本
——每轮只读一次标记(review 10:之前是存储剔一遍时读一次、快照段再读一次)。一个目录要收成一行
「unchanged copy of /agent/<目录>/ (as of this conversation's start)」,必须三件事同时成立:清单里
这个目录下的文件一个不少都还在、都还是原样副本、目录下没有清单之外的文件。删过一个、改过一个、新写
一个、整个改了名,都照常展开。本对话的清单条数到了存储的 2000 条上限(可能被截断,截掉的部分里
可能有新写的文件)就什么都不收成一行(review 10);有目录比遍历深度上限还深、下面的文件没列
(列表结果的 `too_deep`)同样处理(review 11)。

已知不处理(review 9 记下):NFS 属性缓存让别的 pod 在几秒内看到旧的 ctime / 大小(下一次列表自愈);
合并主干时去掉了主干在 `list_files` 前面那次路径字符串 `os.stat` 预检(见上面「列表只按 fd 走」,
有意为之)。review 10 起快照段只列一次本对话,review 9 记下的「两次列表之间有人改文件」不再存在。
标记超过 256 KiB 一律当没有清单(review 10 记下:真实清单受 500 条目上限,远到不了;到了也是多列)。

**列表只按 fd 走(review 8,与主干 #1975 合并)。** `list_files` 起点用 `_open_scope_dir_fd`(逐段
`O_NOFOLLOW`),遍历用 `os.fwalk(follow_symlinks=False)`,不再先拿路径字符串 `os.stat` 一遍。
作用域的任何一段是符号链接(载荷把自己的 `work/` 换成指向上层的链接)→ `WorkspacePathEscapeError`,
端点把它当列不出来、回空列表,快照段整块不出,别的租户的文件名一个都不会出现。

**遍历深度封顶(review 9)。** `list_files` 与按名字 / 内容搜索的按 fd 遍历最多下到 64 层:`fwalk`
每深一层同时多握一个目录 fd,沙箱能造任意深的目录链。再深不走;列表记一条日志。搜索结果另有一个
`too_deep` 标记(review 10,与「命中够了条数、后面没列」的 `truncated` 分开):搜索工具单独一行告诉
模型有目录太深没搜,零命中时也说 —— 那时的「没找到」不等于「没有」。真实工作区实测最深 5 层。
列表本身到顶不在结果里标出来(review 10 记下不改:只有故意造才到得了,日志里有)。

**读文件最多读上限加一个字节(review 10)。** `read_file` 先 `fstat` 判大小,读时也只读 `cap + 1`
字节,多出来就报太大:`fstat` 之后文件还在长,也不会读进超过上限的量。

工具描述里的两句话(`WORKSPACE_PATH_RULE` / `EXEC_WORKSPACE_NOTE`)改成:新对话的 `/workspace`
开场带着 agent 各目录的副本,改副本只影响本对话,要留给以后的对话就放 `/agent/`。两种视图里都成立。

## 第三层:agent 自己的记忆

**规矩(系统提示词)。** 只给有沙箱写工具(`write_file` / `edit_file` / `bash` / `exec_python`)
且不是委派子代的构建。写的是类别:

- 存到 `/agent/`:持久的用户偏好(直接说的,或反复纠正同一件事体现出来的)、被纠正过的做法、
  可复用的资产(模板、脚本、报告结构)。
- 每存一样,在索引里记一行「是什么、在哪」。
- 永远不存:客户 / 患者数据或任何能认出具体客户的东西、一次性请求、中间结果。
- 一事一文件,改文件用 `edit_file` 定点改,不整文件重写。
- 改本对话里的副本只影响本对话;要长期生效,改 `/agent/<目录>/…`。
- 这个 agent 的索引是权威;召回的长期记忆与 `MEMORY.md` 只是提示,冲突时以索引为准
  (平台里已有三条记忆通路:`memory_item`、`remember` 草稿、`MEMORY.md` 投影)。

文本不含任何租户的内容。

**索引文件:`/agent/AGENT_NOTES.md`。** 不叫 `MEMORY.md`:那个名字是老视图里长期记忆的投影文件。

**开场注入。** 对话第一次 run 开始时(入口节点 `agent_notes`)读一次索引:

- 门:对话视图、有工作区存储、agent 有写工具、不是子代、是对话的第一轮且还没注入过(重新
  生成第一轮时旧轮被取代,照样注入;同一轮被重跑时不重复)。
- 不可信数据:先过 `scan_for_threats`(strict,与召回记忆同一口径),命中就不载入、只留一行
  `[BLOCKED:<类别>]`;再按构建的 spotlight nonce 包起来(防线开着时)。
- 截到约 2,000 token,截断处写明 `read_file('/agent/AGENT_NOTES.md')`;文件超过 64 KiB 不读,
  只说一句。索引被换成 FIFO / 目录 / 设备时不读(读文件一律 `O_NONBLOCK` 打开再核对是普通文件,
  见下面「宿主侧读写」),这一轮不注入。
- 作为一条隐藏 HumanMessage 落进第一轮(落检查点)。压缩或滑窗把它挤出提示词视图时,放回原件
  (与「本轮输入」段同一做法)。按标记认它在不在,不按对象身份:正文里有 `<recovery-advisory>`
  字样时转义那一步会换出一份副本,按身份认就会每一步多挂一份。
- **绝不进系统提示词**:构建缓存不分用户。之后对话里的改动经工作区快照段与 `read_file` 看得到,
  不每步重注。

**子代不写索引。** 照 B-122 的边界(子代不永久改变 agent 自己):委派出去的 run 用 `write_file` /
`edit_file` 写 `/agent/AGENT_NOTES.md` 被拒,提示它把要记的写进最终回复。子代的构建也读不到上面的
规矩。已知缺口:子代的 `bash` / `exec_python` 仍然写得到这个文件(沙箱侧没有逐文件的只读),
靠规矩不给子代 + 版本可找回兜底。

**版本(按观察)。**

- 主 run 结束时(`run_agent` 的 `finally`,fire-and-forget;交接给别的副本的不算结束)扫一遍
  `/agent`:一级的非保留文件与目录,含索引;不进保留区与点开头的目录;深度 / 条目数沿用开场复制
  的数,一次最多读 20 MiB,单个文件超过 8 MiB 不留。只看对话视图的主 run。
- 先比大小 + mtime,变了再算 sha256;内容没变只对齐副本的 mtime。大小与 mtime 都没变的不读、
  不花读预算。
- 读的先后(review 10):先遍历完整棵树,再定顺序 —— 索引 `AGENT_NOTES.md` 永远第一个(超过单文件
  8 MiB 照旧不留),其余按 mtime 从新到旧。之前按名字排:排在前面、每轮只被 `touch` 的大文件(内容
  没变、mtime 变了,只能读一遍算 sha256 才知道没变)能把 20 MiB 读预算用光,排在后面的真改动(含
  索引)永远轮不上。遍历时的目录 fd 不留着,按路径从 agent 根 fd 逐段 `O_NOFOLLOW` 重新打开。
- 存在 `{root}/{tenant}/.agent-file-versions/{user}/{agent_key}/{sha256(路径)[:32]}/`,用户根
  旁边,沙箱挂不到;每个文件留最近 20 份。
- 失败只记日志与计数,不影响 run。
- **每个(用户, agent)一份自己的字节预算:100 MiB**(用户 10-30 拍板;review 10 起,取代 review 7~9
  的「一个用户合计 200 MiB、跨 agent 删」:「谁来付」连着三轮审查都有洞 —— 一个 agent 能让另一个
  agent 的历史被删掉。改成按构造隔离)。测试环境实测最大的 agent 根 25.5 MB,100 MiB 放得下它全部
  当前文件一份,再加约三倍的历史。**这个 agent 的全部版本都算,各文件最新那份也算**;删只删这个
  agent 自己的版本,别的 agent 再大也碰不到。一个用户的合计因此不超过「agent 数乘 100 MiB」,版本照旧计入用户的
  工作区配额(配额重算把这个目录一起算)。每个文件最近 20 份(用户拍板)是这个预算**之内**的件数
  上限。
- **不变式(review 13):受保护的版本只在自己到期时删,别的文件做什么都删不到它;满了就不留新的。**
  受保护的是每个文件最新的几份:
  - 在的文件(或这次没法确认在不在的,见下)留最新 2 份;
  - 已不见、还在 30 天宽限期内的文件留最新 1 份;
  - 索引 `AGENT_NOTES.md` 不论在不在都留最新 3 份。

  受保护的版本只有这几条路会删:已不见满 30 天、工作区删文件接口、清除用户。
- **预算吃紧时删什么(review 11 起按 rank,review 13 只删不受保护的)。** 先给每份版本算 rank:在自己
  文件里排第几新,最新的是 1。只删 rank 大于受保护份数的那些,rank 从大到小,跨所有文件:每个文件
  的第 20 新都在任何文件的第 19 新之前删,依此类推;同 rank 的先删大的,再先删早写下的。一个每轮
  重写的大文件因此只让出它自己的旧版本。
- **写之前先算受保护的部分(review 13 起含已不见文件在宽限期内的那几份):** 写了这一份之后它会超
  预算,就跳过这一份(原因 `bytes`;同时要新建版本目录而目录数已到顶的,`dir_cap` 一起记),后面
  放得下的照写。(review 13 之前,已不见文件的最新那份不计入这一项,预算吃紧时会在宽限期内被删 ——
  一个被藏起来的索引当天就被垃圾冲光,即 review 13 的 F2。)
  **代价:** 一下子删掉很多文件之后,最长 30 天里新版本可能因为放不下而不留。
- 记日志 `agent_file_versions.over_budget`(带 `tenant_id` / `user_id` / `agent_key` 与原因 `reason`:
  `bytes` 字节预算放不下、`dir_cap` 版本目录数到顶、`still_over` 删完能删的仍超)、计数
  `outcome=over_budget` 与按租户的 `expert_work_agent_file_versions_over_budget_total{tenant_id}`
  (用户 id 只进日志:按用户打标签基数无上限)。单个观察里删完一定回到预算之内;跨副本同时观察、或
  恢复了一个之前已不见的大文件,受保护部分本身可能超预算,那时记 `still_over`,直到有文件被删掉、
  变小或到期。
- **如实说降级:** 预算够的时候每个文件留最近 20 份;预算吃紧时,每个文件只保证留上面那几份,不是
  20 份。被删的是各文件最旧的那几份。
- **在不在怎么判(review 13,按目录,取代整次遍历「完整 / 不完整」一个开关)。** 遍历记下这次**列全
  了**的目录(里面每个名字都读到、也处理过)和看到过的子目录:
  - 看到了的文件:在,撤掉它的 `missing` 标记;
  - 没看到、一路上每层目录都列全了(或中间某层子目录已经不在了):确认不见,没有标记就记一个;
  - 没看到、中间某层没列全(打不开、读目录出错、太深、条目或名字数到顶、读目录与 `lstat` 之间名字没了、
    `lstat` 被拒 —— 比如目录可读不可进 `0644`,review 15;打开 agent 根时 EIO / ESTALE / EMFILE 之类
    —— 存储层把它们也说成「不存在」,这里只认真正的 ENOENT / ENOTDIR 为「还没有根」,review 16):不知道
    —— 按在算(全额保护),**撤掉它的 `missing` 标记**(review 14):之后要再确认一次不见,30 天从
    那时重新算。review 13 让这种情形「标记一个字都不动」,结果「确认不见 → 一个月都列不全 → 藏
    一次」就能用 T0 的旧标记把整个目录一下删掉(review 14 的 F1)。
  - 版本目录的 `path` 没了、空的、写了一半(内容和目录名对不上):这个目录「不知道」,按在算
    (索引的目录按目录名认出来,仍留 3 份),不当孤儿;这次看到了那个文件就当场原子地重写
    `path`(review 15;之前只在文件变了、要写新版本时才修,文件一直不变就一直「不知道」,删掉后也
    永远不会到期)。`path` 读的时候出 EIO / ESTALE 之类的错误:收尾扫描这一次跳过这个目录(不删、
    不动它的标记),算预算时按「不知道」(全额保护)。`path` 一律先写临时文件再 `rename`。
  - **观察失败也不让旧标记作数(review 15)。** 沙箱与控制面是同一个 uid,载荷能把 `/agent` 下任何
    目录设成可读不可进(`0644`)或干脆 `000`。遍历里每个系统调用的错误都只让那一层算没列全,观察
    照常完成;索引单独查出错就是「不知道」(不是「不见」—— 只看 `index_present` 会在「根目录只有
    索引和点开头的名字」时把在着的索引判成不见)。打不开 agent 根、或遍历自己抛了异常,抛出去之前
    先用一个**空的**扫描结果收一次尾:每个文件都是「不知道」,所以这一遍只撤标记、删一份版本都没有
    的孤儿,不写、不按预算删、不按满 30 天删。复用同一个收尾函数,而不是另写只撤标记的分支:软删
    标记的检查也一起有。没有哪种失败能让 T0 的旧标记一直作数。
  - 索引在遍历之前单独查(`lstat`、普通文件,之后照常 `O_NOFOLLOW` 打开再核对),不受条目 / 名字
    上限影响:根目录塞再多名字,也不能让索引「不知道」或「不见」,它的改动也总排得上(review 13 的 L8)。
    子目录可读不可进也不影响索引(review 15);只有 agent 根本身进不去时,索引这次查不了、也留不了版本。
  - 遍历用 `os.scandir` 边读边数,每个名字(含跳过的点开头、保留、非 UTF-8 名字)都算进 2000 个的
    名字数上限(与开场复制同一个数),到顶就不再读新名字;已经读到的照常处理,只有到顶时正在读的
    那个目录(和之后才打开的目录)算没列全(review 14)。不先把整个目录读进内存(之前 30 万个点开头
    的名字要 77 MiB、4.7 秒)。有目录没列全时观察结果带 `walk_incomplete`,记日志
    `agent_file_versions.walk_incomplete` 与计数 `outcome=walk_incomplete`。
  - 遗留情形:一个永远列不全的目录(打不开、读不了、太深)里删掉的文件永远不会到期,它们的版本
    目录一直占着。条目数(500)在任何地方到顶 —— 包括在某个子目录里 —— 根目录这一层都可能列不全
    (到顶时根目录还有没处理的名字就列不全;在最后一个子目录里到顶时根目录可能已经处理完了);
    名字数(2000)只有在根目录**自己**的名字就超过 2000 个时才让根目录列不全(在子目录里到顶时,
    根目录已经读全了)。根目录列不全时,根目录这一层删掉的文件都不会到期,直到某次观察把它列全。
- 一次观察留在内存里待写的版本合计不超过读预算(20 MiB),不另设上限。
- 写下一份之后,账先按「多了这一份」记上,再做可能出错的清理与重读(review 15):清理出错时后面的放行
  判断不会算松。写过版本之后收回预算前重读一次全部版本目录,把别的副本同时写下的也算进去。
- 版本目录里写到一半被杀留下的 `.tmp-*`(不算版本、不进预算,目录有版本又不是孤儿)建了满 1 小时
  就删(review 15)。review 16 起按 **ctime** 算:写版本时会把源文件的 mtime 抄到临时文件上,那是载荷
  定的 —— 抄成 1970 年,另一个副本的扫描会把正在写的临时文件删掉;抄成 2100 年就永远删不掉。ctime 由
  文件系统定、载荷改不了。版本已经 `link` 好之后删临时文件出错不算这份写失败,留给扫描去清。
- 同一个(租户, 用户, agent)的观察在同一个进程里一个一个来(review 12,进程内的按键锁,不加基础设施;
  review 13/14:调用方被取消时 —— 取消几次都一样 —— 锁等到线程真跑完才放;线程抛的异常被取走,
  只记类型并计失败)。
  **跨副本**的两次观察仍可能同时进行,各自按旧的现状算预算:受保护的部分合计最多冲过预算
  「(同时观察数 − 1)× 20 MiB」(读预算)。冲过之后**不会自动收回**:受保护的版本不删,之后会让受保护
  部分变大的写入一直被跳过,直到有文件被删掉或变小。只在两个对话同时结束、同一 agent 的改动都很大时
  出现。
- 版本目录只在真正写版本时才建(review 10):读预算不够跳过的、读失败的、内容其实没变的,都不建
  目录 —— 之前跳过的文件也会留下一个没有 `path` 的空目录,换着名字就能绕过目录数上限。旧代码留下的
  孤儿目录(一份版本都没有的,review 14 起只有这一种;有版本、只是 `path` 坏了的不算)建了满 1 小时
  就删(留一小时不跟同时进行的观察抢)。
- 每个 agent 最多 2000 个版本目录(每个留过版本的路径一个):字节预算管不住「换着名字写空文件」。
  review 12 起**同字节预算一个原则:满了就停,从不腾地方** —— 要新建版本目录而已到 2000 个,这一份
  不留(记 `over_budget`、算 skipped),已有的目录一个都不删。之前的做法是删最早的目录,空文件就能把
  目录数顶满、连活的索引的历史一起删掉(实测第 10 轮 `index=[]`)。索引的版本目录总留一格(上限
  加一,review 13):目录数被已不见文件的目录顶满时,索引照样建得出来。
- 版本目录只有这几条路会被删:孤儿(一份版本都没有)满 1 小时;源文件确认不见满 30 天;
  工作区删文件接口删了那个文件;清除用户 / 已删工作区到期销账删这个用户的全部。
- 源文件从 `/agent` 消失:观察时确认不见(见上「在不在怎么判」)就在它的版本目录里记一个 `missing`
  标记,满 30 天整个版本目录删掉;看到了文件就撤掉标记。review 16:标记的内容是第一次确认不见的
  时间(30 天从它算),mtime 是最近一次确认的时间,每次确认都刷新;两次确认之间隔了 7 天以上(中间
  没有观察 —— 老视图的对话、控制台上传都会改 `/agent` 而不触发观察,文件可能早就回来过),就从这一次
  重新算 30 天。标记写坏了(空的、写了一半)、时间在将来,也重新算。出错的方向只会是晚到期 / 不到期。
  一个版本目录在收尾扫描里出错(满盘、EIO…)只影响它自己,不让后面的目录停下(review 16)。在运行结束的观察里做(不在留存作业里:只有
  观察知道这次看到了哪些文件)。
- 工作区删文件接口(控制台 `DELETE /v1/workspace/file`、`DELETE /v1/sessions/{id}/workspace/file`)
  删掉文件之后连它的版本一起删(尽力而为,失败只记日志)。
- 清除用户(`purge_user`)与已删工作区到期销账(留存作业)都删这个用户的整个版本目录。清除之后才
  结束的 run 看到软删标记就不观察。`purge_user` 在软删标记落下之后再删一遍(review 11)。观察在收尾
  开始前、和最后一次写之后各再看一次标记(review 12;review 13 起后一次放在 `finally` 里,收尾中途
  抛异常也查):开始前在就什么都不建;写完才在(清除的第二遍删除可能已经跑完)就把这个用户的版本
  整个删掉。这一查在最后一次写之后,所以**在同一个挂载上看得到标记时**,清除的第二遍删除之后任何
  观察留下的版本都会被它自己删掉;跨副本时 NFS 属性缓存可能让别的副本晚几秒看到标记,兜底是留存
  作业按用户删整个版本目录。
- 删版本目录撞上 `ENOTEMPTY` / 已经不在等任何错误只跳过那一个,不让整次观察失败(review 11)。

## 宿主侧读写不被 FIFO 卡住(review 7)

沙箱能在工作区里种 FIFO。`NasWorkspaceStore.read_file`(文件工具的 `read_file`、产物副本与下载、
记忆索引都走它)以 `O_NONBLOCK` 打开,`fstat` 不是普通文件就报「不是文件」;`write_file`(上传)
同样 `O_NONBLOCK` 打开、核对普通文件(`fstat` 本身失败也先关掉 fd 再报错,review 9);按内容搜索
打开前后都核对。开场复制与版本观察本来就这样做。
目录报「不是文件」(文件工具回 `is_a_directory`),FIFO / 设备 / socket 报「不是普通文件」
(`WorkspaceNotARegularFileError`,文件工具回 `not_a_regular_file`)—— 说它是目录,模型会去
`list_dir`。
