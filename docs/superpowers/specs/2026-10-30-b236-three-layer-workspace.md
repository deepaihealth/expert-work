# B-236 三层工作区:对话目录、开场复制、agent 记忆

日期:2026-10-30 · 状态:已拍板,随 B-236 一起发布

## 这份文档回答什么

- 一个对话里,模型写的文件落在哪、能看到哪些文件。
- 存量 agent 根下的模板 / 风格锚 / 脚本,在新对话里怎么还能按老路径用。
- agent 怎么「记住」跨对话的东西,记在哪,谁能改,改坏了怎么找回。

## 用户拍板(10-30)

| 项 | 决定 |
| --- | --- |
| 过渡期映射(compat:只读 bind + 截止日) | 整个删掉,改成开场复制 |
| 开场复制上限 | 每个对话合计 20 MB;超出的目录整个不复制,告诉模型它在 `/agent/<目录>/` |
| 记忆规矩的写法 | 写**类别**,不写关键词 |
| 版本保留 | 每个文件留最近 20 份 |
| 发布 | 与 B-236 同一次发布 |

## 第一层:每个对话一个 `/workspace`(B-236 原有,不变)

- 对话视图里 `/workspace` = `agents/<key>/threads/<conv>/work/`,`/agent` = agent 根。
- 老对话(发布前开的)仍是老视图:`/workspace` 与 `/agent` 是同一个目录。
- exec 脚本按 fd 挂载、`shared/` 只读、tmpfs 盖住、嵌套 user namespace —— 全部保留。
  删掉的只有过渡期目录那一段(`$4` 个数 + 名字、校验、只读 bind 循环),两份脚本仍逐字相同。

## 第二层:开场复制(取代过渡期映射)

**什么时候。** 对话第一次 run 开始时,图的入口节点 `conversation_seed`(与 `inputs` /
`workspace_ingest` 并列,agent 等它做完)。只在对话视图做;委派子代(`child_run`)不做。

**复制什么。** agent 根下已有的一级**目录**,跳过点开头的名字和保留名(`threads` `uploads`
`inputs` `.tool_results` `skills` `shared` `agents`)。根下的单个文件不复制。本对话 `work/`
里已有同名条目就不覆盖。

**怎么保证只复制一次。**

1. 按对话加锁(Postgres advisory lock,新 classid 8624,键 `{tenant}:{conv}`;不是按用户的
   写锁)。锁外先看一眼标记,锁内再看一次。
2. 标记 `threads/<conv>/.seeded` 在就什么都不做。
3. 每个目录先复制进 `threads/<conv>/.seed-tmp-<随机>/<目录>`,再改名进 `work/<目录>`,
   目标名已存在就不动。
4. 标记最后写。
5. 失败:不写标记、清掉临时目录、记日志(只记异常类型),run 照常;下一次 run 重试,
   已经搬进来的目录按「同名不覆盖」跳过。
6. run 被取消:等着复制的协程置停止标志,**仍持锁**等复制线程在下一个名字处停下再放锁
   (最多再写完手上那一个文件);停下按失败处理。选「持锁等停」而不是只靠停止标志:后者会在
   线程还在写时就放锁,下一个持锁者可能看到写到一半的临时目录。等的期间再来的取消一律吞掉
   接着等,但最多等 120 秒;真到上限记一条日志放锁,不让一个卡住的 NAS 把取消永远挡住。
   「等手上那个文件写完」是有意的,不改成立刻放手。

**标记被载荷删掉。** 标记在沙箱够得着的 `threads/<conv>/` 下。删了它,下一次 run 会再复制本对话
`work/` 里**没有**的目录。接受这一点,不把标记挪到沙箱外:再复制从不覆盖、单次仍受 20 MB 上限与
配额闸约束,载荷自己用 `cp` 也写得出同样多的字节;挪出去只换来更多要跟着清理的地方(清除用户、
留存作业)。标记里还有认「原样副本」用的复制清单(见下):载荷伪造或改它,影响的只是这个用户
自己这个对话的列表与快照段。

**配额。** 复制前先只量不读算出这次要复制多少字节,问用户的工作区配额(与上传同一道闸:
已用 + 这次 > 上限就拦)。拦下:一个目录都不复制,照样写标记(每个对话只问一次),状态里
`seed_quota_blocked` 置位,快照段写明是配额满了、去 `/agent/<目录>/` 用;复制了字节之后触发
一次配额重算。配额拦下时也写标记、之后不再复制,是有意的:每个对话只问一次,不会在之后某一轮
空间腾出来时突然多出一批目录。

**安全。** 宿主侧经 NAS store 自己的防穿越闸拿 agent 根的目录 fd,一路
`openat(O_RDONLY|O_DIRECTORY|O_NOFOLLOW)`;文件 `O_RDONLY|O_NOFOLLOW|O_NONBLOCK` 后 `fstat` 核对
是普通文件;符号链接、FIFO、设备、socket、编码不成 UTF-8 的名字跳过并计数;目标端在钉住的
目录 fd 上 `mkdirat` / `O_CREAT|O_EXCL|O_NOFOLLOW`。保留 mtime。

**上限(依据测试环境 2,079 个 agent 根的实测)。**

| 闸 | 值 | 实测 |
| --- | --- | --- |
| 总字节 | 20 MB(拍板) | p99 0.53 MB,最大 25.5 MB,只有 1 个根超过 |
| 条目数(文件 + 子目录) | 500 | 每根最多 77 个文件,p99 22 |
| 深度 | 12 层 | 最深 5 层 |
| 看过的名字数(量 + 复制两遍、全部目录) | 2000 | 两遍合计不到 200 |

先只 `lstat` 量一遍,放不下的目录整个跳过(不读它的字节);复制时再按同一组数守一次。跳过的
名字(符号链接、特殊文件、编码不成 UTF-8 的)同样占条目数,量过又放弃的目录同样算「看过」——
一个种满符号链接或塞满小文件的 agent 根不能让开场做无上限的 `lstat`。名字数到顶之后剩下的
目录不再看:目录项类型(读目录时一并拿到,不另发系统调用)是目录的记成「太大」。「太大」的目录名
在报告 / 状态 / 标记里最多记 20 个,再多只记个数(review 9:一个塞满几万个一级目录的 agent 根
不能让标记与内存跟着涨)。

**模型看到什么。** 工作区快照段里,原样未改的副本在本对话那一节只占一行(「unchanged copy of
/agent/<目录>/」),不占 30 行展开预算;改过的副本照常展开。超出上限没复制的目录在本对话那一节
末尾一行写明 `/agent/<目录>/`(名单存在状态 `seed_skipped_dirs` 里,不对外推送;最多记 20 个、
每个最多 120 字符)。这一行最多列 8 个目录、其余写「and N more」,名字截到 60 字符,控制字符与
换行转义成 `\xNN` —— 名字是沙箱起的,不能在块里另起一行。

**浏览列表不列原样未改的副本。** 文件列表(控制台 `/v1/workspace/files`、对外
`/v1/agents/{code}/workspace/files`、会话 `/v1/sessions/{id}/workspace/files`)默认剔掉开场复制
进对话、之后没被碰过的副本,也不列 `.seeded` 标记 —— 否则每个对话都带着 agent 全部文件的一份,
几十个对话就把 2000 条上限占满,真正的产出被截掉。**先剔再截** 2000 条。

判据(review 9,取代 review 8 只看时间的做法):复制时把**真正写进 `work/` 的每个文件**记进标记
的清单 —— `(work/ 相对路径, 大小, 写完之后的 ctime)`,ctime 取在保留 mtime 的 `utime` 之后;标记
照旧最后写。一个文件是原样副本,当且仅当它在清单里、且现在的大小与 `st_ctime_ns` 都与清单相同。
之后对它的任何写入、改权限、`touch` 都会让 ctime 对不上;ctime 由文件系统设(NFS 上是服务端),
用户态改不回去。

- 不在清单里的从不藏:复制失败之后模型自己写的(`reports/q3.md`)、改了名的(`mv customers
  clients`,新名字下的路径不在清单里)都照常列。
- 不跟 `/agent` 的现状比:源文件之后被改,老对话的副本照样不列;对话自己的产出被 `cp -a` 进
  `/agent`,对话里那份照样列。
- 标记的 mtime 不再用:把它的时间改到将来也藏不住任何东西。
- 清单受开场复制的 500 条目上限约束;标记读到 256 KiB 为止。没有标记、不是普通文件(FIFO)、超过
  上限、读不动、解析不了 —— 一律当没有清单,什么都不藏:认副本只为少列,出错的方向必须是多列。
  目录链的错误仍是 store 自己的异常类型,标记文件本身的错误不往外抛裸 `OSError`。
- 清单在沙箱够得着的地方:伪造它只影响这个用户自己这个对话的列表与快照段。

用户根 / agent 作用域的列表里标记就在遍历之中(按已钉住的目录 fd 读一次);对话作用域的列表多读一次
标记(按 fd)。

会话的文件列表在对话视图里只列它自己的 `threads/<id>/work/`,`path` 写成 agent 相对
(`threads/<id>/work/…`,本会话的下载 / 删除端点按这种写法投影);老视图的会话不变。工作区快照段
要认出副本,同时取全量(`include_seed_copies=True`)与剔过的两份清单,差就是原样副本,再经存储读一次
标记拿到清单;一个目录要收成一行「unchanged copy of /agent/<目录>/ (as of this conversation's
start)」,必须三件事同时成立:清单里这个目录下的文件一个不少都还在、都还是原样副本、目录下没有
清单之外的文件。删过一个、改过一个、新写一个、整个改了名,都照常展开。

已知不处理(review 9 记下):快照段两次列表之间有人改文件,这一轮的收拢可能对不上(下一轮自愈);
NFS 属性缓存让别的 pod 在几秒内看到旧的 ctime / 大小(同样下一次列表自愈);合并主干时去掉了主干在
`list_files` 前面那次路径字符串 `os.stat` 预检(见上面「列表只按 fd 走」,有意为之)。

**列表只按 fd 走(review 8,与主干 #1975 合并)。** `list_files` 起点用 `_open_scope_dir_fd`(逐段
`O_NOFOLLOW`),遍历用 `os.fwalk(follow_symlinks=False)`,不再先拿路径字符串 `os.stat` 一遍。
作用域的任何一段是符号链接(载荷把自己的 `work/` 换成指向上层的链接)→ `WorkspacePathEscapeError`,
端点把它当列不出来、回空列表,快照段整块不出,别的租户的文件名一个都不会出现。

**遍历深度封顶(review 9)。** `list_files` 与按名字 / 内容搜索的按 fd 遍历最多下到 64 层:`fwalk`
每深一层同时多握一个目录 fd,沙箱能造任意深的目录链。再深不走;搜索结果标成截断(`truncated`),
列表记一条日志。真实工作区实测最深 5 层。

工具描述里的两句话(`WORKSPACE_PATH_RULE` / `EXEC_WORKSPACE_NOTE`)改成:新对话的 `/workspace`
开场带着 agent 各目录的副本,改副本只影响本对话,要留给以后的对话就放 `/agent/`。两种视图里都成立。

## 第三层:agent 自己的记忆

**规矩(系统提示词)。** 只给有沙箱写工具(`write_file` / `edit_file` / `bash` / `exec_python`)
且不是委派子代的构建。写的是类别:

- 存到 `/agent/`:持久的用户偏好(直接说的,或反复纠正同一件事体现出来的)、被纠正过的做法、
  可复用的资产(模板、脚本、报告结构)。
- 每存一样,在索引里记一行「是什么、在哪」。
- 永远不存:客户 / 患者数据或任何能认出具体客户的东西、一次性请求、中间结果。
- 一事一文件,改文件用 `edit_file` 定点改,不整文件重写。
- 改本对话里的副本只影响本对话;要长期生效,改 `/agent/<目录>/…`。
- 这个 agent 的索引是权威;召回的长期记忆与 `MEMORY.md` 只是提示,冲突时以索引为准
  (平台里已有三条记忆通路:`memory_item`、`remember` 草稿、`MEMORY.md` 投影)。

文本不含任何租户的内容。

**索引文件:`/agent/AGENT_NOTES.md`。** 不叫 `MEMORY.md`:那个名字是老视图里长期记忆的投影文件。

**开场注入。** 对话第一次 run 开始时(入口节点 `agent_notes`)读一次索引:

- 门:对话视图、有工作区存储、agent 有写工具、不是子代、是对话的第一轮且还没注入过(重新
  生成第一轮时旧轮被取代,照样注入;同一轮被重跑时不重复)。
- 不可信数据:先过 `scan_for_threats`(strict,与召回记忆同一口径),命中就不载入、只留一行
  `[BLOCKED:<类别>]`;再按构建的 spotlight nonce 包起来(防线开着时)。
- 截到约 2,000 token,截断处写明 `read_file('/agent/AGENT_NOTES.md')`;文件超过 64 KiB 不读,
  只说一句。索引被换成 FIFO / 目录 / 设备时不读(读文件一律 `O_NONBLOCK` 打开再核对是普通文件,
  见下面「宿主侧读写」),这一轮不注入。
- 作为一条隐藏 HumanMessage 落进第一轮(落检查点)。压缩或滑窗把它挤出提示词视图时,放回原件
  (与「本轮输入」段同一做法)。按标记认它在不在,不按对象身份:正文里有 `<recovery-advisory>`
  字样时转义那一步会换出一份副本,按身份认就会每一步多挂一份。
- **绝不进系统提示词**:构建缓存不分用户。之后对话里的改动经工作区快照段与 `read_file` 看得到,
  不每步重注。

**子代不写索引。** 照 B-122 的边界(子代不永久改变 agent 自己):委派出去的 run 用 `write_file` /
`edit_file` 写 `/agent/AGENT_NOTES.md` 被拒,提示它把要记的写进最终回复。子代的构建也读不到上面的
规矩。已知缺口:子代的 `bash` / `exec_python` 仍然写得到这个文件(沙箱侧没有逐文件的只读),
靠规矩不给子代 + 版本可找回兜底。

**版本(按观察)。**

- 主 run 结束时(`run_agent` 的 `finally`,fire-and-forget;交接给别的副本的不算结束)扫一遍
  `/agent`:一级的非保留文件与目录,含索引;不进保留区与点开头的目录;深度 / 条目数沿用开场复制
  的数,一次最多读 20 MiB,单个文件超过 8 MiB 不留。只看对话视图的主 run。
- 先比大小 + mtime,变了再算 sha256;内容没变只对齐副本的 mtime。
- 存在 `{root}/{tenant}/.agent-file-versions/{user}/{agent_key}/{sha256(路径)[:32]}/`,用户根
  旁边,沙箱挂不到;每个文件留最近 20 份。
- 失败只记日志与计数,不影响 run。
- 计入用户的工作区配额(配额重算把这个目录一起算)。一个用户全部版本合计上限 200 MiB,在写了
  新版本的那次观察里收(review 9 起):**每个文件最新的那份从不删**;其余版本里,**当前占字节最多的
  agent 先付**,它内部从最早写下(ctime)的删起,每删一份重新比一次谁占得最多。取代 review 8 的
  「观察者先付」:那样一个旧历史很占地方的 agent,能让另一个刚改了文件的 agent 一份历史都留不住。
  因为最新那份从不删,合计可能仍高于 200 MiB;上界是「单文件 8 MiB 乘每个 agent 2000 个目录」,
  再加每次观察最多读 20 MiB 的增长速度。
- 每个 agent 最多 2000 个版本目录(每个留过版本的路径一个):字节上限管不住「换着名字写空文件」。
  超了整个删掉一些:先删源文件已不见的(有 `missing` 标记),再按目录里最新那份版本写下的时间从旧
  到新。不按目录 mtime(review 9):`missing` 标记的建与撤会刷新目录 mtime,按它排,已经删掉的源
  文件反而显得「新」,还活着、只是一直没改的文件先丢了历史。
- 源文件从 `/agent` 消失:观察时第一次发现就在它的版本目录里记一个 `missing` 标记,满 30 天整个
  版本目录删掉;文件回来就撤掉标记。在运行结束的观察里做(不在留存作业里:只有观察知道这次看到了
  哪些文件);遍历不完整时不判「不见」:条目上限截断、某个目录打不开(`chmod 000` / 被换成链接)、
  深度到顶,任一种都算不完整。
- 工作区删文件接口(控制台 `DELETE /v1/workspace/file`、`DELETE /v1/sessions/{id}/workspace/file`)
  删掉文件之后连它的版本一起删(尽力而为,失败只记日志)。
- 清除用户(`purge_user`)与已删工作区到期销账(留存作业)都删这个用户的整个版本目录。清除之后才
  结束的 run 看到软删标记就不观察,不会把版本又建回来。

## 宿主侧读写不被 FIFO 卡住(review 7)

沙箱能在工作区里种 FIFO。`NasWorkspaceStore.read_file`(文件工具的 `read_file`、产物副本与下载、
记忆索引都走它)以 `O_NONBLOCK` 打开,`fstat` 不是普通文件就报「不是文件」;`write_file`(上传)
同样 `O_NONBLOCK` 打开、核对普通文件(`fstat` 本身失败也先关掉 fd 再报错,review 9);按内容搜索
打开前后都核对。开场复制与版本观察本来就这样做。
目录报「不是文件」(文件工具回 `is_a_directory`),FIFO / 设备 / socket 报「不是普通文件」
(`WorkspaceNotARegularFileError`,文件工具回 `not_a_regular_file`)—— 说它是目录,模型会去
`list_dir`。

## 对外文档

`apps/admin-ui/docs-site/guide/query.md` §5.6 写明:每个条目的 `session_id`(Agent 级文件为
`null`)、会话文件的 `threads/{session_id}/work/…` 路径形态、原样副本不列。不列的是会话开始时
Agent 级同名文件的副本,之后 Agent 级文件可能已经改动,两者不一定相同;需要会话里那一份的按
`threads/{session_id}/work/<同一相对路径>` 下载(review 9 改正了「内容相同」的说法)。更新记录里加了
一条「待发布」。
